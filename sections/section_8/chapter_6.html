8. Model Context Protocol (MCP) / Lab - Cấu hình MCP Server MySQL & kiểm chứng dữ liệu
Bài lab này tiếp tục dùng project D:\lab-expense-management và container MySQL expense-mysql (database expense_db, user expense_user/expense_pass, cổng 3306) đã tạo ở Section 4, Chapter 4. Nếu chưa hoàn thành, hãy quay lại thực hiện trước.
Về tên gọi MCP Server MySQL: Không có một MCP Server MySQL "chính thức" duy nhất từ Anthropic — có nhiều MCP Server MySQL do cộng đồng phát triển. Bài lab trình bày cấu trúc .mcp.json tổng quát với placeholder <ten-goi-mcp-mysql> — học viên tự tìm một MCP Server MySQL phù hợp trên MCP registry/GitHub tại thời điểm thực hành (từ khoá gợi ý: "mcp server mysql"), ưu tiên Server có tài liệu rõ ràng về cách cấu hình kết nối (host/port/user/password/database) và có ghi rõ hỗ trợ thao tác nào (chỉ đọc hay cả ghi).

Mục tiêu

  • Cấu hình một MCP Server kết nối MySQL cho database expense_db của project lab-expense-management.
  • Áp dụng nguyên tắc least privilege (đã học ở Chapter 3): tạo riêng một user MySQL chỉ có quyền đọc cho MCP Server, không dùng lại user có toàn quyền CRUD của ứng dụng.
  • Yêu cầu Claude Code thêm một khoản chi tiêu mới qua API của ứng dụng như bình thường (ghi dữ liệu).
  • Dùng chính MCP Server MySQL để Claude Code tự chạy câu SQL SELECT kiểm chứng dữ liệu vừa ghi có đúng trong bảng Expense không — không cần học viên tự mở MySQL Workbench kiểm tra tay.

Claude Code ghi dữ liệu qua đường thông thường của ứng dụng (API), sau đó dùng chính MCP Server MySQL — một đường độc lập — để tự truy vấn và xác nhận dữ liệu vừa ghi đúng trong database, khép kín vòng lặp ghi → đọc → xác nhận.

Yêu cầu trước khi bắt đầu

  • Project D:\lab-expense-management (Section 4) vẫn còn trên máy, có thể chạy npm run dev được.
  • Docker Desktop đang chạy, container MySQL expense-mysql khởi động được (docker compose up -d).
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Node.js phiên bản 18 trở lên.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Khởi động lại project và container MySQL

  1. Bước 1: Vào thư mục project và khởi động MySQL container 
    cd D:\lab-expense-management
docker compose up -d

    Kiểm tra container đã chạy thành công.

    docker ps
CONTAINER ID   IMAGE       ...   PORTS                    NAMES
abc123def456   mysql:8.0   ...   0.0.0.0:3306->3306/tcp   expense-mysql
  2. Bước 2: Khởi động dev server ở một terminal riêng

    Giữ terminal này chạy xuyên suốt bài lab — cần dev server để gọi API ghi dữ liệu ở Phần 3.

    npm run dev

Phần 2: Tạo user MySQL riêng cho MCP Server (least privilege) và cấu hình .mcp.json

  1. Bước 3: Tạo user MySQL chỉ có quyền đọc, dùng riêng cho MCP Server

    Áp dụng đúng nguyên tắc least privilege đã học ở Chapter 3 — MCP Server dùng để kiểm chứng dữ liệu chỉ cần quyền SELECT, không cần dùng lại expense_user (vốn có toàn quyền CRUD của ứng dụng). Mở một terminal mới (giữ 2 terminal ở Bước 1-2 tiếp tục chạy), chạy lệnh sau ở một terminal khác trong D:\lab-expense-management.

    docker exec -it expense-mysql mysql -u root -prootpassword -e "CREATE USER 'expense_readonly'@'%' IDENTIFIED BY 'readonly_pass'; GRANT SELECT ON expense_db.* TO 'expense_readonly'@'%'; FLUSH PRIVILEGES;"
  2. Bước 4: Xác nhận user mới kết nối và đọc được dữ liệu 
    docker exec -it expense-mysql mysql -u expense_readonly -preadonly_pass expense_db -e "SELECT COUNT(*) FROM Expense;"
+----------+
  3. Bước 5: Khai báo MCP Server MySQL trong file .mcp.json

    Tạo (hoặc sửa) file .mcp.json ở gốc project. Đây là cấu trúc minh hoạ — thay <ten-goi-mcp-mysql> bằng tên package/lệnh khởi chạy thật của MCP Server MySQL bạn đã chọn, và đối chiếu README của Server đó để đặt đúng tên biến môi trường (một số Server dùng DB_HOST/DB_USER thay vì MYSQL_HOST/MYSQL_USER, hoặc dùng một biến DATABASE_URL duy nhất).

    .mcp.json{
  "mcpServers": {
    "mysql-expense": {
      "command": "npx",
      "args": ["-y", "<ten-goi-mcp-mysql>"],
      "env": {
        "MYSQL_HOST": "127.0.0.1",
        "MYSQL_PORT": "3306",
        "MYSQL_USER": "expense_readonly",
        "MYSQL_PASSWORD": "readonly_pass",
        "MYSQL_DATABASE": "expense_db"
      }
    }
  }
}
  4. Bước 6: Khởi động lại Claude Code trong project và xác nhận kết nối 
    cd D:\lab-expense-management
claude

    Dùng slash command /mcp trong phiên chat để xem trạng thái kết nối, hoặc kiểm tra bằng lệnh ngoài terminal.

    claude mcp list
mysql-expense: npx -y <ten-goi-mcp-mysql> - ✓ Connected

Phần 3: Ghi dữ liệu qua ứng dụng rồi tự kiểm chứng bằng MCP

  1. Bước 7: Yêu cầu Claude Code thêm khoản chi tiêu mới qua API

    Đây là thao tác ghi dữ liệu theo đường bình thường của ứng dụng — không đi qua MCP Server MySQL.

    Dev server đang chạy ở http://localhost:3000. Gọi API POST /api/expenses để tạo một khoản chi tiêu mới: title "Mua sách kỹ thuật", amount 250000, category "Học tập" (tạo category này trước qua POST /api/categories nếu chưa có), spentAt là ngày hôm nay. Dùng Invoke-RestMethod để gọi, không sửa trực tiếp vào database. Cho tôi biết response trả về.
  2. Bước 8: Yêu cầu Claude Code tự kiểm chứng bằng MCP Server MySQL

    Đây là bước giá trị chính của bài lab — Claude Code dùng một đường hoàn toàn độc lập (MCP Server MySQL, quyền chỉ đọc) để tự xác nhận thao tác ghi ở bước trên đã đúng.

    Dùng MCP Server MySQL vừa cấu hình (mysql-expense), chạy câu SELECT trên bảng Expense để kiểm chứng khoản chi tiêu "Mua sách kỹ thuật" vừa tạo ở bước trên: đúng amount 250000, đúng category "Học tập", đúng ngày hôm nay. Trả về đúng dòng dữ liệu tìm được và xác nhận rõ khớp/không khớp so với yêu cầu ban đầu.
  3. Bước 9: Đọc kết quả và xử lý nếu có sai lệch

    Nếu Claude Code báo có sai lệch (ví dụ lệch category, lệch định dạng ngày do timezone), yêu cầu điều tra nguyên nhân trước khi coi bài lab hoàn thành.

    Nếu có sai lệch ở bước kiểm chứng trên, hãy điều tra nguyên nhân (kiểm tra logic API route /api/expenses, đối chiếu categoryId, kiểm tra định dạng spentAt) và đề xuất cách sửa.

✅ Kết quả mong đợi

Claude Code tự khép kín vòng lặp ghi dữ liệu qua API → tự truy vấn kiểm chứng qua MCP Server MySQL → xác nhận đúng/sai mà không cần học viên tự mở MySQL Workbench hoặc chạy lệnh SQL tay. Dòng dữ liệu mới trong bảng Expense khớp đúng với yêu cầu ban đầu (title, amount, category, spentAt).

Troubleshoot

Lỗi: MCP Server MySQL báo Access denied for user 'expense_readonly'.
Nguyên nhân: Sai user/password trong .mcp.json, hoặc lệnh tạo user ở Bước 3 chưa chạy thành công/chưa FLUSH PRIVILEGES.
Giải pháp: Chạy lại lệnh kiểm tra ở Bước 4 (docker exec ... mysql -u expense_readonly ...) để xác nhận credentials đúng trước khi để MCP Server dùng; nếu vẫn lỗi, tạo lại user từ Bước 3.
Lỗi: MCP Server báo Can't connect to MySQL server.
Nguyên nhân: Container MySQL chưa chạy (kiểm tra lại docker ps), hoặc một số MCP Server chạy trong môi trường sandbox riêng cần dùng host.docker.internal thay vì 127.0.0.1 để với tới container trên máy host.
Giải pháp: Xác nhận docker ps thấy expense-mysql đang chạy; nếu Server chạy trong container/sandbox riêng, đổi MYSQL_HOST theo đúng hướng dẫn README của Server đó.
Lỗi: Claude Code không thấy Tool truy vấn SQL nào từ mysql-expense.
Nguyên nhân: MCP Server kết nối thất bại một cách âm thầm (silent fail).
Giải pháp: Chạy claude mcp list để xem trạng thái kết nối chi tiết, hoặc thử chạy trực tiếp lệnh trong command/args ngoài terminal để xem log lỗi đầy đủ.
Lỗi: Kết quả SELECT không thấy dòng dữ liệu vừa tạo ở Bước 7.
Nguyên nhân: API POST thất bại (dev server chưa chạy hoặc validate lỗi) trước khi kịp kiểm chứng.
Giải pháp: Xác nhận response ở Bước 7 trả về status thành công (2xx) và có id khoản chi tiêu mới trước khi chạy Bước 8.

# Gỡ MCP Server MySQL nếu không cần dùng nữa
claude mcp remove mysql-expense

# Dừng container MySQL (không dùng -v để giữ lại dữ liệu)
cd D:\lab-expense-management
docker compose down

User MySQL expense_readonly chỉ có quyền SELECT nên có thể giữ lại an toàn để dùng cho các lần thực hành sau, không cần xoá.
