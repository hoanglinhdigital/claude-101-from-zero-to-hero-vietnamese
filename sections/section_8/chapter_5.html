8. Model Context Protocol (MCP) / Lab - Cấu hình MCP Server MySQL & kiểm chứng dữ liệu
Bài lab này tiếp tục dùng project D:\lab-expense-management và container MySQL expense-mysql (database expense_db, user expense_user/expense_pass, cổng 3306) đã tạo ở Section 4, Chapter 4. Nếu chưa hoàn thành, hãy quay lại thực hiện trước.
Về MCP Server MySQL trong bài lab: Không có MCP Server MySQL "chính thức" từ Anthropic. Bài lab dùng mysql_mcp_server (package PyPI mysql-mcp-server, giấy phép MIT) — viết bằng Python, chạy trực tiếp qua uvx mà không cần cài đặt thủ công. Server cung cấp 3 Tool: execute_sql, get_schema_info, get_table_sample. Lưu ý: Server này không có chế độ chỉ đọc — execute_sql chạy được cả INSERT/UPDATE/DELETE. Vì vậy việc giới hạn quyền ở tầng MySQL user (chỉ cấp SELECT) là lớp bảo vệ bắt buộc.

Mục tiêu

  • Cấu hình MCP Server mysql_mcp_server (Python, chạy qua uvx) kết nối MySQL cho database expense_db của project lab-expense-management.
  • Dùng MySQL Workbench để tạo user MySQL riêng chỉ có quyền đọc (least privilege, đã học ở Chapter 3) cho MCP Server, không dùng lại user có toàn quyền CRUD của ứng dụng.
  • Yêu cầu Claude Code thêm một khoản chi tiêu mới qua API của ứng dụng như bình thường (ghi dữ liệu).
  • Dùng chính MCP Server MySQL để Claude Code tự chạy câu SQL SELECT kiểm chứng dữ liệu vừa ghi có đúng trong bảng transaction không — sau đó đối chiếu chéo kết quả bằng MySQL Workbench.
  • Ghi rule vào CLAUDE.md để Claude Code luôn dùng MCP Server mysql-expense cho mọi tác vụ query database, thay vì docker exec vào container MySQL.

Claude Code ghi dữ liệu qua đường thông thường của ứng dụng (API), sau đó dùng chính MCP Server MySQL — một đường độc lập — để tự truy vấn và xác nhận dữ liệu vừa ghi đúng trong database, khép kín vòng lặp ghi → đọc → xác nhận.

Yêu cầu trước khi bắt đầu

  • Project D:\lab-expense-management (Section 4) vẫn còn trên máy, có thể chạy npm run dev được.
  • Docker Desktop đang chạy, container MySQL expense-mysql khởi động được (docker compose up -d).
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Node.js phiên bản 18 trở lên (để chạy dev server của ứng dụng).
  • uv (Python package manager, cung cấp lệnh uvx) đã cài đặt. Kiểm tra bằng uv --version; nếu chưa có, cài bằng lệnh bên dưới.
  • MySQL Workbench đã cài đặt (tải tại dev.mysql.com/downloads/workbench).
  • Terminal: PowerShell hoặc Windows Terminal.
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Các bước thực hành

Phần 1: Khởi động lại project và container MySQL

  1. Bước 1: Vào thư mục project và khởi động MySQL container 
    cd D:\lab-expense-management
docker compose up -d

    Kiểm tra container đã chạy thành công.

    docker ps
CONTAINER ID   IMAGE       ...   PORTS                    NAMES
abc123def456   mysql:8.0   ...   0.0.0.0:3306->3306/tcp   expense-mysql
  2. Bước 2: Khởi động dev server ở một terminal riêng

    Giữ terminal này chạy xuyên suốt bài lab — cần dev server để gọi API ghi dữ liệu ở Phần 3.

    npm run dev

Phần 2: Tạo user MySQL riêng cho MCP Server (least privilege) và cấu hình .mcp.json

  1. Bước 3: Tạo user MySQL chỉ có quyền đọc, dùng riêng cho MCP Server

    Áp dụng đúng nguyên tắc least privilege đã học ở Chapter 3 — MCP Server dùng để kiểm chứng dữ liệu chỉ cần quyền SELECT, không cần dùng lại expense_user (vốn có toàn quyền CRUD của ứng dụng). Thực hiện bằng MySQL Workbench (giữ 2 terminal ở Bước 1-2 tiếp tục chạy):

    1. Mở MySQL Workbench, bấm dấu + cạnh MySQL Connections để tạo connection mới.
    2. Điền: Connection Name expense-root, Hostname 127.0.0.1, Port 3306, Username root. Bấm Store in Vault... nhập password rootpassword, rồi Test Connection → OK.
    3. Mở connection vừa tạo, mở tab SQL mới (Ctrl+T), dán đoạn SQL sau rồi chạy toàn bộ bằng Ctrl+Shift+Enter.
    CREATE USER 'expense_readonly'@'%' IDENTIFIED BY 'readonly_pass';
GRANT SELECT ON expense_db.* TO 'expense_readonly'@'%';
FLUSH PRIVILEGES;
  2. Bước 4: Xác nhận user mới kết nối và đọc được dữ liệu

    Trong MySQL Workbench, tạo thêm connection thứ hai: Connection Name expense_readonly, Hostname 127.0.0.1, Port 3306, Username expense_readonly, password readonly_pass, Default Schema expense_db. Mở connection này và chạy câu SELECT bên dưới — kết quả trả về số dòng của bảng transaction.

    SELECT COUNT(*) FROM transaction;

    Thử thêm một lệnh ghi để xác nhận quyền bị chặn — Workbench phải báo lỗi INSERT command denied to user 'expense_readonly'.

    DELETE FROM transaction WHERE id = -1;
  3. Bước 5: Khai báo MCP Server MySQL trong file .mcp.json

    Tạo (hoặc sửa) file .mcp.json ở gốc project. Server được chạy qua uvx — uv tự tải package mysql-mcp-server từ PyPI vào môi trường tạm, không cần pip install. Thông tin kết nối truyền qua biến môi trường MYSQL_*.

    .mcp.json{
  "mcpServers": {
    "mysql-expense": {
      "command": "uvx",
      "args": ["--from", "mysql-mcp-server", "mysql_mcp_server"],
      "env": {
        "MYSQL_HOST": "127.0.0.1",
        "MYSQL_PORT": "3306",
        "MYSQL_USER": "expense_readonly",
        "MYSQL_PASSWORD": "readonly_pass",
        "MYSQL_DATABASE": "expense_db"
      }
    }
  }
}
  4. Bước 6: Khởi động lại Claude Code trong project và xác nhận kết nối 
    cd D:\lab-expense-management
claude

    Dùng slash command /mcp trong phiên chat để xem trạng thái kết nối, hoặc kiểm tra bằng lệnh ngoài terminal.

    claude mcp list
mysql-expense: uvx --from mysql-mcp-server mysql_mcp_server - ✓ Connected

Phần 3: Ghi dữ liệu qua ứng dụng rồi tự kiểm chứng bằng MCP

  1. Bước 7: Yêu cầu Claude Code thêm khoản chi tiêu mới qua API

    Đây là thao tác ghi dữ liệu theo đường bình thường của ứng dụng — không đi qua MCP Server MySQL.

    
Dev server đang chạy ở http://localhost:3000. 
Tham khảo API Spect tại: docs\api-spec\category.yaml và docs\api-spec\transaction.yaml
Gọi API Post /api/auth/login với user/password lấy từ file .env (cặp thông tin: TEST_LOCAL_EMAIL, TEST_LOCAL_PASSWORD). 
Sau đó gọi API POST /api/transactions để tạo một khoản chi tiêu mới: note "Mua sách kỹ thuật", amount 250000, category "Học tập" (tạo category này trước qua POST /api/categories nếu chưa có), spentAt là ngày hôm nay. Dùng Invoke-RestMethod để gọi, không sửa trực tiếp vào database. Cho tôi biết response trả về.
  2. Bước 8: Yêu cầu Claude Code tự kiểm chứng bằng MCP Server MySQL

    Đây là bước giá trị chính của bài lab — Claude Code dùng một đường hoàn toàn độc lập (MCP Server MySQL, quyền chỉ đọc) để tự xác nhận thao tác ghi ở bước trên đã đúng.

    Dùng MCP Server MySQL vừa cấu hình (mysql-expense, Tool execute_sql), chạy câu SELECT trên bảng transaction, lọc type=EXPENSE, userId là id user đang login để kiểm chứng khoản chi tiêu với note "Mua sách kỹ thuật" vừa tạo ở bước trên: đúng amount 250000, đúng category "Học tập", đúng ngày hôm nay. Trả về đúng dòng dữ liệu tìm được và xác nhận rõ khớp/không khớp so với yêu cầu ban đầu.
  3. Bước 9: Đọc kết quả và xử lý nếu có sai lệch

    Nếu Claude Code báo có sai lệch (ví dụ lệch category, lệch định dạng ngày do timezone), yêu cầu điều tra nguyên nhân trước khi coi bài lab hoàn thành.

    Nếu có sai lệch ở bước kiểm chứng trên, hãy điều tra nguyên nhân (kiểm tra logic API route /api/transactions, đối chiếu categoryId, kiểm tra định dạng spentAt) và đề xuất cách sửa.
  4. Bước 10: Yêu cầu Claude Code bổ sung rule "luôn dùng MCP Server mysql-expense để query database"

    Nếu không có rule, Claude Code có thể tự chọn cách quen thuộc là docker exec ... mysql -u ... -e "SELECT ..." để truy vấn database — cách này cần truyền password trên command line và đi vòng qua quyền của user khác (thường là root hoặc expense_user), bỏ qua lớp least privilege đã thiết lập ở Bước 3. Hãy ghi rule vào file CLAUDE.md của project để mọi phiên làm việc sau đều tuân thủ.

    Hãy bổ sung vào file CLAUDE.md của project một rule mới (tạo file nếu chưa có, giữ nguyên nội dung cũ): mọi tác vụ query/đọc dữ liệu từ database MySQL expense_db (SELECT, SHOW, DESCRIBE, kiểm tra schema, đếm dòng...) BẮT BUỘC phải dùng MCP Server mysql-expense (các Tool execute_sql, get_schema_info, get_table_sample). KHÔNG dùng docker exec hoặc bất kỳ cách nào khác để truyền lệnh vào container expense-mysql, và không tự đăng nhập MySQL bằng user root hay expense_user. Nếu MCP Server mysql-expense không kết nối được, hãy dừng lại và báo lỗi cho tôi thay vì tự chuyển sang docker exec. Sau khi thêm xong, cho tôi xem nội dung rule đã ghi.

    Nội dung rule Claude Code ghi vào CLAUDE.md sẽ có dạng tương tự (bên dưới chỉ là ví dụ):

    CLAUDE.md## Truy vấn database
- Mọi tác vụ đọc dữ liệu từ database expense_db (SELECT, SHOW, DESCRIBE, kiểm tra schema...) phải dùng MCP Server mysql-expense.
- KHÔNG dùng docker exec để chạy lệnh mysql trong container expense-mysql.
- Nếu MCP Server không kết nối được, dừng lại và báo lỗi, không tự chuyển sang cách khác.

    Kiểm tra rule có hiệu lực: khởi động lại Claude Code (/exit rồi chạy lại claude) để nạp lại CLAUDE.md, sau đó đặt một câu hỏi cần truy vấn database.

    Cho tôi biết trong bảng transaction hiện có tổng cộng bao nhiêu dòng có type=EXPENSE. Nói rõ bạn đã dùng công cụ nào để truy vấn.

    Claude Code phải gọi Tool execute_sql của mysql-expense và không xuất hiện lệnh docker exec nào trong danh sách Tool đã dùng.

✅ Kết quả mong đợi

Claude Code tự khép kín vòng lặp ghi dữ liệu qua API → tự truy vấn kiểm chứng qua MCP Server MySQL → xác nhận đúng/sai mà không cần User chạy SQL tay. Dòng dữ liệu mới trong bảng transaction khớp đúng với yêu cầu ban đầu (title, amount, category, spentAt).

Để đối chiếu chéo, mở connection expense_readonly trong MySQL Workbench và chạy câu SELECT sau — kết quả phải trùng với những gì Claude Code báo:

      
SELECT * FROM expense_db.transaction
WHERE id='cmub14xvq001zecv717gs537z';

Troubleshoot

Lỗi: MCP Server MySQL báo Access denied for user 'expense_readonly'.
Nguyên nhân: Sai user/password trong .mcp.json, hoặc lệnh tạo user ở Bước 3 chưa chạy thành công/chưa FLUSH PRIVILEGES.
Giải pháp: Đăng nhập lại bằng connection expense_readonly trong MySQL Workbench (Bước 4) để xác nhận credentials đúng trước khi để MCP Server dùng; nếu vẫn lỗi, tạo lại user từ Bước 3.
Lỗi: MCP Server báo Can't connect to MySQL server.
Nguyên nhân: Container MySQL chưa chạy (kiểm tra lại docker ps), hoặc cổng 3306 bị chiếm bởi một MySQL khác trên máy.
Giải pháp: Xác nhận docker ps thấy expense-mysql đang chạy và connection Workbench kết nối được vào 127.0.0.1:3306; nếu Workbench vẫn kết nối được mà MCP lỗi, thử đổi MYSQL_HOST thành localhost.
Lỗi: Claude Code không thấy Tool truy vấn SQL nào từ mysql-expense.
Nguyên nhân: MCP Server kết nối thất bại một cách âm thầm (silent fail).
Giải pháp: Chạy claude mcp list để xem trạng thái kết nối chi tiết, hoặc thử chạy trực tiếp lệnh trong command/args ngoài terminal để xem log lỗi đầy đủ.
Lỗi: Kết quả SELECT không thấy dòng dữ liệu vừa tạo ở Bước 7.
Nguyên nhân: API POST thất bại (dev server chưa chạy hoặc validate lỗi) trước khi kịp kiểm chứng.
Giải pháp: Xác nhận response ở Bước 7 trả về status thành công (2xx) và có id khoản chi tiêu mới trước khi chạy Bước 8.
