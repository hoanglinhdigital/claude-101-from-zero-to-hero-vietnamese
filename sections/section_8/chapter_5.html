8. Model Context Protocol (MCP) / Lab - Cấu hình MCP Server CodeGraph
Bài lab này dùng lại project D:\lab-expense-management đã tạo ở Section 4 (Chapter 4, cập nhật thêm ở Chapter 6 và Chapter 7). Nếu chưa hoàn thành các Chapter đó, hãy quay lại thực hiện trước — bài lab này cần project đã có sẵn lib/expense-service.ts với hàm getMonthlySummary() (được tạo ra ở Chapter 7 khi refactor).
Về tên gọi "MCP Server CodeGraph": Đây không phải tên một package cố định mà là ví dụ minh hoạ cho một loại MCP Server chuyên phân tích call graph/dependency graph giữa các module code. Bài lab tập trung vào kỹ năng cấu hình một MCP Server bất kỳ và cách đặt câu hỏi truy vấn quan hệ code hiệu quả — kỹ năng này áp dụng được cho bất kỳ MCP Server CodeGraph cụ thể nào bạn chọn dùng tại thời điểm thực hành.

Mục tiêu

  • Biết cách thêm một MCP Server bất kỳ vào Claude Code — qua lệnh claude mcp add hoặc file .mcp.json ở gốc project.
  • Cấu hình một MCP Server dạng CodeGraph (ví dụ minh hoạ) cho project lab-expense-management.
  • Dùng Claude Code đặt câu hỏi truy vấn call graph/dependency giữa các module trước khi yêu cầu sửa một tính năng, để giảm rủi ro sửa sai chỗ hoặc bỏ sót nơi cần cập nhật.
  • Biết cách đọc và diễn giải kết quả phân tích quan hệ code trả về từ MCP Server.

Claude Code gọi Tool của MCP Server CodeGraph để phân tích quan hệ giữa các file trong project, sau đó diễn giải lại kết quả thô thành câu trả lời dễ hiểu cho developer.

Yêu cầu trước khi bắt đầu

  • Project D:\lab-expense-management (Section 4) vẫn còn trên máy, đầy đủ code sau Chapter 7 (đã có lib/expense-service.ts).
  • Claude Code CLI đã cài đặt và đăng nhập thành công, nên cập nhật lên bản mới nhất (claude update nếu có) để có đầy đủ lệnh quản lý MCP.
  • Node.js phiên bản 18 trở lên (hầu hết MCP Server chạy qua npx).
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Cách thêm một MCP Server vào Claude Code

  1. Bước 1: Xem danh sách MCP Server hiện đang kết nối (nếu có) 
    cd D:\lab-expense-management
claude mcp list
  2. Bước 2: Hai cách thêm một MCP Server bất kỳ

    Có hai cách tương đương để khai báo một MCP Server cho Claude Code — dùng lệnh CLI, hoặc sửa trực tiếp file cấu hình. Cú pháp/flag cụ thể có thể thay đổi theo phiên bản Claude Code — luôn kiểm tra lại bằng claude mcp add --help hoặc tài liệu Claude Code chính thức trước khi dùng.

    # Cách 1: dùng lệnh CLI (khái quát cú pháp, tham khảo --help để có flag mới nhất)
claude mcp add --help

# Cách 2: sửa trực tiếp file .mcp.json ở gốc project — thực hiện ở Bước 4

Phần 2: Cấu hình MCP Server CodeGraph cho project

  1. Bước 3: Tìm một MCP Server phân tích code phù hợp

    Vào thời điểm thực hành, tìm trên MCP registry hoặc GitHub với từ khoá "mcp server code graph", "mcp server dependency analysis", ưu tiên Server hỗ trợ tốt TypeScript/JavaScript (vì project lab-expense-management dùng Next.js + TypeScript). Ghi lại tên package/lệnh khởi chạy của Server đã chọn để dùng ở bước tiếp theo.

  2. Bước 4: Khai báo MCP Server trong file .mcp.json

    Tạo (hoặc sửa) file .mcp.json ở gốc thư mục D:\lab-expense-management. Đây là ví dụ cấu trúc minh hoạ — thay <ten-goi-mcp-codegraph> bằng tên package/lệnh khởi chạy thật của MCP Server bạn đã chọn ở Bước 3, và điều chỉnh args/env theo đúng README của Server đó.

    .mcp.json{
  "mcpServers": {
    "codegraph": {
      "command": "npx",
      "args": ["-y", "<ten-goi-mcp-codegraph>", "--project", "D:\\lab-expense-management"]
    }
  }
}

    Nếu Server bạn chọn yêu cầu cấu hình khác (thêm biến môi trường, transport khác stdio...), điều chỉnh theo đúng hướng dẫn của Server đó — cấu trúc mcpServers ở trên chỉ là bộ khung chung.

  3. Bước 5: Khởi động lại Claude Code và xác nhận kết nối 
    cd D:\lab-expense-management
claude

    Trong phiên chat, dùng slash command /mcp để xem nhanh trạng thái kết nối, hoặc chạy lệnh sau ngoài terminal:

    claude mcp list
codegraph: npx -y <ten-goi-mcp-codegraph> --project D:\lab-expense-management - ✓ Connected

Phần 3: Đặt câu hỏi truy vấn call graph/dependency

  1. Bước 6: Hỏi tổng quan dependency graph của project

    Bắt đầu bằng một câu hỏi tổng quát để hiểu bức tranh chung trước khi đi sâu vào một hàm cụ thể.

    Dùng MCP Server CodeGraph để phân tích dependency graph tổng quan của project này. Những module chính nào trong app/ và lib/ đang phụ thuộc vào module nào? Trình bày dưới dạng danh sách dễ đọc.
  2. Bước 7: Đặt câu hỏi cụ thể trước khi sửa một hàm dùng chung

    Đây là câu hỏi giá trị nhất trong thực tế — xác định phạm vi ảnh hưởng trước khi động vào một hàm đang được nhiều nơi gọi tới, dùng đúng hàm getMonthlySummary() đã tạo ra ở Chapter 7.

    Dùng MCP Server CodeGraph để phân tích: nếu tôi sửa hàm getMonthlySummary() trong lib/expense-service.ts, những file và route nào sẽ bị ảnh hưởng? Liệt kê đầy đủ các nơi gọi trực tiếp (direct caller) và các nơi phụ thuộc gián tiếp (ví dụ trang frontend đang gọi route đó).
  3. Bước 8: Yêu cầu diễn giải lại kết quả cho dễ đọc

    Nhiều MCP Server CodeGraph trả về kết quả dạng dữ liệu thô (JSON, cây quan hệ) — yêu cầu Claude Code diễn giải lại thành danh sách dễ hiểu, có phân loại mức độ ảnh hưởng.

    Tóm tắt kết quả phân tích trên thành danh sách gạch đầu dòng, xếp theo 2 nhóm: "Ảnh hưởng trực tiếp" và "Ảnh hưởng gián tiếp". Với mỗi file, cho biết tôi có nên viết thêm test cho file đó trước khi sửa getMonthlySummary() hay không, và vì sao.
  4. Bước 9: Tiến hành yêu cầu sửa tính năng dựa trên phân tích đã có

    Sau khi đã biết rõ phạm vi ảnh hưởng, giao tác vụ sửa thực tế — ví dụ thêm tham số lọc theo danh mục cho hàm tổng hợp.

    Dựa trên phân tích ảnh hưởng ở trên, sửa hàm getMonthlySummary() trong lib/expense-service.ts để nhận thêm tham số tuỳ chọn categoryId — nếu được truyền, chỉ tổng hợp chi tiêu thuộc category đó. Cập nhật đúng các file bị ảnh hưởng trực tiếp đã xác định ở Bước 7, và chạy lại npm test sau khi sửa xong để xác nhận không phá vỡ hành vi cũ.

✅ Kết quả mong đợi

Trước khi sửa getMonthlySummary(), học viên đã biết chính xác những file/route nào sẽ bị ảnh hưởng nhờ MCP Server CodeGraph, thay vì tự đoán hoặc phải đọc thủ công toàn bộ project. Sau khi sửa, toàn bộ test hiện có (từ Chapter 6, Chapter 7) vẫn pass, xác nhận không bỏ sót nơi cần cập nhật.

Troubleshoot

Lỗi: MCP Server báo "failed to start" hoặc không kết nối được sau khi cấu hình .mcp.json.
Nguyên nhân: Sai tên package trong args, hoặc package yêu cầu cài đặt/cấu hình bổ sung chưa thực hiện đúng.
Giải pháp: Chạy thử trực tiếp lệnh trong command/args ngoài terminal (ví dụ npx -y <ten-goi-mcp-codegraph> --project D:\lab-expense-management) để xem lỗi thực tế trước khi để Claude Code gọi qua MCP.
Lỗi: Claude Code không thấy Tool nào từ MCP Server CodeGraph, hoặc trả lời "không có công cụ phù hợp".
Nguyên nhân: Server chưa expose đúng Tool phân tích code, hoặc chưa được cấu hình đúng đường dẫn project.
Giải pháp: Đọc lại README của Server đã chọn, xác nhận tham số chỉ định thư mục project (--project hoặc tương đương) đã đúng, khởi động lại Claude Code sau khi sửa.
Lỗi: Kết quả phân tích thiếu file hoặc không chính xác.
Nguyên nhân: Nhiều MCP Server CodeGraph chỉ hỗ trợ một số ngôn ngữ nhất định, hoặc mặc định bỏ qua thư mục như node_modules, .next.
Giải pháp: Kiểm tra cấu hình include/exclude pattern của Server, hoặc yêu cầu Claude Code tự đọc thêm file liên quan để đối chiếu lại kết quả trước khi tin tưởng hoàn toàn.
