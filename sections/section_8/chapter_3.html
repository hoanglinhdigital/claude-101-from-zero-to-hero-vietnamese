8. Model Context Protocol (MCP) / MCP Server local vs remote & rủi ro bảo mật

Giới thiệu

MCP Server có thể được triển khai theo hai mô hình: local — chạy ngay trên máy của bạn, hoặc remote — chạy trên một server khác và kết nối qua network. Lựa chọn mô hình nào ảnh hưởng trực tiếp đến hiệu năng, độ phức tạp cấu hình, và quan trọng nhất — bề mặt rủi ro bảo mật. Vì một MCP Server có quyền truy cập tương đương với những gì bạn cấp cho nó (đọc file, chạy lệnh, truy vấn database...), hiểu rõ sự khác biệt này và áp dụng đúng nguyên tắc cấp quyền là điều bắt buộc trước khi đưa MCP vào công việc thực tế.

Các tính năng chính

  • MCP Server local — được Host (Claude Code/Claude Desktop) khởi chạy như một process con ngay trên máy, giao tiếp qua stdio (chuẩn input/output). Server dừng theo phiên làm việc, không cần mở cổng mạng.
  • MCP Server remote — đã chạy sẵn ở một server khác (on-premise hoặc cloud), Host kết nối tới qua HTTP hoặc SSE (Server-Sent Events), thường đi kèm cơ chế xác thực (API key, OAuth...).
  • Local phù hợp với công cụ cá nhân trên máy dev (filesystem, Git local, database chạy Docker local). Remote phù hợp khi Server cần dùng chung cho nhiều người/nhiều Host, hoặc khi hệ thống đích chỉ truy cập được qua network.
  • Dù local hay remote, MCP Server đều chạy với quyền tương đương quyền bạn cấp cho nó — không phải "chạy trong sandbox an toàn tuyệt đối" theo mặc định.

MCP Server local được Host tự khởi chạy như process con trên chính máy đang dùng; MCP Server remote đã chạy sẵn ở nơi khác, Host chỉ kết nối tới qua network và cần cơ chế xác thực.

Use Cases

Local — công cụ cá nhân trên máy dev

MCP Server filesystem/Git chạy local phục vụ đúng một developer trên máy của họ, không cần hạ tầng thêm.

Remote — Server dùng chung cho team

Một MCP Server database được deploy trên server riêng, nhiều thành viên team cùng kết nối tới qua HTTP với tài khoản/quyền riêng của từng người.

Remote — cổng kết nối SaaS doanh nghiệp

Nhà cung cấp SaaS (CRM, ticketing...) expose MCP Server remote chính thức, khách hàng chỉ cần cấu hình kết nối, không cần tự host.

Thông tin bổ sung

Nguyên tắc quan trọng nhất khi cấp quyền cho MCP Server là least privilege — chỉ cấp phạm vi truy cập tối thiểu cần thiết cho đúng mục đích sử dụng, dù Server chạy local hay remote.

Rủi ro thường gặp: Cấp cho một MCP Server database quyền tài khoản admin/root trong khi mục đích thực tế chỉ là đọc dữ liệu để kiểm chứng. Nếu MCP Server có lỗi, bị khai thác, hoặc model bị dẫn dụ gọi sai Tool (prompt injection từ dữ liệu bên ngoài), phạm vi thiệt hại tương đương đúng quyền đã cấp — cấp quyền admin nghĩa là rủi ro cao nhất có thể xảy ra là mất/hỏng toàn bộ database.
Với dữ liệu nhạy cảm: Khi dùng MCP Server remote do một bên thứ 3 cung cấp, dữ liệu bạn cho phép Server truy cập có thể đi qua hạ tầng của bên đó. Cân nhắc kỹ trước khi kết nối MCP Server remote với hệ thống chứa dữ liệu nhạy cảm (thông tin khách hàng, secret, dữ liệu tài chính), đặc biệt với Server chưa rõ nguồn gốc.
  • Với MCP Server database: tạo một user riêng chỉ có đúng quyền cần dùng (ví dụ chỉ SELECT nếu mục đích là kiểm chứng dữ liệu), không dùng lại user có toàn quyền CRUD của ứng dụng.
  • Trước khi thêm một MCP Server cộng đồng, kiểm tra mã nguồn có công khai không, ai duy trì, và Server yêu cầu quyền gì — càng yêu cầu quyền rộng mà không giải thích rõ vì sao, càng cần cẩn trọng.
  • Chỉ giữ kết nối những MCP Server thực sự đang cần dùng — gỡ bỏ Server không dùng nữa để giảm bề mặt rủi ro.
