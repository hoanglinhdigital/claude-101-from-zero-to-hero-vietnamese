8. Model Context Protocol (MCP) / Kiến trúc MCP: Host – Client – Server & primitives

Giới thiệu

Một hệ thống MCP luôn gồm 3 thành phần phối hợp với nhau: MCP Host — ứng dụng AI mà bạn đang dùng (Claude Code, Claude Desktop), MCP Client — phần nằm bên trong Host, chịu trách nhiệm quản lý kết nối và gửi/nhận thông điệp, và MCP Server — chương trình cung cấp khả năng thực tế (đọc file, truy vấn database, gọi API...). Phía Server expose khả năng của mình cho Host thông qua 3 loại primitive chuẩn hoá: Tools, Resources và Prompts. Chương này giải thích vai trò từng thành phần và cách chúng kết nối với nhau.

Các tính năng chính

  • MCP Host — ứng dụng AI mà người dùng tương tác trực tiếp (Claude Code, Claude Desktop). Host có thể kết nối với nhiều MCP Server cùng lúc.
  • MCP Client — thành phần nằm bên trong Host (người dùng không thấy trực tiếp), giữ một kết nối riêng tới mỗi MCP Server, gửi yêu cầu (gọi Tool, đọc Resource...) và nhận kết quả trả về cho model xử lý.
  • MCP Server — chương trình độc lập cung cấp khả năng cụ thể, có thể do Anthropic, nhà cung cấp dịch vụ, hoặc bất kỳ ai (kể cả bạn) viết ra, chạy local hoặc remote.
  • Một Host có thể kết nối đồng thời với nhiều Server thuộc nhiều nhà cung cấp khác nhau — ví dụ Claude Code có thể vừa kết nối MCP Server đọc file, vừa kết nối MCP Server truy vấn database, trong cùng một phiên làm việc.

MCP Client nằm bên trong Host, giữ kết nối riêng tới từng MCP Server. Một Host có thể kết nối nhiều Server cùng lúc, kể cả kết hợp Server chạy local (qua stdio) và Server chạy remote (qua HTTP/SSE) — xem chi tiết ở Chapter 3.

Ba primitive chính mà MCP Server cung cấp

🔧

Tools

Hành động cụ thể mà Server cho phép Host/model gọi để thực thi — ví dụ chạy một câu SQL, tạo một file, gọi một API. Model chủ động quyết định khi nào gọi Tool nào.

📄

Resources

Dữ liệu mà Server expose ra để Host đọc — ví dụ nội dung một file, một bản ghi trong database, một trang tài liệu nội bộ. Giống việc "nạp" thêm ngữ cảnh cho model.

📝

Prompts

Template prompt dựng sẵn do Server cung cấp cho một tác vụ lặp lại thường gặp (ví dụ "tóm tắt issue", "review PR") — người dùng chọn dùng lại thay vì tự soạn prompt từ đầu mỗi lần.

Use Cases

Một Host, nhiều Server

Claude Code kết nối đồng thời MCP Server filesystem, MCP Server Git và MCP Server database trong cùng một phiên làm việc, phối hợp cả 3 để hoàn thành một tác vụ.

Server nội bộ do team tự viết

Team tự viết một MCP Server expose Tool nghiệp vụ riêng (ví dụ "tạo ticket hỗ trợ") để Claude Code gọi trực tiếp, không cần đội ngũ khác tích hợp lại từ đầu.

Resources thay cho copy-paste

Một MCP Server expose Resource là tài liệu wiki nội bộ, giúp Claude đọc trực tiếp nội dung mới nhất thay vì người dùng phải tự copy-paste vào khung chat.

Thông tin bổ sung

Không phải MCP Server nào cũng implement đủ cả 3 primitive — rất nhiều Server chỉ tập trung vào Tools vì đó là dạng phổ biến và hữu ích nhất trong thực tế. Khi kết nối nhiều Server cùng lúc, số lượng Tools khả dụng cho model cũng tăng lên — cần lưu ý điều này có thể làm tăng độ dài ngữ cảnh mỗi lượt gọi (model cần "biết" mô tả của mọi Tool đang kết nối), vì vậy chỉ nên giữ kết nối những MCP Server thực sự cần dùng cho phiên làm việc hiện tại.
