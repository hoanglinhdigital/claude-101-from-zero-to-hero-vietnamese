8. Model Context Protocol (MCP) / Lab - Cấu hình MCP Server Graphify
Bài lab này dùng lại project D:\lab-expense-management đã tạo ở Section 4 (Chapter 4, cập nhật thêm ở Chapter 6 và Chapter 7). Nếu chưa hoàn thành các Chapter đó, hãy quay lại thực hiện trước — bài lab này cần project đã có sẵn lib/expense-service.ts với hàm getMonthlySummary() (được tạo ra ở Chapter 7 khi refactor).
Về Graphify: Graphify là công cụ mã nguồn mở biến source code (và cả tài liệu, PDF, hình ảnh) thành một knowledge graph có thể truy vấn. Graphify dùng tree-sitter để parse AST cục bộ (không gọi LLM), phân giải quan hệ calls, imports, inherits, mixes_in giữa các entity trong code — sau đó expose kết quả qua một MCP Server chạy local để Claude Code có thể truy vấn trực tiếp.

Mục tiêu

  • Cài đặt Graphify và sinh knowledge graph cho project lab-expense-management.
  • Cấu hình Graphify làm MCP Server local cho Claude Code qua file .mcp.json.
  • Dùng các Tool query_graph, get_neighbors, shortest_path của Graphify để phân tích quan hệ giữa các module trước khi yêu cầu sửa một tính năng, giảm rủi ro sửa sai chỗ hoặc bỏ sót nơi cần cập nhật.
  • Biết cách đọc và diễn giải kết quả phân tích quan hệ code trả về từ Graphify.

Graphify parse source code bằng tree-sitter để sinh graph.json một lần, sau đó MCP Server đọc file graph này để trả lời các câu truy vấn quan hệ code từ Claude Code — không cần gọi LLM để phân tích code.

Yêu cầu trước khi bắt đầu

  • Project D:\lab-expense-management (Section 4) vẫn còn trên máy, đầy đủ code sau Chapter 7 (đã có lib/expense-service.ts).
  • Claude Code CLI đã cài đặt và đăng nhập thành công, nên cập nhật lên bản mới nhất (claude update nếu có).
  • Python 3.10 trở lên đã cài đặt trên máy (Graphify chạy trên Python).
  • uv đã cài đặt (khuyến nghị) — xem hướng dẫn cài uv. Có thể thay bằng pipx nếu không dùng uv.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Cài đặt Graphify và sinh knowledge graph

  1. Bước 1: Cài Graphify qua uv

    Gói trên PyPI có tên graphifyy (2 chữ "y"), nhưng lệnh CLI sau khi cài là graphify.

    
uv tool install graphifyy
graphify install --project
  2. Bước 2: Sinh knowledge graph cho project lab-expense-management

    Có thể sinh graph bằng slash command /graphify . ngay trong Claude Code, hoặc chạy trực tiếp CLI ngoài terminal. Ở đây dùng CLI để thấy rõ output.

    cd D:\lab-expense-management
graphify .
# Output: graphify-out/graph.json, graphify-out/graph.html, graphify-out/GRAPH_REPORT.md
# Parse local qua tree-sitter, không gọi LLM cho phần phân tích code

    Mở graphify-out/graph.html bằng trình duyệt để xem trực quan force-directed graph của toàn bộ project, hoặc đọc graphify-out/GRAPH_REPORT.md để xem các "god node" (module được gọi nhiều nhất) và các kết nối bất ngờ.

Phần 2: Cấu hình Graphify làm MCP Server cho Claude Code

  1. Bước 3: Xem danh sách MCP Server hiện đang kết nối (nếu có) 
    cd D:\lab-expense-management
claude mcp list
  2. Bước 4: Khai báo Graphify trong file .mcp.json

    Tạo (hoặc sửa) file .mcp.json ở gốc thư mục D:\lab-expense-management, trỏ MCP Server tới file graph.json vừa sinh ra ở Bước 2. Đây là cấu hình stdio — chạy local, không cần mở port.

    .mcp.json{
  "mcpServers": {
    "graphify": {
      "command": "python",
      "args": ["-m", "graphify.serve", "graphify-out/graph.json"]
    }
  }
}

    Nếu muốn chia sẻ graph này cho cả team qua HTTP thay vì chỉ chạy local cho một máy, Graphify hỗ trợ transport HTTP kèm API key:

    # Tham khảo — không bắt buộc cho bài lab này, dùng khi muốn share graph qua mạng nội bộ
python -m graphify.serve graphify-out/graph.json --transport http `
  --host 0.0.0.0 --port 8080 --api-key "your-secret-key"
  3. Bước 5: Khởi động lại Claude Code và xác nhận kết nối 
    cd D:\lab-expense-management
claude

    Trong phiên chat, dùng slash command /mcp để xem nhanh trạng thái kết nối, hoặc chạy lệnh sau ngoài terminal:

    claude mcp list
graphify: python -m graphify.serve graphify-out/graph.json - ✓ Connected

Phần 3: Đặt câu hỏi truy vấn call graph/dependency

  1. Bước 6: Hỏi tổng quan knowledge graph của project

    Bắt đầu bằng một câu hỏi tổng quát để hiểu bức tranh chung trước khi đi sâu vào một hàm cụ thể. Claude Code sẽ tự chọn gọi Tool query_graph của Graphify.

    Dùng MCP Server Graphify (query_graph) để phân tích knowledge graph tổng quan của project này. Những module chính nào trong app/ và lib/ đang phụ thuộc vào module nào? Trình bày dưới dạng danh sách dễ đọc.
  2. Bước 7: Đặt câu hỏi cụ thể trước khi sửa một hàm dùng chung

    Đây là câu hỏi giá trị nhất trong thực tế — xác định phạm vi ảnh hưởng trước khi động vào một hàm đang được nhiều nơi gọi tới, dùng đúng hàm getExpenseByCategory() Yêu cầu Claude Code dùng get_neighbors và shortest_path để truy vết quan hệ.

    
Dùng Graphify để phân tích: nếu tôi sửa hàm getExpenseByCategory() trong src/lib/services/report.service.ts, những file và route nào sẽ bị ảnh hưởng? Dùng get_neighbors để tìm các node gọi trực tiếp (direct caller), và shortest_path để kiểm tra xem các trang frontend có phụ thuộc gián tiếp vào hàm này qua route API không.
Tóm tắt kết quả phân tích trên thành danh sách gạch đầu dòng, xếp theo 2 nhóm: "Ảnh hưởng trực tiếp" và "Ảnh hưởng gián tiếp". Với mỗi file, cho biết tôi có nên viết thêm test cho file đó trước khi sửa getExpenseByCategory() hay không, và vì sao.
  3. Bước 8: Tiến hành yêu cầu sửa tính năng dựa trên phân tích đã có

    Sau khi đã biết rõ phạm vi ảnh hưởng, giao tác vụ sửa thực tế — ví dụ thêm tham số sort Tăng/Giảm cho hàm.

    
Dựa trên phân tích ảnh hưởng ở trên, sửa hàm getExpenseByCategory() trong src/lib/services/report.service.ts để nhận thêm tham số sort Type: ascending/descending — nếu được truyền, áp dụng loại sort theo user. 
Add thêm một Nút sort trên trang frontend /expense-report để user chọn Tăng/Giảm, và gọi lại API khi user click nút này (đang sắp xếp tăng thì thành giảm và ngược lại).
Cập nhật đúng các file bị ảnh hưởng trực tiếp đã xác định ở Bước trước, và chạy lại npm test sau khi sửa xong để xác nhận không phá vỡ hành vi cũ.

Phần 4: Biến quy trình thành quy tắc cố định trong CLAUDE.md

  1. Bước 9: Thêm rule vào CLAUDE.md để mọi thay đổi source code đều phải đánh giá ảnh hưởng bằng Graphify

    Ở Bước 7 và 8, bạn phải tự nhắc Claude Code dùng Graphify mỗi lần sửa code. Để agent tự động làm điều đó trong mọi phiên làm việc, hãy ghi thành quy tắc trong CLAUDE.md. Quy tắc này yêu cầu agent luôn truy vấn Graphify trước khi sửa/xóa function, từ đó quyết định cần cập nhật UI, class nào và cần chạy lại hoặc bổ sung testcase nào trong plan.

    
Cập nhật file CLAUDE.md giúp tôi để phản ánh quy tắc sử dụng MCP Server Graphify: một code-graph giúp truy vấn quan hệ của các method, các class code, đánh giá ảnh hưởng.
Yêu cầu AI agent luôn sử dụng Graphify này để đánh giá ảnh hưởng trước khi implement tính năng mới (sửa function, xóa function), từ đó quyết định có cần sửa UI, class, bổ sung testcase liên quan trong plan.
Rule cần nêu rõ: (1) dùng get_neighbors/shortest_path để tìm direct caller và phụ thuộc gián tiếp; (2) liệt kê testcase hiện có cần chạy lại; (3) đề xuất testcase mới nếu vùng bị ảnh hưởng chưa được cover; (4) chạy lại graphify . để cập nhật graph sau khi sửa code xong.

    Sau khi Claude Code cập nhật xong, mở file CLAUDE.md để kiểm tra rule đã được ghi đúng. Từ các phiên sau, mỗi khi bạn yêu cầu sửa/xóa function, agent sẽ tự chạy Graphify và đưa kết quả đánh giá ảnh hưởng (kèm danh sách testcase cần chạy lại hoặc bổ sung) vào plan mà không cần nhắc lại.

✅ Kết quả mong đợi

Trước khi sửa getExpenseByCategory(), User đã biết chính xác những file/route nào sẽ bị ảnh hưởng nhờ knowledge graph do Graphify sinh ra (dựa trên phân tích AST cục bộ, không phụ thuộc LLM), thay vì tự đoán hoặc phải đọc thủ công toàn bộ project. Sau khi sửa, toàn bộ test hiện có (từ Chapter 6, Chapter 7) vẫn pass, xác nhận không bỏ sót nơi cần cập nhật.

Troubleshoot

Lỗi: Permission Denied.
Nguyên nhân: Trình Windows Security của máy tính chặn app lạ.
Giải pháp: Mở Windows Security → App & browser control → cuộn xuống mục Smart App Control → chọn Off (hoặc Warn nếu muốn được hỏi trước khi chạy app lạ). Sau đó mở lại terminal và chạy lại lệnh.
Lỗi: MCP Server báo "failed to start" hoặc FileNotFoundError: graph.json.
Nguyên nhân: Chưa chạy graphify . (hoặc /graphify .) để sinh file graphify-out/graph.json trước khi khởi động MCP Server, hoặc đường dẫn trong args của .mcp.json không đúng thư mục làm việc hiện tại.
Giải pháp: Chạy thử trực tiếp python -m graphify.serve graphify-out/graph.json ngoài terminal tại đúng thư mục D:\lab-expense-management để xem lỗi thực tế trước khi để Claude Code gọi qua MCP.
Lỗi: graphify: command not found sau khi cài đặt.
Nguyên nhân: uv tool install cài binary vào thư mục riêng chưa được thêm vào PATH.
Giải pháp: Chạy uv tool update-shell rồi mở lại terminal, hoặc dùng uv tool run graphifyy để gọi trực tiếp không cần thêm PATH.
Lỗi: Kết quả phân tích thiếu file hoặc không chính xác.
Nguyên nhân: Graph đã sinh ra (graph.json) là một snapshot tại thời điểm chạy graphify . — nếu code đã thay đổi sau đó (ví dụ sau khi sửa ở Bước 9), graph cũ sẽ không phản ánh đúng quan hệ mới.
Giải pháp: Chạy lại graphify update . để sinh graph mới sau mỗi lần thay đổi cấu trúc code đáng kể, trước khi tiếp tục truy vấn.

Dọn dẹp resource

Bài lab này không tạo resource cloud — Graphify chỉ chạy local, đọc file graph.json trên máy. Nếu không cần dùng tiếp, gỡ kết nối MCP và xoá dữ liệu graph đã sinh:
claude mcp remove graphify
Remove-Item -Recurse -Force D:\lab-expense-management\graphify-out

Nếu muốn gỡ hẳn Graphify khỏi máy (không dùng cho project khác nữa): 

uv tool uninstall graphifyy
Quan trọng: Không xoá thư mục project D:\lab-expense-management — project này tiếp tục được dùng ở Chapter 6 (MCP Server MySQL) của Section này.
