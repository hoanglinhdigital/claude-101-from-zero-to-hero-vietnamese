8. Model Context Protocol (MCP) / Model Context Protocol là gì

Giới thiệu

Model Context Protocol (MCP) là một chuẩn giao tiếp mở do Anthropic công bố cuối năm 2024, định nghĩa cách một AI Agent (như Claude Code, Claude Desktop) kết nối và thao tác với các hệ thống, dữ liệu, công cụ bên ngoài — database, filesystem, API nội bộ, dịch vụ SaaS... MCP thường được ví như "USB-C cho AI Agent": giống như USB-C cho phép một cáp duy nhất cắm được vào nhiều loại thiết bị khác nhau thay vì mỗi thiết bị cần một loại cổng riêng, MCP cho phép một AI Agent nói cùng một "ngôn ngữ" để kết nối với rất nhiều hệ thống khác nhau, thay vì phải viết tích hợp riêng cho từng cặp Agent – Hệ thống.

Vấn đề MCP giải quyết thường được gọi là bài toán M × N integrations: nếu có M AI Agent/AI App khác nhau và N hệ thống/công cụ cần kết nối tới, theo cách truyền thống cần viết tới M × N đoạn tích hợp riêng lẻ (mỗi Agent tự viết code kết nối riêng cho từng hệ thống). Với MCP, mỗi hệ thống chỉ cần expose một MCP Server, và mỗi AI Agent chỉ cần implement một MCP Client hiểu chuẩn chung — số lượng tích hợp cần xây giảm từ M × N xuống còn M + N.

Các tính năng chính

  • Chuẩn mở, không ràng buộc vào một AI App cụ thể — bất kỳ AI Agent nào implement đúng chuẩn MCP (Claude Code, Claude Desktop, hoặc các AI App khác) đều có thể dùng lại cùng một MCP Server.
  • Giảm số lượng tích hợp cần viết — từ M × N xuống M + N, mỗi hệ thống chỉ cần viết/duy trì một MCP Server duy nhất cho mọi AI Agent sử dụng.
  • Mở rộng khả năng của Agent không cần sửa code Agent — muốn Claude Code đọc thêm một hệ thống mới, chỉ cần thêm một MCP Server tương ứng, không cần chờ cập nhật bản thân Claude Code.
  • Hệ sinh thái MCP Server sẵn có đang phát triển nhanh — nhiều MCP Server cho các hệ thống phổ biến (filesystem, Git, database, các dịch vụ SaaS...) đã được cộng đồng và các nhà cung cấp xây dựng sẵn, có thể tái sử dụng thay vì tự viết từ đầu.
  • Giao tiếp theo chuẩn JSON-RPC 2.0, hỗ trợ cả kết nối chạy trên máy local (qua stdio) và kết nối tới server ở nơi khác (qua HTTP/SSE) — sẽ tìm hiểu chi tiết ở Chapter 3.

Trước MCP, mỗi AI App phải tự viết tích hợp riêng cho từng hệ thống (số lượng tích hợp = số AI App × số hệ thống). Sau khi có MCP, mọi AI App nói cùng một chuẩn để dùng chung mọi MCP Server — số lượng tích hợp cần xây chỉ còn bằng tổng số AI App cộng tổng số hệ thống.

Use Cases

Trợ lý code hiểu codebase nội bộ

Một MCP Server phân tích quan hệ code (call graph, dependency) giúp Claude Code hiểu kiến trúc project phức tạp trước khi sửa một tính năng, thay vì chỉ đọc file rời rạc.

Kiểm chứng dữ liệu tự động

Một MCP Server kết nối database cho phép Claude Code tự truy vấn để xác nhận một thao tác ghi dữ liệu (tạo/sửa/xoá) đã thực sự đúng, không cần học viên tự mở công cụ quản trị DB kiểm tra tay.

Kết nối hệ thống doanh nghiệp

Doanh nghiệp expose một MCP Server duy nhất cho hệ thống nội bộ (ticketing, wiki, CRM...), mọi AI Agent trong tổ chức dùng chung, không cần xây tích hợp riêng cho từng công cụ AI đang dùng.

Thông tin bổ sung

MCP không phải là sản phẩm riêng của Claude — đây là một chuẩn mở, bất kỳ ai cũng có thể viết MCP Server hoặc MCP Client theo chuẩn này. Vì một MCP Server có thể chạy code tuỳ ý và truy cập đúng những gì bạn cấp quyền, nên trước khi thêm bất kỳ MCP Server nào (đặc biệt là MCP Server do cộng đồng viết) vào Claude Code, cần đánh giá độ tin cậy của nó — nguồn gốc, mã nguồn có công khai không, phạm vi quyền yêu cầu là gì. Chương 3 của Section này sẽ đi sâu vào các nguyên tắc an toàn khi cấp quyền cho MCP Server.
