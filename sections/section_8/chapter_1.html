8. Model Context Protocol (MCP) / Model Context Protocol là gì

Giới thiệu

Model Context Protocol (MCP) là một chuẩn giao tiếp mở do Anthropic công bố cuối năm 2024, định nghĩa cách một AI Agent (như Claude Code, Claude Desktop) kết nối và thao tác với các hệ thống, dữ liệu, công cụ bên ngoài — database, filesystem, API nội bộ, dịch vụ SaaS... MCP thường được ví như "USB-C cho AI Agent": giống như USB-C cho phép một cáp duy nhất cắm được vào nhiều loại thiết bị khác nhau thay vì mỗi thiết bị cần một loại cổng riêng, MCP cho phép một AI Agent nói cùng một "ngôn ngữ" để kết nối với rất nhiều hệ thống khác nhau, thay vì phải viết tích hợp riêng cho từng cặp Agent – Hệ thống.

Vấn đề MCP giải quyết thường được gọi là bài toán M × N integrations: nếu có M AI Agent/AI App khác nhau và N hệ thống/công cụ cần kết nối tới, theo cách truyền thống cần viết tới M × N đoạn tích hợp riêng lẻ (mỗi Agent tự viết code kết nối riêng cho từng hệ thống). Với MCP, mỗi hệ thống chỉ cần expose một MCP Server, và mỗi AI Agent chỉ cần implement một MCP Client hiểu chuẩn chung — số lượng tích hợp cần xây giảm từ M × N xuống còn M + N. Để làm được điều này, một hệ thống MCP luôn gồm 3 thành phần phối hợp với nhau: MCP Host — ứng dụng AI mà bạn đang dùng, MCP Client — phần nằm bên trong Host chịu trách nhiệm quản lý kết nối và gửi/nhận thông điệp, và MCP Server — chương trình cung cấp khả năng thực tế (đọc file, truy vấn database, gọi API...).

Các tính năng chính

  • Chuẩn mở, không ràng buộc vào một AI App cụ thể — bất kỳ AI Agent nào implement đúng chuẩn MCP (Claude Code, Claude Desktop, hoặc các AI App khác) đều có thể dùng lại cùng một MCP Server.
  • Giảm số lượng tích hợp cần viết — từ M × N xuống M + N, mỗi hệ thống chỉ cần viết/duy trì một MCP Server duy nhất cho mọi AI Agent sử dụng.
  • MCP Host — ứng dụng AI mà người dùng tương tác trực tiếp (Claude Code, Claude Desktop). Host có thể kết nối với nhiều MCP Server cùng lúc, kể cả kết hợp Server local và Server remote.
  • MCP Client — thành phần nằm bên trong Host (người dùng không thấy trực tiếp), giữ một kết nối riêng tới mỗi MCP Server, gửi yêu cầu (gọi Tool, đọc Resource...) và nhận kết quả trả về cho model xử lý.
  • MCP Server — chương trình độc lập cung cấp khả năng cụ thể, có thể do Anthropic, nhà cung cấp dịch vụ, hoặc bất kỳ ai (kể cả bạn) viết ra, chạy local hoặc remote.
  • Hệ sinh thái MCP Server sẵn có đang phát triển nhanh — nhiều MCP Server cho các hệ thống phổ biến (filesystem, Git, database, các dịch vụ SaaS...) đã được cộng đồng và các nhà cung cấp xây dựng sẵn, có thể tái sử dụng thay vì tự viết từ đầu.
  • Giao tiếp theo chuẩn JSON-RPC 2.0, hỗ trợ cả kết nối chạy trên máy local (qua stdio) và kết nối tới server ở nơi khác (qua HTTP/SSE) — sẽ tìm hiểu chi tiết ở Chapter 3.

Ba primitive chính mà MCP Server cung cấp

🔧

Tools

Hành động cụ thể mà Server cho phép Host/model gọi để thực thi — ví dụ chạy một câu SQL, tạo một file, gọi một API. Model chủ động quyết định khi nào gọi Tool nào.

📄

Resources

Dữ liệu mà Server expose ra để Host đọc — ví dụ nội dung một file, một bản ghi trong database, một trang tài liệu nội bộ. Giống việc "nạp" thêm ngữ cảnh cho model.

📝

Prompts

Template prompt dựng sẵn do Server cung cấp cho một tác vụ lặp lại thường gặp (ví dụ "tóm tắt issue", "review PR") — người dùng chọn dùng lại thay vì tự soạn prompt từ đầu mỗi lần.

Use Cases

Trợ lý code hiểu codebase nội bộ

Một MCP Server phân tích quan hệ code (call graph, dependency) giúp Claude Code hiểu kiến trúc project phức tạp trước khi sửa một tính năng, thay vì chỉ đọc file rời rạc.

Một Host, nhiều Server

Claude Code kết nối đồng thời MCP Server filesystem, MCP Server Git và MCP Server database trong cùng một phiên làm việc, phối hợp cả 3 để hoàn thành một tác vụ.

Kết nối hệ thống doanh nghiệp

Doanh nghiệp expose một MCP Server duy nhất cho hệ thống nội bộ (ticketing, wiki, CRM...), mọi AI Agent trong tổ chức dùng chung, không cần xây tích hợp riêng cho từng công cụ AI đang dùng.

Thông tin bổ sung

MCP không phải là sản phẩm riêng của Claude — đây là một chuẩn mở, bất kỳ ai cũng có thể viết MCP Server hoặc MCP Client theo chuẩn này. Vì một MCP Server có thể chạy code tuỳ ý và truy cập đúng những gì bạn cấp quyền, nên trước khi thêm bất kỳ MCP Server nào (đặc biệt là MCP Server do cộng đồng viết) vào Claude Code, cần đánh giá độ tin cậy của nó — nguồn gốc, mã nguồn có công khai không, phạm vi quyền yêu cầu là gì. Chương 3 của Section này sẽ đi sâu vào các nguyên tắc an toàn khi cấp quyền cho MCP Server.

Không phải MCP Server nào cũng implement đủ cả 3 primitive — rất nhiều Server chỉ tập trung vào Tools vì đó là dạng phổ biến và hữu ích nhất trong thực tế. Khi kết nối nhiều Server cùng lúc, số lượng Tools khả dụng cho model cũng tăng lên — cần lưu ý điều này có thể làm tăng độ dài ngữ cảnh mỗi lượt gọi (model cần "biết" mô tả của mọi Tool đang kết nối), vì vậy chỉ nên giữ kết nối những MCP Server thực sự cần dùng cho phiên làm việc hiện tại.
