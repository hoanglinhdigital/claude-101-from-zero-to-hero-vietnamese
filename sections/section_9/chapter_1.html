9. Claude Code Hooks / Hook là gì, phân biệt & use case thực tế

Giới thiệu

Hook là cơ chế cho phép "chèn" một shell command tuỳ chỉnh vào những thời điểm cố định trong vòng đời làm việc của Claude Code — ví dụ ngay trước khi một tool được gọi, ngay sau khi tool chạy xong, hoặc khi một phiên làm việc kết thúc. Điểm khác biệt quan trọng nhất so với Skill và Sub-agent (đã học ở Section 3): Hook chạy độc lập với model — không cần Claude Code "quyết định" có nên chạy hay không, chỉ cần điều kiện khai báo trước (event + matcher) khớp là Hook tự động thực thi, giống một quy tắc cố định luôn được áp dụng.

Các tính năng chính

  • Hook cho phép "chèn" shell command vào các thời điểm cố định trong vòng đời một phiên Claude Code (trước/sau khi gọi tool, khi nhận prompt, khi phiên kết thúc hoặc khởi động...).
  • Hook chạy độc lập với model — không cần Claude Code chủ động gọi, cũng không thể "quên" gọi giống như một Skill mô tả chưa đủ rõ.
  • Hook được khai báo trong file cấu hình settings.json (ở phạm vi project hoặc user), không cần viết Markdown hướng dẫn như Skill, không cần system prompt riêng như Sub-agent.
  • Hook nhận thông tin về sự kiện hiện tại (tool nào, input nào, session nào...) qua stdin dạng JSON, và có thể ảnh hưởng đến luồng chạy tiếp theo qua exit code/output.
  • Vì là shell command thông thường, Hook có thể làm bất cứ điều gì command line làm được: format code, ghi log, gửi thông báo, kiểm tra và chặn một hành động trước khi nó xảy ra.

PreToolUse hook đóng vai trò một "trạm kiểm soát" độc lập, chạy trước khi command thực sự được thực thi — hoàn toàn không phụ thuộc việc model có tự nhận ra rủi ro hay không.

Tự động format code (PostToolUse)

Mỗi khi Claude Code sửa hoặc tạo file qua tool Edit/Write, Hook tự động chạy formatter (vd Prettier, Black) ngay sau đó — đảm bảo code luôn đúng chuẩn của team, không phụ thuộc việc model có được nhắc hay không.

Chặn lệnh nguy hiểm (PreToolUse)

Trước khi tool Bash chạy, Hook kiểm tra nội dung command và chặn lại nếu khớp các pattern nguy hiểm như rm -rf, git push --force, hoặc lệnh xoá dữ liệu không có xác nhận — thêm một lớp an toàn nằm ngoài khả năng "tự ý thức" của model.

Thông báo khi hoàn thành tác vụ dài (Stop)

Khi Claude Code hoàn thành một tác vụ mất nhiều thời gian (vd refactor lớn, sinh nhiều file), Hook Stop ghi log và/hoặc hiện thông báo để User biết ngay mà không cần ngồi canh terminal.

Thông tin bổ sung

Chương này chỉ giới thiệu khái niệm, điểm khác biệt cốt lõi và các use case phổ biến của Hook. Danh sách chi tiết các loại event (PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionStart...) và cách khai báo cụ thể trong settings.json được trình bày ở chương tiếp theo.

Lưu ý an toàn khi sử dụng Hook

Hook chạy với đúng quyền của người dùng hiện tại trên máy — không có sandbox riêng biệt như một số cơ chế khác. Một Hook có nội dung sai hoặc độc hại có thể gây hậu quả thật trên máy (xoá file, gửi dữ liệu ra ngoài...), giống như khi tự tay chạy command đó trong terminal.
  • Luôn review kỹ nội dung command trước khi thêm vào settings.json — đặc biệt với Hook copy từ nguồn không tin cậy (repository lạ, script chia sẻ trên mạng chưa kiểm chứng).
  • Tránh để Hook tự ý gửi dữ liệu ra ngoài (gọi API/webhook không rõ mục đích) mà User không kiểm soát được nội dung gửi đi — vì Hook chạy tự động, không có bước xác nhận thủ công như khi model đề xuất chạy một tool thông thường.
  • Test riêng Hook trước khi đưa vào cấu hình chính thức — chạy thử command trực tiếp trong terminal để chắc chắn không có lỗi cú pháp hoặc hành vi ngoài ý muốn, vì lỗi trong Hook có thể làm gián đoạn luồng làm việc của cả phiên Claude Code.
  • Hạn chế phạm vi tác động — ưu tiên Hook chỉ đọc/kiểm tra thay vì Hook có khả năng ghi/xoá dữ liệu trên phạm vi rộng, trừ khi thực sự cần thiết.
Lưu ý: Danh sách event, tên field trong JSON input, và quy ước exit code của Hook có thể được Anthropic bổ sung hoặc thay đổi theo thời gian. Luôn tham khảo tài liệu Claude Code chính thức tại docs.claude.com để có thông tin đầy đủ và mới nhất trước khi áp dụng vào công việc thật.
