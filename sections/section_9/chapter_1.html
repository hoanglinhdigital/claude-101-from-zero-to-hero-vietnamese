9. Claude Code Hooks / Hook là gì & phân biệt với Skill/Sub-agent

Giới thiệu

Hook là cơ chế cho phép "chèn" một shell command tuỳ chỉnh vào những thời điểm cố định trong vòng đời làm việc của Claude Code — ví dụ ngay trước khi một tool được gọi, ngay sau khi tool chạy xong, hoặc khi một phiên làm việc kết thúc. Điểm khác biệt quan trọng nhất so với Skill và Sub-agent (đã học ở Section 3): Hook chạy độc lập với model — không cần Claude Code "quyết định" có nên chạy hay không, chỉ cần điều kiện khai báo trước (event + matcher) khớp là Hook tự động thực thi, giống một quy tắc cố định luôn được áp dụng.

Các tính năng chính

  • Hook cho phép "chèn" shell command vào các thời điểm cố định trong vòng đời một phiên Claude Code (trước/sau khi gọi tool, khi nhận prompt, khi phiên kết thúc hoặc khởi động...).
  • Hook chạy độc lập với model — không cần Claude Code chủ động gọi, cũng không thể "quên" gọi giống như một Skill mô tả chưa đủ rõ.
  • Hook được khai báo trong file cấu hình settings.json (ở phạm vi project hoặc user), không cần viết Markdown hướng dẫn như Skill, không cần system prompt riêng như Sub-agent.
  • Hook nhận thông tin về sự kiện hiện tại (tool nào, input nào, session nào...) qua stdin dạng JSON, và có thể ảnh hưởng đến luồng chạy tiếp theo qua exit code/output.
  • Vì là shell command thông thường, Hook có thể làm bất cứ điều gì command line làm được: format code, ghi log, gửi thông báo, kiểm tra và chặn một hành động trước khi nó xảy ra.

Skill/Sub-agent chỉ được gọi khi model tự nhận diện yêu cầu khớp mô tả; Hook thì ngược lại — luôn chạy trong một process riêng biệt mỗi khi điều kiện (event + matcher) khớp, bất kể model có "muốn" hay không.

So sánh Hook với Skill và Sub-agent

Tiêu chíSkillSub-agentHook
Ai quyết định chạy? Model tự quyết định, dựa trên việc so khớp description với yêu cầu hiện tại Model (Main Agent) tự quyết định gọi qua Task tool, hoặc học viên chỉ định rõ qua /agents Luôn chạy khi điều kiện (event + matcher) khớp — không cần model "muốn" hay "nhớ" gọi
Chạy ở đâu? Trong cùng context của Agent đang chạy — nội dung SKILL.md được nạp thêm vào ngữ cảnh Trong context riêng của Sub-agent — tách biệt với context Agent chính Trong một process hệ điều hành riêng biệt (shell command) — độc lập hoàn toàn với context của model
Dùng khi nào? Quy trình lặp lại, cần model tự nhận diện đúng lúc để áp dụng hướng dẫn cụ thể Việc cần tách phạm vi tool/system prompt riêng, tránh làm phình context của Agent chính Việc cần đảm bảo luôn xảy ra mỗi khi có điều kiện, không phụ thuộc model có quyết định đúng hay không (vd: luôn format code, luôn chặn lệnh nguy hiểm)

Use Cases

Đảm bảo hành động luôn xảy ra

Không phụ thuộc việc model có "nhớ" hay không — vd luôn format lại code ngay sau khi Claude Code sửa file, dù model không được nhắc trong prompt.

Thêm lớp kiểm soát an toàn độc lập

Chặn một hành động nguy hiểm trước khi nó thực thi, mà không phụ thuộc vào việc model có tự nhận ra rủi ro hay không.

Tự động hoá phần "phụ trợ"

Ghi log, gửi thông báo khi hoàn thành tác vụ — những việc không cần chiếm context hay khả năng suy luận của model.

Thông tin bổ sung

Chương này chỉ giới thiệu khái niệm và điểm khác biệt cốt lõi của Hook. Danh sách chi tiết các loại event (PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionStart...) và cách khai báo cụ thể trong settings.json sẽ được trình bày ở chương tiếp theo.

Lưu ý: Danh sách event, tên field trong JSON input, và quy ước exit code của Hook có thể được Anthropic bổ sung hoặc thay đổi theo thời gian. Luôn tham khảo tài liệu Claude Code chính thức tại docs.claude.com để có thông tin đầy đủ và mới nhất trước khi áp dụng vào công việc thật.
