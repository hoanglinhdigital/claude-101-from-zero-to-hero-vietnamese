9. Claude Code Hooks / Các loại event Hook & cấu trúc khai báo trong settings.json

Giới thiệu

Claude Code kích hoạt Hook tại nhiều điểm cố định trong vòng đời một phiên làm việc — mỗi điểm gọi là một event. Mỗi event được khai báo trong file settings.json cùng một matcher (điều kiện khớp, thường theo tên tool) và danh sách command sẽ chạy khi điều kiện đó xảy ra. Hiểu đúng từng event và cấu trúc khai báo là điều kiện cần trước khi tự viết một Hook cho công việc thật.

Các tính năng chính

Các loại event Hook chính

EventThời điểm kích hoạt
PreToolUse Trước khi Claude Code thực thi một tool cụ thể (Edit, Write, Bash...) — dùng để kiểm tra hoặc chặn hành động trước khi nó thực sự xảy ra.
PostToolUse Ngay sau khi một tool đã thực thi xong — phù hợp để xử lý tiếp theo dựa trên kết quả (vd format lại file vừa sửa).
UserPromptSubmit Khi User gửi một prompt mới trong phiên làm việc — trước khi model bắt đầu xử lý prompt đó.
Stop Khi Claude Code hoàn thành một tác vụ/phiên trả lời — không còn hành động tiếp theo cần thực hiện.
SessionStart Khi một phiên làm việc mới của Claude Code được khởi động.
Lưu ý: Đây là các event phổ biến và ổn định nhất tại thời điểm biên soạn khoá học. Claude Code có thể hỗ trợ thêm event khác hoặc điều chỉnh chi tiết theo phiên bản — tham khảo tài liệu chính thức tại docs.claude.com để có danh sách đầy đủ và mới nhất.

Cấu trúc khai báo trong settings.json

  • Hook được khai báo dưới key "hooks" trong settings.json — có thể đặt ở phạm vi user (áp dụng mọi project trên máy) hoặc project (.claude/settings.json, chia sẻ được qua Git cho cả team).
  • Mỗi event (vd PostToolUse) là một danh sách các matcher — mỗi matcher có field "matcher" để khớp theo tên tool (vd "Edit|Write" khớp cả 2 tool) và field "hooks" là danh sách command sẽ chạy khi matcher đó khớp.
  • Mỗi command trong danh sách "hooks" có dạng {"type": "command", "command": "..."}" — chuỗi lệnh sẽ được chạy bằng shell của hệ điều hành (PowerShell/cmd trên Windows).
  • Một số event không gắn với tool cụ thể (vd Stop, SessionStart, UserPromptSubmit) nên thường không cần khai báo "matcher" — chỉ cần danh sách "hooks" chạy mỗi khi event đó xảy ra.
  • Hook nhận thông tin ngữ cảnh (tool nào, input nào, đường dẫn project...) qua stdin dạng JSON — command có thể đọc stdin để xử lý chi tiết hơn, hoặc bỏ qua nếu chỉ cần chạy một hành động cố định.

Một request có thể lặp lại nhiều vòng "gọi tool" (Model → PreToolUse → Tool → PostToolUse → Model) trước khi kết thúc bằng event Stop. Mỗi điểm trên vòng đời này đều có thể chèn Hook riêng.

Ví dụ file settings.json khai báo nhiều Hook

.claude/settings.json{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "echo Kiem tra truoc khi chay Bash..." }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write ." }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File ./notify.ps1" }
        ]
      }
    ]
  }
}

Use Cases

Kết hợp Pre + Post cho một tool

Vừa kiểm tra trước khi Bash chạy (PreToolUse), vừa xử lý kết quả sau khi Edit/Write hoàn tất (PostToolUse) — trong cùng một file cấu hình.

Ghi log toàn bộ phiên làm việc

Dùng SessionStart để ghi lại thời điểm bắt đầu, Stop để ghi thời điểm kết thúc — phục vụ thống kê thời gian sử dụng.

Kiểm soát nội dung prompt đầu vào

UserPromptSubmit cho phép chạy một bước xử lý (vd log lại prompt) trước khi model bắt đầu suy luận.

Thông tin bổ sung

Giá trị "matcher" hoạt động giống một pattern khớp tên tool — có thể khớp chính xác một tool (vd "Bash") hoặc nhiều tool cùng lúc bằng dấu | (vd "Edit|Write"). Nếu bỏ trống hoặc không khai báo "matcher", Hook thường áp dụng cho mọi trường hợp của event đó.

Lưu ý: Cấu trúc JSON input qua stdin (tên field chính xác cho tool name, tool input, exit code đặc biệt để chặn hành động ở PreToolUse...) có thể khác nhau giữa các phiên bản Claude Code. Trước khi viết Hook xử lý sâu vào nội dung stdin, hãy kiểm tra lại tài liệu chính thức tại docs.claude.com để dùng đúng field và đúng quy ước exit code hiện hành.
