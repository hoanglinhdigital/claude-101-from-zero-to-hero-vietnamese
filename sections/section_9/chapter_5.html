9. Claude Code Hooks / Lab - Cấu hình Hook chặn hành động nguy hiểm
Tái sử dụng project: Bài lab này tiếp tục dùng project D:\lab-expense-management đã dùng ở các bài Lab trước (Chapter 3 & 4). Có thể giữ nguyên Hook PostToolUse và Stop đã cấu hình — bài lab này chỉ thêm một Hook mới cho event PreToolUse.

Mục tiêu

  • Cấu hình một Hook PreToolUse khớp với tool Bash, kiểm tra nội dung lệnh trước khi Claude Code thực thi thật.
  • Hook tự động chặn (block) các lệnh nguy hiểm: xoá file/thư mục (dù nằm trong hay ngoài project), git push và git reset.
  • Kiểm chứng bằng cách yêu cầu Claude Code thực hiện lần lượt từng hành động nguy hiểm, xác nhận lệnh bị chặn kèm lý do, đồng thời xác nhận lệnh Bash an toàn khác vẫn chạy bình thường.

Hook PreToolUse chèn một bước kiểm tra ngay trước khi tool Bash thực thi. Nếu nội dung lệnh khớp một trong các pattern nguy hiểm đã định nghĩa, script trả về exit code 2 — Claude Code huỷ lệnh, không cho chạy thật, và trả lý do chặn lại cho Model biết.

Yêu cầu trước khi bắt đầu

  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • PowerShell có thể chạy được file .ps1 — bài lab dùng cờ -ExecutionPolicy Bypass ngay trong command của Hook nên không cần đổi execution policy chung của máy.
  • Project D:\lab-expense-management đã có sẵn (tái sử dụng từ các bài Lab trước).

Các bước thực hành

  1. Bước 1: Tạo thư mục chứa script Hook (nếu chưa có)

    Nếu đã làm bài Lab Chapter 4, thư mục .claude\hooks đã tồn tại — lệnh dưới có thể chạy lại an toàn nhờ -Force.

    cd D:\lab-expense-management
mkdir .claude\hooks -Force
  2. Bước 2: Tạo file script guard-dangerous-commands.ps1

    Script đọc nội dung JSON mà Claude Code truyền qua stdin, lấy ra field tool_input.command (chuỗi lệnh Bash sắp chạy), rồi đối chiếu với danh sách pattern nguy hiểm. Nếu khớp, script ghi lý do ra stderr và thoát với exit 2 để báo cho Claude Code huỷ lệnh.

    Nội dung file như sau:

    .claude/hooks/guard-dangerous-commands.ps1
          
# Doc JSON input tu stdin ma Claude Code truyen vao Hook
$rawInput = [Console]::In.ReadToEnd()
$data = $rawInput | ConvertFrom-Json
$command = $data.tool_input.command

if ([string]::IsNullOrWhiteSpace($command)) {
    exit 0
}

# Danh sach pattern nguy hiem can chan, khong phan biet lenh nam trong hay ngoai project
$dangerousRules = @(
    @{ Pattern = "Remove-Item|(^|\s)rm(\s|$)|(^|\s)del(\s|$)|rmdir|rd\s+/s"; Reason = "Lenh xoa file/thu muc bi chan boi Hook bao ve (ap dung ca file trong lan ngoai project)." },
    @{ Pattern = "git\s+push"; Reason = "Lenh git push bi chan boi Hook bao ve - can nguoi review truoc khi day code len remote repository." },
    @{ Pattern = "git\s+reset"; Reason = "Lenh git reset bi chan boi Hook bao ve - co the lam mat commit hoac lich su thay doi." }
)

foreach ($rule in $dangerousRules) {
    if ($command -match $rule.Pattern) {
        [Console]::Error.WriteLine("[BLOCKED BY HOOK] $($rule.Reason)")
        [Console]::Error.WriteLine("Lenh bi chan: $command")
        exit 2
    }
}

# Khong khop pattern nguy hiem nao -> cho phep chay binh thuong
exit 0
  3. Bước 3: Khai báo Hook PreToolUse trong .claude/settings.json

    Cập nhật file settings.json, thêm event PreToolUse với "matcher": "Bash" — chỉ áp dụng cho tool Bash, gọi script vừa tạo. Giữ lại các Hook PostToolUse và Stop đã cấu hình ở bài Lab trước.

    Nội dung file như sau (đã thêm Hook PreToolUse mới, giữ nguyên PostToolUse & Stop):

    
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/guard-dangerous-commands.ps1" }
        ]
      }
    ]
  }
}
  4. Bước 4: Khởi động lại Claude Code để áp dụng cấu hình mới

    Thoát phiên hiện tại (nếu đang mở) và mở lại trong đúng thư mục project.

    cd D:\lab-expense-management
claude
  5. Cảnh báo: Trước khi thực hiện các lệnh bên dưới, hãy đảm bảo backup source code bằng lệnh git add, git commit, git push origin
    Nếu không, các lệnh git reset hoặc xoá file có thể làm mất dữ liệu quan trọng.
    Bước 5: Kiểm tra chặn — xoá file trong project

    Yêu cầu Claude Code xoá một file bất kỳ nằm trong chính project hiện tại.

    Hãy chạy lệnh Bash để xoá file README.md trong project này.

    Claude Code sẽ cố chạy lệnh (vd rm README.md hoặc Remove-Item README.md), nhưng Hook PreToolUse chặn lại trước khi lệnh thực thi. Claude Code sẽ báo lại rằng hành động bị từ chối kèm lý do từ Hook, và file không bị xoá.

  6. Bước 6: Kiểm tra chặn — xoá file ngoài project

    Yêu cầu Claude Code xoá một file nằm ngoài thư mục project, ví dụ trong C:\Temp, để xác nhận Hook chặn cả trường hợp này chứ không chỉ giới hạn trong project.

    Hãy chạy lệnh Bash để xoá file C:\Temp\test-lab.txt (không cần quan tâm file đó có tồn tại hay không).

    Kết quả tương tự Bước 5 — lệnh bị chặn ngay trước khi thực thi, bất kể đường dẫn đích nằm trong hay ngoài project.

  7. Bước 7: Kiểm tra chặn — git push

    Yêu cầu Claude Code đẩy code lên remote repository.

    Hãy chạy git push để đẩy commit hiện tại lên remote.

    Hook chặn lệnh git push trước khi thực thi, báo lý do "cần người review trước khi đẩy code lên remote".

  8. Bước 8: Kiểm tra chặn — git reset

    Yêu cầu Claude Code hoàn tác các thay đổi bằng git reset.

    Hãy chạy git reset --hard HEAD~1 để hoàn tác commit gần nhất.

    Hook chặn lệnh git reset trước khi thực thi, tránh nguy cơ mất commit hoặc lịch sử thay đổi ngoài ý muốn.

  9. Bước 9: Xác nhận lệnh Bash an toàn vẫn chạy bình thường

    Yêu cầu một lệnh Bash không nằm trong danh sách nguy hiểm, để chắc chắn Hook không chặn nhầm các thao tác bình thường.

    Hãy chạy git status và git log --oneline -5 để xem tình trạng repository hiện tại.

    Cả hai lệnh chạy và trả kết quả bình thường — Hook chỉ chặn đúng các pattern đã định nghĩa (xoá file, git push, git reset), không ảnh hưởng đến các lệnh Bash khác.

✅ Kết quả mong đợi

Các lệnh xoá file (trong lẫn ngoài project), git push và git reset đều bị Hook PreToolUse chặn lại trước khi thực thi thật, kèm thông báo lý do rõ ràng. Trong khi đó, các lệnh Bash an toàn khác (vd git status, git log) vẫn chạy và trả kết quả bình thường.

Troubleshoot

Lỗi: Lệnh nguy hiểm vẫn chạy được, không bị chặn.
Nguyên nhân: Claude Code có thể đã dùng một tool khác ngoài Bash để thực hiện hành động tương đương (vd gọi trực tiếp qua một tool file-system riêng), trong khi Hook hiện chỉ khai báo "matcher": "Bash".
Giải pháp: Kiểm tra Claude Code thực sự đã gọi tool nào bằng transcript của phiên làm việc; nếu cần chặn cả các tool khác, mở rộng "matcher" (vd "Bash|Edit|Write") và bổ sung logic kiểm tra tương ứng trong script cho từng loại tool_input.
Lỗi: PowerShell báo lỗi ConvertFrom-Json hoặc script luôn thoát với lỗi khi Hook chạy.
Nguyên nhân: Nội dung JSON truyền qua stdin không đúng định dạng mong đợi, hoặc field tool_input.command không tồn tại với phiên bản Claude Code đang dùng.
Giải pháp: Test thử script bằng cách tự tạo một file JSON mẫu và pipe vào: Get-Content sample.json | powershell -File .claude\hooks\guard-dangerous-commands.ps1; đối chiếu tên field thực tế trong JSON stdin với tài liệu chính thức tại docs.claude.com.
Lỗi: Hook chặn luôn cả những lệnh an toàn có chứa từ khoá tương tự (vd tên biến chứa chữ "del" hoặc "reset").
Nguyên nhân: Regex pattern trong script đang khớp quá rộng (false positive).
Giải pháp: Tinh chỉnh lại regex trong $dangerousRules cho chặt chẽ hơn (vd thêm ranh giới từ, loại trừ ngữ cảnh cụ thể) và test lại với nhiều câu lệnh mẫu trước khi áp dụng cho công việc thật.
Lưu ý: Field chính xác trong JSON stdin (tên tool, cấu trúc tool_input) và exit code đặc biệt để chặn hành động ở PreToolUse có thể khác nhau giữa các phiên bản Claude Code. Trước khi áp dụng Hook bảo vệ này cho công việc thật, hãy kiểm tra lại tài liệu chính thức tại docs.claude.com để dùng đúng quy ước hiện hành.
Lưu ý: Hook này chỉ là một lớp bảo vệ bổ sung ở tầng ứng dụng, không thay thế cho các biện pháp bảo mật khác (backup định kỳ, branch protection trên remote repository, quyền hạn hệ điều hành...). Không nên xem đây là cơ chế bảo vệ duy nhất cho dữ liệu quan trọng.

Dọn dẹp resource

Bài lab này không tạo resource trên Cloud, chỉ thêm file cấu hình và script cục bộ. Không bắt buộc phải xoá gì — chỉ cần gỡ Hook nếu không muốn tiếp tục chặn các lệnh này khi dùng Claude Code trên project.

Nếu muốn tạm ngưng Hook PreToolUse mà không xoá project, xoá phần "PreToolUse" trong .claude/settings.json (giữ lại "Stop" nếu vẫn muốn dùng):


{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/notify-stop.ps1" }
        ]
      }
    ]
  }
}

Xoá file script guard nếu không muốn giữ lại (tuỳ chọn):

Remove-Item "D:\lab-expense-management\.claude\hooks\guard-dangerous-commands.ps1" -Confirm:$false
Quan trọng: Không xoá thư mục D:\lab-expense-management — project này còn được dùng lại ở các Section khác. Chỉ dọn phần cấu hình Hook nếu không muốn giữ.
