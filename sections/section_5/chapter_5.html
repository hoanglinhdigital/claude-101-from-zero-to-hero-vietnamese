5. Claude cho DevOps & Cloud Engineer / Lab - Sinh & review Terraform hạ tầng cơ bản
Cảnh báo chi phí: Bài lab này tạo resource AWS thật (EC2, S3, DynamoDB, VPC, IAM) và sẽ phát sinh chi phí trên tài khoản AWS của bạn (dù không nhiều với cấu hình t3.micro/on-demand). Bắt buộc phải có AWS account và AWS CLI đã cấu hình (aws configure) trước khi bắt đầu, và phải thực hiện đầy đủ phần Dọn dẹp resource ở cuối bài để tránh bị tính phí ngoài ý muốn.

Mục tiêu

  • Dùng Claude Code sinh file Terraform tạo hạ tầng cơ bản trên AWS: VPC, EC2, DynamoDB Table, S3 bucket, IAM policy.
  • Biết cách viết prompt IaC đầy đủ 4 phần đã học ở Chapter 2 (Resource – Region – Naming/Tag – Ràng buộc bảo mật).
  • Đọc và review kỹ output terraform plan trước khi apply — đây là bước quan trọng nhất của bài lab.
  • Kiểm chứng hạ tầng đã tạo đúng, và dọn dẹp (terraform destroy) toàn bộ resource sau khi hoàn thành.

Claude Code sinh toàn bộ Terraform theo prompt của Engineer; Engineer luôn review kỹ terraform plan trước khi resource thật được tạo trên AWS — IAM role của EC2 chỉ có quyền least-privilege đúng trên bucket S3 và table DynamoDB của bài lab này.

Yêu cầu trước khi bắt đầu

  • AWS account đã có quyền tạo VPC/EC2/S3/DynamoDB/IAM (quyền IAM đủ rộng cho tài khoản cá nhân/sandbox học tập).
  • AWS CLI v2 đã cài đặt và cấu hình: aws configure chạy thành công với Access Key/Secret Key của bạn.
  • Terraform CLI phiên bản 1.5.0 trở lên đã cài đặt (terraform -version chạy được).
  • Claude Code CLI đã cài đặt và đăng nhập thành công (xem lại Section 2).
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Chuẩn bị

  1. Bước 1: Lấy public IP hiện tại để dùng cho biến allowed_ssh_cidr

    (Invoke-RestMethod -Uri "https://api.ipify.org")
203.0.113.10

    Ghi lại IP này, dùng dạng <IP>/32 (vd 203.0.113.10/32) khi chạy terraform plan/apply ở Bước 6.

cd D:\lab-terraform-infra-co-ban

Phần 2: Yêu cầu Claude Code sinh Terraform

  1. Bước 3: Viết prompt IaC đầy đủ theo cấu trúc Resource – Region – Naming/Tag – Ràng buộc bảo mật

    Áp dụng đúng kỹ thuật đã học ở Chapter 2 — nêu rõ từng resource, region, quy ước tên/tag, và ràng buộc bảo mật (không mở SSH public, IAM least-privilege).

    Viết Terraform tạo hạ tầng cơ bản trên AWS, tách thành nhiều file rõ ràng. Yêu cầu cụ thể:

RESOURCE CẦN TẠO:
1. main.tf: provider "aws", required_providers (aws ~>5.0, random ~>3.6 để sinh suffix tên bucket unique).
2. vpc.tf: 1 VPC (CIDR biến vpc_cidr), 1 subnet public (CIDR biến public_subnet_cidr, map_public_ip_on_launch = true), 1 Internet Gateway, 1 route table 0.0.0.0/0 -> Internet Gateway, route table association.
3. ec2.tf: data source lấy AMI Amazon Linux 2023 mới nhất; 1 security group chỉ mở port 22 từ biến allowed_ssh_cidr và port 80 public (0.0.0.0/0); 1 EC2 instance loại t3.micro trong subnet public, gắn iam_instance_profile.
4. dynamodb.tf: 1 DynamoDB table billing_mode = PAY_PER_REQUEST (on-demand), hash_key "id" kiểu String.
5. s3.tf: 1 S3 bucket tên có suffix random để unique toàn cầu, bật versioning, bật server-side encryption AES256, và aws_s3_bucket_public_access_block chặn toàn bộ public access (block_public_acls, block_public_policy, ignore_public_acls, restrict_public_buckets = true).
6. iam.tf: 1 IAM role cho EC2 (assume role từ ec2.amazonaws.com) và 1 IAM policy LEAST-PRIVILEGE — chỉ cho phép s3:GetObject/PutObject/ListBucket đúng trên ARN của bucket ở bước 5, và các action đọc/viết cần thiết (GetItem/PutItem/UpdateItem/DeleteItem/Query/Scan) đúng trên ARN của DynamoDB table ở bước 4. KHÔNG dùng wildcard "*" cho Resource, KHÔNG gắn AdministratorAccess.
7. outputs.tf: output ec2_public_ip, s3_bucket_name, dynamodb_table_name.

REGION: ap-southeast-1 (Singapore), đặt làm default cho variable "region".

NAMING/TAG: mọi resource đặt tên theo pattern ${var.project_name}- (vd ${var.project_name}-vpc, ${var.project_name}-web). Mọi resource gắn tag Project = var.project_name và ManagedBy = "Terraform".

RÀNG BUỘC BẢO MẬT (bắt buộc):
- variables.tf: biến allowed_ssh_cidr KHÔNG có giá trị default, thêm validation block chặn giá trị "0.0.0.0/0" — bắt buộc học viên tự nhập CIDR/IP cụ thể.
- Không mở port nào khác ngoài 22 (giới hạn theo allowed_ssh_cidr) và 80 (public) trên security group.
- IAM policy tuyệt đối không dùng Resource = "*" hay Action = "*".

Sau khi tạo xong toàn bộ file, chạy terraform init và terraform validate để đảm bảo cú pháp đúng, KHÔNG chạy terraform apply.
  2. Bước 4: Duyệt kế hoạch và xác nhận thực thi

    Nếu ở Plan mode, đọc kỹ danh sách file Claude Code dự kiến tạo trước khi Approve. Ở Accept Edits mode, xác nhận từng file được tạo.

Phần 3: Tham khảo nội dung Terraform (đối chiếu với kết quả Claude Code sinh ra)

Nội dung dưới đây là ví dụ tham khảo cho những gì Claude Code nên sinh ra ở Bước 3 — dùng để đối chiếu và review, không cần tự tay gõ lại các file này.

main.tfterraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
    random = {
      source  = "hashicorp/random"
      version = "~> 3.6"
    }
  }
}

provider "aws" {
  region = var.region
}

resource "random_id" "suffix" {
  byte_length = 4
}
variables.tfvariable "region" {
  default = "ap-southeast-1"
}

variable "project_name" {
  default = "claude101-devops-lab"
}

variable "vpc_cidr" {
  default = "10.20.0.0/16"
}

// KHÔNG đặt default = "0.0.0.0/0" — bắt buộc học viên tự nhập CIDR IP
// của mình để tránh vô tình mở SSH cho toàn bộ Internet.
variable "allowed_ssh_cidr" {
  type = string

  validation {
    condition     = var.allowed_ssh_cidr != "0.0.0.0/0"
    error_message = "Không được dùng 0.0.0.0/0 cho allowed_ssh_cidr."
  }
}

variable "instance_type" {
  default = "t3.micro"
}
ec2.tfresource "aws_security_group" "web" {
  name   = "${var.project_name}-web-sg"
  vpc_id = aws_vpc.main.id

  ingress {
    # SSH — chỉ từ allowed_ssh_cidr, KHÔNG mở 0.0.0.0/0
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.allowed_ssh_cidr]
  }

  ingress {
    # HTTP — public
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Project   = var.project_name
    ManagedBy = "Terraform"
  }
}

resource "aws_instance" "web" {
  ami                    = data.aws_ami.amazon_linux.id
  instance_type          = var.instance_type
  subnet_id              = aws_subnet.public.id
  vpc_security_group_ids = [aws_security_group.web.id]
  iam_instance_profile   = aws_iam_instance_profile.ec2_profile.name

  tags = {
    Name      = "${var.project_name}-web"
    Project   = var.project_name
    ManagedBy = "Terraform"
  }
}
iam.tf# Least-privilege: chỉ đúng action cần thiết, chỉ trên đúng ARN của
# bucket S3 và table DynamoDB của bài lab — KHÔNG dùng wildcard "*".
data "aws_iam_policy_document" "app_access" {
  statement {
    sid = "S3ReadWriteAppBucket"
    actions = [
      "s3:GetObject", "s3:PutObject", "s3:ListBucket",
    ]
    resources = [
      aws_s3_bucket.app_data.arn,
      "${aws_s3_bucket.app_data.arn}/*",
    ]
  }

  statement {
    sid = "DynamoDBReadWriteAppTable"
    actions = [
      "dynamodb:GetItem", "dynamodb:PutItem",
      "dynamodb:UpdateItem", "dynamodb:DeleteItem",
      "dynamodb:Query", "dynamodb:Scan",
    ]
    resources = [aws_dynamodb_table.app_table.arn]
  }
}

  1. Bước 5: Khởi tạo Terraform

  2. Bước 6: Chạy terraform plan — đây là bước REVIEW quan trọng nhất

    Thay 203.0.113.10/32 bằng IP thật của bạn lấy ở Bước 1. Đọc kỹ toàn bộ output: số resource sẽ được tạo (Plan: N to add, 0 to change, 0 to destroy), đặc biệt kiểm tra kỹ block aws_security_group (không có cidr_blocks = ["0.0.0.0/0"] nào cho port 22) và block IAM policy (không có "Resource": "*").

  3. Bước 7: (Khuyến nghị) Yêu cầu Claude Code giải thích plan bằng ngôn ngữ dễ hiểu

    Áp dụng mẹo đã học ở Chapter 1 — nhờ Claude Code diễn giải lại các thay đổi trong plan trước khi tự mình quyết định apply.

    Giải thích các thay đổi trong terraform plan này bằng ngôn ngữ dễ hiểu, đặc biệt chỉ rõ: resource nào sẽ bị tạo/sửa/xoá, security group có mở port nào ra 0.0.0.0/0 ngoài port 80 không, và IAM policy có dùng wildcard "*" ở đâu không.
  4. Bước 8: Chỉ apply sau khi đã review kỹ plan ở Bước 6-7

    Dùng đúng file plan đã lưu ở Bước 6 (tfplan) để đảm bảo apply đúng những gì đã review, không bị lệch do state thay đổi giữa lúc plan và apply.

    terraform apply tfplan

✅ Kết quả mong đợi

Lệnh terraform apply hoàn thành không lỗi, terraform output trả về đúng 3 giá trị. Trang web mặc định trên EC2 truy cập được qua HTTP. Security group chỉ mở SSH từ đúng IP của bạn (không phải 0.0.0.0/0), và IAM role gắn cho EC2 chỉ có quyền đọc/viết đúng bucket S3 và table DynamoDB vừa tạo — kiểm tra lại trên AWS Console > IAM > Roles.

Troubleshoot

Lỗi: terraform plan báo lỗi allowed_ssh_cidr is required hoặc validation fail.
Nguyên nhân: Biến allowed_ssh_cidr không có giá trị mặc định (đúng như thiết kế an toàn), hoặc bạn đã vô tình truyền 0.0.0.0/0.
Giải pháp: Luôn truyền -var="allowed_ssh_cidr=<IP-của-bạn>/32" khi chạy plan/apply, dùng đúng IP lấy được ở Bước 1.
Lỗi: terraform apply báo Error: creating S3 Bucket: BucketAlreadyExists.
Nguyên nhân: Tên S3 bucket phải unique toàn cầu trên AWS; suffix ngẫu nhiên (random_id.suffix) trùng với bucket đã tồn tại (hiếm gặp) hoặc project_name đã được dùng bởi người khác.
Giải pháp: Đổi giá trị project_name thành một chuỗi khác đặc trưng hơn (vd thêm tên của bạn), chạy lại terraform apply.
Lỗi: Không SSH được vào EC2 dù đã dùng đúng key pair.
Nguyên nhân: IP public của bạn đã thay đổi (IP động) sau khi apply, không còn khớp với allowed_ssh_cidr đã cấu hình trong security group.
Giải pháp: Lấy lại IP hiện tại (Bước 1), chạy lại terraform apply -var="allowed_ssh_cidr=<IP-mới>/32" để cập nhật rule security group.

Dọn dẹp resource

Bắt buộc thực hiện: Toàn bộ resource trong bài lab này là hạ tầng AWS thật (EC2, S3, DynamoDB, VPC, IAM) và sẽ tiếp tục phát sinh chi phí nếu không được xoá. Luôn chạy terraform destroy ngay sau khi hoàn thành bài lab, không để resource chạy qua đêm nếu không cần thiết. 
cd D:\lab-terraform-infra-co-ban

terraform destroy `
  -var="allowed_ssh_cidr=203.0.113.10/32" `
  -auto-approve

Sau khi lệnh trên hoàn thành, kiểm tra lại trên AWS Console (EC2, VPC, S3, DynamoDB, IAM) để xác nhận không còn resource nào sót lại từ bài lab — đặc biệt lưu ý S3 bucket có versioning bật sẵn đôi khi cần xoá thủ công các object version cũ nếu terraform destroy báo lỗi bucket chưa rỗng.
