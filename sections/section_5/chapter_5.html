5. Claude cho Tester / QA / Lab - Test tự động end-to-end với Playwright
Bài lab này tiếp tục dùng project D:\lab-expense-management và app đã triển khai ở Section 4 (https://claude101expensemanagement.vercel.app). Nếu chưa hoàn thành, hãy quay lại thực hiện trước. Ở các bài trước ta test ở tầng API (K6); bài này test ở tầng giao diện người dùng (UI) — thao tác thật trên trình duyệt.

Playwright là gì?

Playwright là framework kiểm thử end-to-end (E2E) do Microsoft phát triển, cho phép điều khiển trình duyệt thật (Chromium, Firefox, WebKit) bằng script để mô phỏng đúng hành vi người dùng: mở trang, nhập liệu, click, chờ phần tử xuất hiện, kiểm tra nội dung. So với test API, test E2E kiểm được cả luồng thực tế xuyên suốt: UI → API → database → UI.

  • Auto-wait — tự chờ phần tử UI sẵn sàng trước khi thao tác, giảm test "flaky".
  • Locator theo vai trò — getByRole, getByLabel, getByText bám theo ngữ nghĩa giao diện thay vì CSS selector dễ vỡ.
  • Trace, screenshot, video — tự ghi lại bằng chứng mỗi khi test fail.
  • HTML report — báo cáo trực quan có sẵn, không cần cài thêm.
  • Codegen — npx playwright codegen <url> ghi lại thao tác tay thành code mẫu.

Mục tiêu

  • Cài đặt Playwright vào project và làm quen cú pháp cơ bản (test, page, locator, expect).
  • Đóng gói quy ước viết test E2E (cấu trúc file, locator theo vai trò, Page Object, dữ liệu login, đường dẫn output) vào Skill playwright-e2e-generator.
  • Dùng Claude Code sinh test E2E tự động dựa trên thiết kế màn hình (mô tả màn hình / ảnh mockup / file screen design) thông qua Skill.
  • Thực thi bộ test, tạo HTML report, thu thập screenshot và trace cho các case fail, đọc báo cáo để khoanh vùng lỗi.

Phần 1: Cài đặt Playwright

  1. Bước 1: Cài Playwright và trình duyệt vào project 
    cd D:\lab-expense-management
npm init playwright@latest -- --quiet --browser=chromium --lang=ts

    Lệnh này tạo playwright.config.ts, thư mục tests/ (ví dụ mẫu) và tải sẵn Chromium. Khi được hỏi thư mục test, chọn mặc định; không cần thêm GitHub Actions cho bài lab này. 

    npx playwright install chromium
  2. Bước 2: Cấu hình base URL và thư mục test

    Sửa playwright.config.ts để trỏ về app đã deploy và bật thu thập bằng chứng khi fail:

    playwright.config.tsimport { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './e2e-test',
  reporter: [['html', { open: 'never' }]],
  use: {
    baseURL: process.env.BASE_URL || 'https://claude101expensemanagement.vercel.app',
    screenshot: 'only-on-failure',
    trace: 'retain-on-failure',
    video: 'retain-on-failure',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  ],
});

    Tạo file .env chứa thông tin đăng nhập test (đừng commit file này):

    .env# Tài khoản dùng riêng cho test E2E
E2E_EMAIL=tester@example.com
E2E_PASSWORD=Tester@12345

Phần 2: Làm quen cú pháp cơ bản

  1. Bước 3: Tự viết tay 1 test đơn giản để hiểu 4 khái niệm cốt lõi

    Tạo file e2e-test/smoke.spec.ts. Test này mở trang chủ và kiểm tra tiêu đề — chưa cần login:

    e2e-test/smoke.spec.tsimport { test, expect } from '@playwright/test';

// test()  : khai báo một kịch bản kiểm thử
test('trang đăng nhập hiển thị đúng', async ({ page }) => {
  // page   : 1 tab trình duyệt do Playwright điều khiển
  await page.goto('/login');

  // locator: trỏ tới phần tử theo VAI TRÒ / nhãn, không dùng CSS dễ vỡ
  const emailInput = page.getByLabel('Email');
  const submitBtn = page.getByRole('button', { name: /Đăng nhập/i });

  // expect : khẳng định trạng thái mong đợi (tự auto-wait)
  await expect(emailInput).toBeVisible();
  await expect(submitBtn).toBeEnabled();
});
    npx playwright test e2e-test/smoke.spec.ts
  2. Bước 4: Dùng Codegen để xem Playwright "dịch" thao tác tay thành code

    Lệnh dưới mở trình duyệt kèm cửa sổ ghi code; bạn thao tác tay, Playwright sinh script tương ứng. Dùng để học cú pháp locator nhanh:

    npx playwright codegen https://claude101expensemanagement.vercel.app
    Ưu tiên getByRole / getByLabel / getByText. Chỉ dùng locator('css=...') hoặc getByTestId khi không có cách nào theo vai trò.

# Playwright E2E Generator

## Nguyên tắc
- Góc nhìn người dùng cuối: thao tác qua UI trên trình duyệt, KHÔNG gọi thẳng API trừ bước dọn dữ liệu.
- Input người dùng cung cấp: thiết kế màn hình (mô tả / ảnh / đường dẫn file), URL app, danh sách luồng cần kiểm.
- Với mỗi màn hình sinh đủ 3 nhóm test: happy path, validate/edge case, negative case (đúng theo ràng buộc ghi trên thiết kế).

## Quy ước code
1. Đặt file tại e2e-test/<tên-màn-hình>.spec.ts. Mỗi test() độc lập, không phụ thuộc thứ tự chạy.
2. Locator ưu tiên getByRole / getByLabel / getByText; chỉ dùng getByTestId khi bắt buộc.
3. Dùng fixture login chung tại e2e-test/fixtures/auth.ts (đọc E2E_EMAIL / E2E_PASSWORD từ .env); test cần đăng nhập thì import fixture này.
4. Màn hình phức tạp: tách Page Object vào e2e-test/pages/<Tên>Page.ts.
5. Assertion dùng expect() của Playwright (auto-wait), không dùng page.waitForTimeout cố định.
6. Test tạo dữ liệu phải tự xoá ở afterEach (gọi API xoá hoặc thao tác UI xoá).
7. Không tự sửa playwright.config.ts đã có; giả định server đã deploy sẵn.

## Sau khi sinh
- Liệt kê bảng: Màn hình | Test case | Nhóm | Locator chính | Assertion.
- Nhắc người dùng chạy: npx playwright test và npx playwright show-report.

Troubleshoot

Lỗi: Claude không gọi Skill playwright-e2e-generator, hoặc sinh test không theo quy ước (không dùng fixture login, dùng CSS selector cứng).
Nguyên nhân: Skill chưa được nạp (phiên mở trước khi tạo Skill), hoặc prompt không chứa từ khoá khớp description.
Giải pháp: Kiểm tra /skills, mở lại phiên; nêu tường minh "dùng skill playwright-e2e-generator" ở đầu prompt như Bước 8.
Lỗi: browserType.launch: Executable doesn't exist.
Nguyên nhân: Chưa tải binary trình duyệt.
Giải pháp: Chạy npx playwright install chromium.
Lỗi: Test fail ở bước login với Timeout ... waiting for locator.
Nguyên nhân: Locator không khớp giao diện thật (nhãn nút/ô nhập khác mô tả), hoặc sai E2E_EMAIL/E2E_PASSWORD.
Giải pháp: Dùng npx playwright codegen <url> để lấy đúng locator; kiểm tra lại tài khoản trong .env.
Lỗi: Test "flaky" — lúc pass lúc fail.
Nguyên nhân: Dùng page.waitForTimeout() cố định thay vì expect() auto-wait, hoặc test phụ thuộc dữ liệu test khác để lại.
Giải pháp: Thay chờ cứng bằng await expect(locator).toBeVisible(); đảm bảo mỗi test tự tạo và tự xoá dữ liệu trong afterEach.
