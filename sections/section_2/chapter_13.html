2. Làm quen với Claude / Lab: Viết CLAUDE.md cho project mẫu

Mục tiêu

  • Hiểu vai trò của file CLAUDE.md — system prompt riêng cho một project, tự động được Claude Code nạp vào ngữ cảnh mỗi khi khởi động.
  • Biết cách xác định những thông tin nào nên đưa vào CLAUDE.md để Claude Code tạo ra code nhất quán, đúng định hướng project.
  • Thực hành viết một file CLAUDE.md đầy đủ cho project mẫu — ứng dụng quản lý chi tiêu (Expense Management), phản ánh đúng tech stack, quy tắc styling, quy tắc icon và quy tắc thiết kế database với Prisma.
  • Kiểm chứng được CLAUDE.md thực sự ảnh hưởng tới cách Claude Code sinh code.

CLAUDE.md không phải là tài liệu để đọc thủ công — mỗi khi Claude Code khởi động trong thư mục project, nội dung file này được tự động nạp làm ngữ cảnh nền, ảnh hưởng tới toàn bộ code được sinh ra sau đó.

Yêu cầu trước khi bắt đầu

  • Project Next.js đã được tạo ở Lab trước (Chapter 10), nằm tại D:\lab-claude-code-cli — bài lab này dùng lại đúng thư mục này.
  • Claude Code CLI đã đăng nhập và chạy được trong thư mục project.
  • Không cần cài đặt Prisma/MySQL/Docker thật ở bài lab này — CLAUDE.md là tài liệu định hướng, phần cài đặt thực tế cho ứng dụng quản lý chi tiêu sẽ được thực hành đầy đủ ở Section 4.

Các bước thực hành

  1. Bước 1: Mở lại project và khởi động Claude Code

    Di chuyển vào thư mục project đã tạo ở Lab trước và khởi động lại Claude Code.

    cd D:\lab-claude-code-cli
claude
  2. Bước 2: Mô tả định hướng mới cho project

    Vì project hiện tại chỉ là một Next.js base project, cần cung cấp ngữ cảnh rằng từ giờ project này được định hướng phát triển thành ứng dụng quản lý chi tiêu — làm nền để Claude Code viết CLAUDE.md đúng định hướng.

    Từ giờ project này sẽ được phát triển thành một ứng dụng quản lý chi tiêu cá nhân (Expense Management App), giúp người dùng ghi nhận, theo dõi và thống kê thu nhập/chi tiêu hằng ngày. Hãy ghi nhớ nội dung này và tạm thời chưa làm bất kỳ điều gì.
  3. Bước 3: Yêu cầu viết file CLAUDE.md đầy đủ

    Gửi yêu cầu chi tiết, nêu rõ từng mục cần có trong CLAUDE.md — nêu càng cụ thể, Claude Code càng viết đúng ý và ít phải chỉnh sửa lại nhiều lần.

    Viết (hoặc cập nhật nếu đã có) file CLAUDE.md ở thư mục gốc project, gồm đầy đủ các mục sau:

1. Tổng quan project: ứng dụng quản lý chi tiêu (Expense Management App) — mục đích, đối tượng sử dụng.
2. Công nghệ sử dụng: Next.js dùng chung cho cả backend (API routes) và frontend, Prisma ORM, MySQL chạy qua Docker container cho môi trường local, Tailwind CSS cho toàn bộ styling.
3. Quy tắc phối màu & styling:
   - Màu chủ đạo: xanh dương (#2563eb) cho hành động chính (button, link).
   - Xanh lá (#16a34a) cho số liệu thu nhập, đỏ (#dc2626) cho số liệu chi tiêu.
   - Chỉ dùng Tailwind utility class, không dùng inline style, không viết CSS file riêng trừ khi thực sự cần.
4. Quy tắc sử dụng icon:
   - Dùng thống nhất bộ icon "lucide-react", không trộn lẫn với bộ icon khác.
   - Icon dùng trong danh mục chi tiêu phải có ý nghĩa rõ ràng (vd: icon xe cho "Di chuyển", icon giỏ hàng cho "Mua sắm").
5. Quy tắc thiết kế database với Prisma:
   - Toàn bộ schema định nghĩa trong file prisma/schema.prisma, không tạo bảng thủ công qua SQL trực tiếp.
   - Có script seed (prisma/seed.ts) để tạo dữ liệu mẫu ban đầu (danh mục chi tiêu mặc định, 1 user demo).
   - Mỗi khi thay đổi schema, bắt buộc tạo migration bằng "npx prisma migrate dev --name ", không sửa trực tiếp trên database.

Trình bày rõ theo từng heading markdown tương ứng.
  4. Bước 4: Review nội dung file CLAUDE.md vừa tạo

    Mở file để kiểm tra Claude Code đã phản ánh đầy đủ 5 mục yêu cầu ở Bước 3 hay chưa.

    Nội dung tham khảo nên có cấu trúc tương tự như sau:

    # CLAUDE.md — Expense Management App

## Tổng quan project
Ứng dụng quản lý chi tiêu cá nhân, giúp người dùng ghi nhận, theo dõi
và thống kê thu nhập/chi tiêu hằng ngày.

## Công nghệ sử dụng
- Next.js: dùng chung cho backend (API routes) và frontend.
- Prisma ORM kết nối MySQL.
- MySQL chạy qua Docker container cho môi trường local.
- Tailwind CSS cho toàn bộ styling.

## Quy tắc phối màu & styling
- Màu chủ đạo: xanh dương #2563eb cho hành động chính.
- Xanh lá #16a34a cho thu nhập, đỏ #dc2626 cho chi tiêu.
- Chỉ dùng Tailwind utility class, không dùng inline style.

## Quy tắc sử dụng icon
- Dùng thống nhất bộ icon lucide-react.
- Icon danh mục chi tiêu phải có ý nghĩa rõ ràng, dễ nhận diện.

## Quy tắc thiết kế database (Prisma)
- Định nghĩa schema trong prisma/schema.prisma, không tạo bảng
  thủ công qua SQL trực tiếp.
- Có script seed (prisma/seed.ts) tạo dữ liệu mẫu ban đầu.
- Mỗi khi thay đổi schema: chạy
  `npx prisma migrate dev --name `,
  không sửa trực tiếp trên database.
  5. Bước 5: Kiểm chứng CLAUDE.md có tác dụng với styling & icon

    Bắt đầu một hội thoại mới (/clear) để CLAUDE.md được nạp lại từ đầu, sau đó yêu cầu Claude Code tạo một component nhỏ — không nhắc lại quy tắc màu sắc/icon, chỉ để xem Claude Code có tự áp dụng đúng theo CLAUDE.md hay không.

    /clear
    Tạo layout tổng cho ứng dụng gồm 5 tab bên dưới màn hình: Home, Analytic, Record, History, Setting. Nút để click sang 5 tab này sử dụng các icon tương ứng: icon Home, icon Analytic, icon dấu (+), icon History, icon Bánh răng. Tạm thời chưa tạo nội dung cho các tab, chỉ hiển thị chữ "to be implemented".
    Tạo các component cần thiết cho trang "Record", bao gồm: Loại giao dịch chọn giữa: Income hoặc Expense, số tiền, tài khoản (dropdown list), nút save, nút clear
    Nếu CLAUDE.md phát huy đúng tác dụng, component sinh ra sẽ tự dùng màu xanh dương làm màu chính, dùng icon từ lucide-react và chỉ dùng Tailwind class — dù prompt không nhắc lại các quy tắc này.
  6. Bước 6: Kiểm chứng quy tắc thiết kế database

    Yêu cầu Claude Code phác thảo schema Prisma cho 2 bảng cơ bản của ứng dụng, để kiểm tra Claude có tuân đúng quy tắc "định nghĩa trong schema.prisma + có seed data + nhắc migration khi đổi schema" đã khai báo trong CLAUDE.md.

    Phác thảo schema Prisma cho 2 bảng: Category (danh mục chi tiêu) và Expense (khoản chi tiêu, liên kết tới Category). Nhắc lại quy trình cần làm sau khi tạo/sửa schema này theo đúng quy tắc project.
    Câu trả lời đúng theo CLAUDE.md phải nhắc tới việc chạy npx prisma migrate dev để tạo migration, và có gợi ý cập nhật script seed — thay vì chỉ đưa ra schema rồi dừng lại.

Troubleshoot

Lỗi: Claude Code không áp dụng đúng quy tắc trong CLAUDE.md khi sinh code.
Nguyên nhân: CLAUDE.md nằm sai vị trí (không phải thư mục gốc project), hoặc phiên làm việc hiện tại được mở trước khi file CLAUDE.md được tạo/sửa nên chưa nạp lại.
Giải pháp: Xác nhận file nằm đúng tại thư mục gốc (cùng cấp với package.json), chạy /clear hoặc khởi động lại claude để nạp lại ngữ cảnh mới nhất.
Lỗi: Nội dung CLAUDE.md quá dài, lặp lại nhiều thông tin không cần thiết.
Nguyên nhân: Yêu cầu ban đầu quá chung, Claude Code tự thêm nhiều mục không được yêu cầu.
Giải pháp: Yêu cầu Claude Code rút gọn lại, chỉ giữ đúng 5 mục đã thống nhất; nên liệt kê rõ từng mục cần có ngay từ prompt đầu tiên như ở Bước 3.
Lỗi: Component/schema sinh ra ở Bước 5, 6 không đúng theo quy tắc đã đặt ra.
Nguyên nhân: Quy tắc trong CLAUDE.md viết chưa đủ rõ ràng, hoặc mang tính mô tả chung thay vì chỉ dẫn cụ thể (actionable).
Giải pháp: Viết lại quy tắc theo dạng chỉ dẫn cụ thể (vd thay "dùng màu sắc hợp lý" bằng đúng mã màu hex như trong Bước 3), yêu cầu Claude Code chỉnh sửa lại đúng phần quy tắc chưa rõ.

Best Practices khi viết CLAUDE.md

CLAUDE.md càng rõ ràng, cụ thể và ngắn gọn thì Claude Code càng tuân theo đúng và ít tốn context mỗi phiên làm việc. Nguyên tắc chung: viết CLAUDE.md giống như hướng dẫn nhanh cho một thành viên mới join team — chỉ những gì họ cần biết để code đúng convention, không phải toàn bộ tài liệu dự án.

✅ Nên làm

  • Viết ngắn gọn, dùng bullet point cụ thể — ưu tiên chỉ dẫn hành động (actionable) hơn mô tả chung.
  • Đưa vào các quy tắc lặp lại nhiều lần: tech stack, cấu trúc thư mục, coding convention, quy tắc styling/icon, quy trình database.
  • Dùng ví dụ cụ thể — mã màu hex, tên thư viện chính xác, tên lệnh đầy đủ — thay vì mô tả mơ hồ.
  • Đặt file ở thư mục gốc project để Claude Code tự động nạp mỗi khi khởi động.
  • Cập nhật lại ngay khi project có thay đổi lớn (đổi tech stack, thêm quy tắc mới).
  • Tách thêm CLAUDE.md riêng ở thư mục con nếu khu vực đó có quy tắc đặc thù khác với quy tắc chung.

❌ Không nên

  • Nhồi nhét toàn bộ tài liệu dự án (business logic chi tiết, ghi chú họp, kế hoạch) vào CLAUDE.md.
  • Viết quy tắc chung, không có tính hành động (vd "code phải sạch", "UI phải đẹp").
  • Để file quá dài (hàng trăm dòng) — vừa khó đọc, vừa tốn context ở mọi phiên làm việc.
  • Đưa thông tin nhạy cảm (API key, mật khẩu, secret) vào CLAUDE.md — file này thường được commit vào Git.
  • Viết quy tắc mâu thuẫn nhau giữa các phần, hoặc để file lỗi thời khi project đã thay đổi convention.
  • Yêu cầu Claude Code tự bịa ra quy tắc khi chưa chắc — nên tự xác nhận rõ trước khi đưa vào CLAUDE.md.

Thông tin bổ sung

Claude Code có thể nạp file CLAUDE.md từ nhiều vị trí khác nhau, mỗi vị trí phục vụ một phạm vi ảnh hưởng khác nhau. Hiểu rõ các vị trí này giúp tổ chức quy tắc hợp lý — quy tắc riêng cho project, quy tắc riêng cho một thư mục con, hoặc quy tắc áp dụng cho mọi project trên máy.

Vị tríĐường dẫnPhạm vi ảnh hưởng
Thư mục gốc project <project>/CLAUDE.md Áp dụng cho toàn bộ project — vị trí phổ biến nhất, nơi khai báo tech stack, quy tắc styling, quy tắc database như thực hành ở bài lab này.
Thư mục .claude <project>/.claude/CLAUDE.md Tương đương thư mục gốc, nhưng gom chung với các file cấu hình khác của Claude Code (settings, commands...) trong cùng một thư mục ẩn.
Thư mục con <project>/<thư_mục_con>/CLAUDE.md Chỉ nạp thêm khi Claude Code làm việc trong thư mục con đó — dùng khi một phần project (vd module backend, frontend, infra riêng) có quy tắc đặc thù khác với quy tắc chung.
Thư mục user trên máy local ~/.claude/CLAUDE.md (Windows: C:\Users\<user>\.claude\CLAUDE.md) Áp dụng cho mọi project Claude Code chạy trên máy — phù hợp cho quy tắc cá nhân, không phụ thuộc project cụ thể (vd phong cách trả lời, ngôn ngữ giao tiếp).
Khi nhiều file CLAUDE.md cùng tồn tại (user, project, thư mục con), Claude Code nạp và kết hợp tất cả — quy tắc ở thư mục con không thay thế mà bổ sung thêm cho quy tắc ở thư mục gốc và thư mục user.
