10. Phát triển phần mềm với Spec-Kit Framework / Cấu trúc file sinh ra bởi Spec-Kit & slash command /speckit.*

Giới thiệu

Mỗi giai đoạn SDD đã học ở chương trước đều gắn với một slash command /speckit.* cụ thể trong Claude Code, và mỗi slash command đó lại sinh ra (hoặc cập nhật) một file Markdown cố định trong project. Nắm rõ file nào nằm ở đâu, sinh ra từ lệnh nào giúp học viên dễ dàng đọc lại, chỉnh sửa tay khi cần, và hiểu Claude Code đang lấy ngữ cảnh từ đâu ở mỗi bước.

Các tính năng chính

  • Toàn bộ file Spec-Kit sinh ra đều là Markdown thuần — đọc được trực tiếp, chỉnh sửa tay được, và theo dõi lịch sử thay đổi qua Git như code thông thường.
  • .specify/memory/constitution.md — nguyên tắc chung của cả project, dùng chung cho mọi tính năng, chỉ nằm ở một vị trí duy nhất.
  • Mỗi tính năng có một thư mục riêng dưới specs/{feature-id}/ — chứa spec.md, plan.md, tasks.md của riêng tính năng đó, không lẫn với tính năng khác.
  • Slash command sau khi specify init được Claude Code tự nhận diện — gõ /speckit. trong khung chat để xem gợi ý danh sách lệnh khả dụng.
  • Mỗi slash command đọc ngữ cảnh từ file do lệnh trước đó sinh ra (vd /speckit.plan đọc lại spec.md và constitution.md) — giữ tính liên kết xuyên suốt cả quy trình.

Mỗi slash command vừa đọc lại file do lệnh trước sinh ra để giữ ngữ cảnh, vừa tạo file output riêng cho giai đoạn hiện tại — tạo thành một chuỗi phụ thuộc tuyến tính từ Constitution đến Implementation.

Cấu trúc thư mục Spec-Kit sinh ra

.specify/
  memory/
    constitution.md — nguyên tắc chung của cả project
  templates/ (nội bộ) — template Spec-Kit dùng để sinh các file trên
specs/
  001-xuat-bao-cao/ (ví dụ feature-id)
    spec.md — đặc tả tính năng, sinh bởi /speckit.specify
    plan.md — kế hoạch kỹ thuật, sinh bởi /speckit.plan
    tasks.md — danh sách task, sinh bởi /speckit.tasks
Lưu ý: Tên thư mục {feature-id} (vd 001-xuat-bao-cao) do Spec-Kit tự đặt dựa trên số thứ tự và tên tính năng khi chạy /speckit.specify. Quy ước đặt tên chính xác có thể điều chỉnh theo phiên bản — quan trọng là luôn có một thư mục riêng cho mỗi tính năng chứa đủ 3 file spec.md, plan.md, tasks.md.

5 slash command chính

Slash commandGiai đoạnFile sinh ra / cập nhật
/speckit.constitution Constitution .specify/memory/constitution.md
/speckit.specify Specification specs/{feature-id}/spec.md
/speckit.plan Planning specs/{feature-id}/plan.md
/speckit.tasks Task Breakdown specs/{feature-id}/tasks.md
/speckit.implement Implementation Code thực tế trong project (đánh dấu tiến độ ngược lại vào tasks.md)

Use Cases

Đọc lại spec khi quên yêu cầu

Không cần nhớ toàn bộ ngữ cảnh trong đầu — mở lại specs/{feature-id}/spec.md bất cứ lúc nào để xem lại yêu cầu gốc.

Review đặc tả như review code

Vì là file Markdown trong Git, có thể tạo Pull Request riêng cho thay đổi spec, để đồng nghiệp review trước khi cho Claude Code implement.

Nhiều tính năng song song

Mỗi tính năng có thư mục specs/{feature-id}/ riêng — theo dõi được nhiều tính năng đang ở giai đoạn khác nhau cùng lúc.

Thông tin bổ sung

Ngoài 5 slash command chính ở trên, Spec-Kit có thể bổ sung thêm các lệnh phụ trợ khác theo thời gian (vd lệnh hỗ trợ làm rõ yêu cầu, kiểm tra môi trường...). Gõ /speckit. trong Claude Code để xem danh sách lệnh khả dụng thực tế trên phiên bản đang cài, hoặc tham khảo github.com/github/spec-kit để có thông tin đầy đủ và mới nhất.
