10. Phát triển phần mềm với Spec-Kit Framework / Spec-Kit: 6 giai đoạn SDD & cấu trúc file

Giới thiệu

Spec-Kit (github.com/github/spec-kit) là công cụ mã nguồn mở do GitHub phát hành, hiện thực hoá triết lý Spec-Driven Development đã học ở chương trước thành một quy trình cụ thể có thể dùng ngay. Spec-Kit chia quy trình Spec-Driven Development đó thành 6 giai đoạn nối tiếp nhau — Constitution → Specification → Planning → Task Breakdown → Implementation → Convergence — mỗi giai đoạn tương ứng một slash command /speckit-* trong Claude Code và sinh ra (hoặc cập nhật) một file Markdown cụ thể trong project. User chỉ cần gõ slash command ngay trong Claude Code để đi qua từng giai đoạn, không cần tự tay tạo file hay nhớ cấu trúc đặc tả.

Các tính năng chính

  • Đóng gói sẵn slash command và template cho từng giai đoạn SDD (constitution, specify, plan, tasks, implement, converge) — User không cần tự thiết kế cấu trúc đặc tả từ đầu.
  • Hỗ trợ nhiều AI coding agent khác nhau (Claude Code là một trong số đó) — mỗi agent nhận đúng định dạng slash command phù hợp; với Claude Code, các lệnh này được cài dưới dạng Agent Skill (.claude/skills/speckit-*/SKILL.md) thay vì file lệnh thông thường.
  • Toàn bộ file Spec-Kit sinh ra đều là Markdown thuần — đọc được trực tiếp, chỉnh sửa tay được, và theo dõi lịch sử thay đổi qua Git như code thông thường.
  • Không phụ thuộc dịch vụ cloud nào — .specify/, specs/ đều là thư mục nằm ngay trong project.
  • Mỗi slash command đọc ngữ cảnh từ file do lệnh trước đó sinh ra (vd /speckit-plan đọc lại spec.md và constitution.md) — giữ tính liên kết xuyên suốt cả quy trình.
  • Ngoài Spec-Driven Development, Spec-Kit còn hai quy trình độc lập cài thêm qua extension: bug fixing (/speckit-bug-assess, /speckit-bug-fix, /speckit-bug-test) và idea assessment (/speckit-assess-*) — chương này chỉ tập trung vào quy trình SDD cốt lõi.

6 giai đoạn chạy nối tiếp trong cùng một vòng đời tính năng. Constitution chỉ cần định nghĩa một lần cho cả project (có thể tái sử dụng cho nhiều tính năng), còn 5 giai đoạn sau lặp lại cho mỗi tính năng mới. Implementation và Convergence thường lặp qua lại (/speckit-implement → /speckit-converge → sửa tiếp → …) cho đến khi Convergence báo cáo "Converged".

1. Constitution Nguyên tắc chung, ràng buộc không thể vi phạm của cả project (vd luôn validate input, không phá vỡ API hiện có) — định nghĩa một lần, dùng lại cho mọi tính năng.
2. Specification Đặc tả chi tiết một tính năng cụ thể: tính năng làm gì, cho ai, hành vi mong đợi — chưa bàn đến công nghệ triển khai.
3. Planning Lập kế hoạch kỹ thuật — chọn thư viện, thiết kế API/route, các thay đổi cần thực hiện để đáp ứng spec.
4. Task Breakdown Chia kế hoạch thành các task nhỏ, cụ thể, có thể thực hiện và kiểm tra độc lập từng phần.
5. Implementation Claude Code thực thi lần lượt từng task, sinh/sửa code thực tế.
6. Convergence Chạy /speckit-converge để Claude Code tự đối chiếu kết quả implement với spec ban đầu, báo cáo trạng thái Converged hoặc phần còn lệch — lặp lại Implementation cho phần lệch đến khi hội tụ.

Mỗi slash command vừa đọc lại file do lệnh trước sinh ra để giữ ngữ cảnh, vừa tạo file output riêng cho giai đoạn hiện tại — tạo thành một chuỗi phụ thuộc tuyến tính từ Constitution đến Convergence, với vòng lặp implement ⇄ converge cho đến khi hội tụ.

Lưu ý: Với Claude Code, Spec-Kit cài các slash command dưới dạng Agent Skill — mỗi lệnh là một thư mục riêng trong .claude/skills/ chứa file SKILL.md, thay vì một file lệnh đơn giản như các phiên bản Spec-Kit cũ hơn. Về phía người dùng, cách gọi lệnh (gõ /speckit-tên-lệnh trong Claude Code) không đổi. Tên thư mục {feature-id} (vd 001-xuat-bao-cao) do Spec-Kit tự đặt dựa trên số thứ tự và tên tính năng khi chạy /speckit-specify. Quy ước đặt tên chính xác có thể điều chỉnh theo phiên bản — quan trọng là luôn có một thư mục riêng cho mỗi tính năng chứa đủ 3 file spec.md, plan.md, tasks.md.

6 slash command chính

Slash commandGiai đoạnFile sinh ra / cập nhật
/speckit-constitution Constitution .specify/memory/constitution.md
/speckit-specify Specification specs/{feature-id}/spec.md
/speckit-plan Planning specs/{feature-id}/plan.md
/speckit-tasks Task Breakdown specs/{feature-id}/tasks.md
/speckit-implement Implementation Code thực tế trong project (đánh dấu tiến độ ngược lại vào tasks.md)
/speckit-converge Convergence Báo cáo đối chiếu code với spec.md — trạng thái Converged hoặc phần còn lệch
Lưu ý: Ngoài 6 lệnh chính trên, Spec-Kit còn các lệnh phụ trợ tuỳ chọn dùng làm quality gate: /speckit-clarify (làm rõ điểm mơ hồ trong spec trước khi plan), /speckit-checklist (sinh checklist kiểm tra theo domain) và /speckit-analyze (đối chiếu tính nhất quán giữa spec/plan/tasks trước khi implement). Đây là các lệnh tuỳ chọn, không bắt buộc trong vòng đời 6 giai đoạn.

Use Cases

Tính năng phức tạp, nhiều bước

Chia nhỏ theo 6 giai đoạn giúp kiểm soát tốt hơn một tính năng có nhiều phần liên quan (API, UI, xử lý dữ liệu) so với một prompt duy nhất.

Review đặc tả như review code

Vì spec/plan/task đều là file Markdown trong Git, có thể tạo Pull Request riêng cho thay đổi spec, để đồng nghiệp review trước khi cho Claude Code implement.

Nhiều tính năng song song

Mỗi tính năng có thư mục specs/{feature-id}/ riêng — theo dõi được nhiều tính năng đang ở giai đoạn khác nhau cùng lúc, không lẫn với nhau.

Thông tin bổ sung

6 giai đoạn không bắt buộc phải chạy tuyến tính một chiều — /speckit-converge ở giai đoạn cuối chủ động đối chiếu kết quả implement với spec ban đầu; nếu phát hiện lệch, quay lại cập nhật spec/plan/task rồi chạy lại /speckit-implement cho phần bị lệch, thay vì sửa tay trực tiếp vào code (điều này sẽ làm code và spec lệch nhau trở lại — đúng vấn đề SDD muốn tránh). Lặp lại cặp /speckit-implement → /speckit-converge đến khi báo cáo Convergence xác nhận Converged. Ngoài 6 slash command chính ở trên, Spec-Kit liên tục bổ sung thêm lệnh và cả những quy trình độc lập khác (bug fixing, idea assessment) theo thời gian. Gõ /speckit- trong Claude Code để xem danh sách lệnh khả dụng thực tế trên phiên bản đang cài.

Lưu ý: Tên slash command, tên file output và cấu trúc thư mục ở trên là các quy ước ổn định của Spec-Kit tại thời điểm biên soạn khoá học nhưng có thể thay đổi theo phiên bản mới — luôn tham khảo github.com/github/spec-kit để có thông tin đầy đủ và mới nhất. Bài lab tiếp theo sẽ hướng dẫn cài đặt specify CLI và khởi tạo Spec-Kit từng bước cụ thể trên một project mới hoàn toàn.
