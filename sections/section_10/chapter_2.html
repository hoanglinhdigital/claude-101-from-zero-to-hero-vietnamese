10. Phát triển phần mềm với Spec-Kit Framework / Spec-Kit: 6 giai đoạn SDD & cấu trúc file

Giới thiệu

Spec-Kit (github.com/github/spec-kit) là công cụ mã nguồn mở do GitHub phát hành, hiện thực hoá triết lý Spec-Driven Development đã học ở chương trước thành một quy trình cụ thể có thể dùng ngay. Spec-Kit chia quy trình đó thành 6 giai đoạn nối tiếp nhau — Constitution → Specification → Planning → Task Breakdown → Implementation → Convergence — mỗi giai đoạn tương ứng một slash command /speckit.* trong Claude Code và sinh ra (hoặc cập nhật) một file Markdown cụ thể trong project. User chỉ cần gõ slash command ngay trong Claude Code để đi qua từng giai đoạn, không cần tự tay tạo file hay nhớ cấu trúc đặc tả.

Các tính năng chính

  • Đóng gói sẵn slash command và template cho từng giai đoạn SDD (constitution, specify, plan, tasks, implement) — User không cần tự thiết kế cấu trúc đặc tả từ đầu.
  • Hỗ trợ nhiều AI coding agent khác nhau (Claude Code là một trong số đó) — mỗi agent nhận đúng định dạng slash command phù hợp.
  • Toàn bộ file Spec-Kit sinh ra đều là Markdown thuần — đọc được trực tiếp, chỉnh sửa tay được, và theo dõi lịch sử thay đổi qua Git như code thông thường.
  • Không phụ thuộc dịch vụ cloud nào — .specify/, specs/ đều là thư mục nằm ngay trong project.
  • Mỗi slash command đọc ngữ cảnh từ file do lệnh trước đó sinh ra (vd /speckit.plan đọc lại spec.md và constitution.md) — giữ tính liên kết xuyên suốt cả quy trình.

6 giai đoạn chạy nối tiếp trong cùng một vòng đời tính năng. Constitution chỉ cần định nghĩa một lần cho cả project (có thể tái sử dụng cho nhiều tính năng), còn 5 giai đoạn sau lặp lại cho mỗi tính năng mới.

1. Constitution Nguyên tắc chung, ràng buộc không thể vi phạm của cả project (vd luôn validate input, không phá vỡ API hiện có) — định nghĩa một lần, dùng lại cho mọi tính năng.
2. Specification Đặc tả chi tiết một tính năng cụ thể: tính năng làm gì, cho ai, hành vi mong đợi — chưa bàn đến công nghệ triển khai.
3. Planning Lập kế hoạch kỹ thuật — chọn thư viện, thiết kế API/route, các thay đổi cần thực hiện để đáp ứng spec.
4. Task Breakdown Chia kế hoạch thành các task nhỏ, cụ thể, có thể thực hiện và kiểm tra độc lập từng phần.
5. Implementation Claude Code thực thi lần lượt từng task, sinh/sửa code thực tế.
6. Convergence Đối chiếu kết quả implement với spec ban đầu, xác nhận đúng yêu cầu, khép lại vòng SDD cho tính năng đó.

Mỗi slash command vừa đọc lại file do lệnh trước sinh ra để giữ ngữ cảnh, vừa tạo file output riêng cho giai đoạn hiện tại — tạo thành một chuỗi phụ thuộc tuyến tính từ Constitution đến Implementation.

Cấu trúc thư mục Spec-Kit sinh ra

.specify/
  memory/
    constitution.md — nguyên tắc chung của cả project
  templates/ (nội bộ) — template Spec-Kit dùng để sinh các file trên
specs/
  001-xuat-bao-cao/ (ví dụ feature-id)
    spec.md — đặc tả tính năng, sinh bởi /speckit.specify
    plan.md — kế hoạch kỹ thuật, sinh bởi /speckit.plan
    tasks.md — danh sách task, sinh bởi /speckit.tasks
Lưu ý: Tên thư mục {feature-id} (vd 001-xuat-bao-cao) do Spec-Kit tự đặt dựa trên số thứ tự và tên tính năng khi chạy /speckit.specify. Quy ước đặt tên chính xác có thể điều chỉnh theo phiên bản — quan trọng là luôn có một thư mục riêng cho mỗi tính năng chứa đủ 3 file spec.md, plan.md, tasks.md.

Use Cases

Tính năng phức tạp, nhiều bước

Chia nhỏ theo 6 giai đoạn giúp kiểm soát tốt hơn một tính năng có nhiều phần liên quan (API, UI, xử lý dữ liệu) so với một prompt duy nhất.

Review đặc tả như review code

Vì spec/plan/task đều là file Markdown trong Git, có thể tạo Pull Request riêng cho thay đổi spec, để đồng nghiệp review trước khi cho Claude Code implement.

Nhiều tính năng song song

Mỗi tính năng có thư mục specs/{feature-id}/ riêng — theo dõi được nhiều tính năng đang ở giai đoạn khác nhau cùng lúc, không lẫn với nhau.

Thông tin bổ sung

6 giai đoạn không bắt buộc phải chạy tuyến tính một chiều — nếu ở giai đoạn Convergence phát hiện kết quả chưa đúng spec, hoàn toàn có thể quay lại cập nhật spec/plan/task rồi chạy lại Implementation cho phần bị lệch, thay vì sửa tay trực tiếp vào code (điều này sẽ làm code và spec lệch nhau trở lại — đúng vấn đề SDD muốn tránh). Ngoài 5 slash command chính ở trên, Spec-Kit có thể bổ sung thêm các lệnh phụ trợ khác theo thời gian (vd lệnh hỗ trợ làm rõ yêu cầu, kiểm tra môi trường...). Gõ /speckit. trong Claude Code để xem danh sách lệnh khả dụng thực tế trên phiên bản đang cài.

Lưu ý: Tên slash command, tên file output và cấu trúc thư mục ở trên là các quy ước ổn định của Spec-Kit tại thời điểm biên soạn khoá học nhưng có thể thay đổi theo phiên bản mới — luôn tham khảo github.com/github/spec-kit để có thông tin đầy đủ và mới nhất. Bài lab tiếp theo sẽ hướng dẫn cài đặt specify CLI và khởi tạo Spec-Kit từng bước cụ thể trên project lab-expense-management đã tạo ở Section 4.
