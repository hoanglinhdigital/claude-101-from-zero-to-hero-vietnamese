10. Phát triển phần mềm với Spec-Kit Framework / Các giai đoạn trong quy trình SDD

Giới thiệu

Spec-Kit chia quy trình Spec-Driven Development thành 6 giai đoạn nối tiếp nhau, mỗi giai đoạn tương ứng một slash command /speckit.* và sinh ra (hoặc cập nhật) một file cụ thể: Constitution → Specification → Planning → Task Breakdown → Implementation → Convergence. Hiểu rõ từng giai đoạn làm gì, nhận input nào và tạo ra output nào là điều kiện để dùng Spec-Kit hiệu quả trong 4 bài lab tiếp theo.

Các tính năng chính

  • Constitution — định nghĩa nguyên tắc chung, ràng buộc không thể vi phạm của cả project (vd luôn validate input, không phá vỡ API hiện có).
  • Specification — đặc tả chi tiết một tính năng cụ thể: tính năng làm gì, cho ai, hành vi mong đợi — chưa bàn đến công nghệ triển khai.
  • Planning — lập kế hoạch kỹ thuật: chọn thư viện, thiết kế API/route, các thay đổi cần thực hiện để đáp ứng spec.
  • Task Breakdown — chia kế hoạch thành các task nhỏ, cụ thể, có thể thực hiện và kiểm tra độc lập từng phần.
  • Implementation — AI agent (Claude Code) thực thi lần lượt từng task, sinh/sửa code thực tế.
  • Convergence — đối chiếu kết quả implement với spec ban đầu, xác nhận đúng yêu cầu, khép lại vòng SDD cho tính năng đó.

6 giai đoạn chạy nối tiếp trong cùng một vòng đời tính năng. Constitution chỉ cần định nghĩa một lần cho cả project (có thể tái sử dụng cho nhiều tính năng), còn 5 giai đoạn sau lặp lại cho mỗi tính năng mới.

Tổng quan 6 giai đoạn

1. Constitution Nguyên tắc chung của project — định nghĩa một lần, dùng lại cho mọi tính năng.
2. Specification Đặc tả "làm gì" cho một tính năng cụ thể — chưa bàn công nghệ.
3. Planning Kế hoạch kỹ thuật — chọn thư viện, thiết kế API, các thay đổi cần làm.
4. Task Breakdown Chia plan thành các task nhỏ, cụ thể, kiểm tra được từng phần.
5. Implementation Claude Code thực thi lần lượt từng task, sinh code thật.
6. Convergence Đối chiếu kết quả với spec ban đầu, xác nhận đúng yêu cầu.

Use Cases

Tính năng phức tạp, nhiều bước

Chia nhỏ theo 6 giai đoạn giúp kiểm soát tốt hơn một tính năng có nhiều phần liên quan (API, UI, xử lý dữ liệu) so với một prompt duy nhất.

Cần đối chiếu lại sau khi code xong

Giai đoạn Convergence đóng vai trò checklist, giúp phát hiện sớm phần nào Claude Code hiểu sai hoặc bỏ sót so với spec.

Constitution dùng lại nhiều lần

Một khi định nghĩa xong nguyên tắc chung, các tính năng sau chỉ cần chạy lại từ giai đoạn Specification, không cần lặp lại Constitution.

Thông tin bổ sung

6 giai đoạn không bắt buộc phải chạy tuyến tính một chiều — nếu ở giai đoạn Convergence phát hiện kết quả chưa đúng spec, hoàn toàn có thể quay lại cập nhật spec/plan/task rồi chạy lại Implementation cho phần bị lệch, thay vì sửa tay trực tiếp vào code (điều này sẽ làm code và spec lệch nhau trở lại — đúng vấn đề SDD muốn tránh).

Lưu ý: Tên slash command và tên file output ở trên là các quy ước ổn định của Spec-Kit tại thời điểm biên soạn khoá học. Chương tiếp theo sẽ đi sâu vào cấu trúc file cụ thể và bảng chi tiết từng slash command.
