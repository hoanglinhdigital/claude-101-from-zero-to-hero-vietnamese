10. Phát triển phần mềm với Spec-Kit Framework / Lab - Implement & đối chiếu kết quả
Bài lab này tiếp tục dùng project D:\lab-codekids-blocks và tasks.md của tính năng "kéo thả khối lệnh vượt mê cung" đã tạo ở Chapter 5. Đây là bài lab khép lại vòng SDD bằng giai đoạn Implementation và Convergence — Chapter 7 tiếp theo sẽ triển khai sản phẩm hoàn chỉnh này lên Vercel và TiDB.

Mục tiêu

  • Dùng /speckit.implement để Claude Code triển khai lần lượt các task đã chia ở tasks.md.
  • Theo dõi tiến độ thực thi từng task, xác nhận từng bước trước khi cho phép ghi file.
  • Kiểm chứng màn chơi kéo thả vượt mê cung chạy đúng thực tế trên trình duyệt sau khi implement xong.
  • Đối chiếu kết quả thực tế với spec.md ban đầu (giai đoạn Convergence) — xác nhận không thiếu, không lệch yêu cầu.

Claude Code thực thi tuần tự từng task trong tasks.md, đánh dấu hoàn thành ngược lại vào file này. Sau khi hết task, bước Convergence đối chiếu toàn bộ kết quả với spec.md gốc để xác nhận đúng yêu cầu — khép vòng SDD cho tính năng lõi của CodeKids Blocks.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Chapter 5 — specs/{feature-id}/plan.md và tasks.md đã có nội dung chi tiết, đủ nhỏ để implement từng phần.
  • Docker Desktop đang chạy, MySQL container (codekids-mysql) đã khởi động lại nếu trước đó đã docker compose down.
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Triển khai bằng /speckit.implement

  1. Bước 1: Khởi động lại MySQL container và Claude Code 
    cd D:\lab-codekids-blocks
docker compose up -d
claude
  2. Bước 2: Chạy /speckit.implement để bắt đầu triển khai

    Claude Code sẽ đọc tasks.md và thực thi lần lượt từng task theo đúng thứ tự đã chia ở Chapter 5.

    /speckit.implement
  3. Bước 3: Theo dõi và xác nhận từng task

    Ở mỗi task (cập nhật schema.prisma, tạo lib/maze-engine.ts, viết unit test, tạo API route, thêm UI kéo thả...), đọc qua thay đổi được đề xuất trước khi xác nhận cho ghi file — đặc biệt chú ý logic trong lib/maze-engine.ts vì đây là phần chấm điểm chính thức, ảnh hưởng trực tiếp đến tính công bằng của trò chơi.

  4. Bước 4: Chạy migration Prisma khi task tạo/sửa schema.prisma hoàn tất 
    npx prisma migrate dev --name add_level_player_progress
  5. Bước 5: Chạy unit test sau khi các task liên quan lib/maze-engine.ts hoàn tất

    Tự chạy lại test độc lập, không chỉ tin vào báo cáo "đã pass" của Claude Code.

    npm test
PASS  __tests__/maze-engine.test.ts
  runProgram
    ✓ nhân vật đến đúng ô đích khi chuỗi lệnh hợp lệ
    ✓ dừng lại và báo va chạm khi đi vào ô tường
  6. Bước 6: Chờ Claude Code hoàn thành toàn bộ task và báo cáo tổng kết

    Sau khi hết task trong tasks.md, đọc lại tổng kết các file đã tạo/sửa trước khi qua bước kiểm chứng thực tế.

Phần 2: Kiểm chứng thực tế và Convergence

  1. Bước 7: Khởi động dev server và thử màn chơi trên trình duyệt 
    npm run dev

    Mở http://localhost:3000, nhập một biệt danh bất kỳ, kéo các khối lệnh (Đi tới, Rẽ trái, Rẽ phải, Lặp lại) vào khung làm việc ở màn 1, bấm "Chạy" và xác nhận nhân vật di chuyển từng bước đúng theo chuỗi lệnh đã ghép, đến đích thì hiển thị số sao đạt được.

  2. Bước 8: Thử trường hợp va chạm và chưa hoàn thành

    Ghép một chuỗi lệnh cố tình khiến nhân vật đi vào tường — xác nhận trò chơi dừng đúng vị trí va chạm, hiển thị thông báo thân thiện (không dùng từ "Thua"/"Sai") và cho phép sửa lại ngay. Sau đó thử một chuỗi lệnh ngắn hơn cần thiết để xác nhận trường hợp "chưa hoàn thành" (hết lệnh mà chưa đến đích) hiển thị đúng và không lưu kết quả.

  3. Bước 9: Thử màn khó hơn cần dùng khối Lặp lại

    Ở màn có độ khó cao hơn, thử ghép chuỗi lệnh không dùng khối Lặp lại (nhiều khối Đi tới lặp lại thủ công) và so sánh số sao đạt được với khi dùng khối Lặp lại để tối ưu — xác nhận cơ chế chấm sao theo số khối lệnh hoạt động đúng như đã đặc tả.

  4. Bước 10: Đối chiếu kết quả với spec.md — giai đoạn Convergence

    Mở lại spec.md ở Chapter 4, lập checklist từng yêu cầu (9 mục đã liệt kê) và xác nhận từng mục đã đáp ứng đúng trên thực tế.

    Đọc lại spec.md của tính năng kéo thả vượt mê cung và so sánh với code đã implement. Liệt kê rõ: yêu cầu nào đã đáp ứng đầy đủ, yêu cầu nào còn thiếu hoặc chưa đúng (nếu có), kèm vị trí file liên quan.
  5. Bước 11: Xử lý phần chưa khớp (nếu có)

    Nếu Bước 10 phát hiện sai lệch, quay lại cập nhật spec.md/plan.md/tasks.md cho đúng thực tế mong muốn rồi chạy lại /speckit.implement cho phần liên quan — không sửa tay trực tiếp vào code mà bỏ qua việc cập nhật spec.

✅ Kết quả mong đợi

Màn chơi kéo thả khối lệnh vượt mê cung hoạt động đúng với cả 3 kết quả (đến đích, va chạm, chưa hoàn thành), chấm sao đúng theo số khối lệnh đã dùng, chơi được ngay bằng biệt danh không cần đăng nhập. Toàn bộ yêu cầu trong spec.md được đối chiếu và xác nhận đã đáp ứng — hoàn tất giai đoạn Convergence, khép vòng SDD cho tính năng lõi của CodeKids Blocks.

Troubleshoot

Lỗi: /speckit.implement dừng giữa chừng, báo lỗi khi thực thi một task cụ thể.
Nguyên nhân: Task đó phụ thuộc vào một package chưa được cài đặt đúng, hoặc mô tả task chưa đủ rõ so với thực tế project.
Giải pháp: Đọc thông báo lỗi cụ thể, yêu cầu Claude Code cài package còn thiếu (npm install) hoặc làm rõ lại task đó rồi tiếp tục /speckit.implement — các task đã hoàn thành trước đó vẫn được giữ nguyên.
Lỗi: Kéo thả khối lệnh trên trình duyệt bị giật, thả không đúng vị trí trong khung làm việc.
Nguyên nhân: Logic tính vị trí thả (drop) trong component workspace chưa xử lý đúng toạ độ tương đối khi khung làm việc có scroll hoặc padding.
Giải pháp: Yêu cầu Claude Code kiểm tra lại hàm xử lý sự kiện ondrop, tính toạ độ dựa trên getBoundingClientRect() của khung làm việc thay vì toạ độ tuyệt đối trên trang.
Lỗi: Số sao lưu vào database khác với số sao hiển thị trên giao diện.
Nguyên nhân: UI tự tính sao ở client bằng logic riêng thay vì dùng đúng kết quả server trả về từ /api/progress.
Giải pháp: Yêu cầu Claude Code sửa UI để hiển thị đúng số sao lấy từ response của API — chỉ dùng logic client để xem trước hiệu ứng di chuyển, không dùng để tính điểm cuối cùng.

Dọn dẹp resource

Bài lab này không tạo resource cloud tính phí. Chỉ cần dừng container MySQL khi tạm nghỉ giữa các buổi thực hành:

docker compose down

Có thể commit toàn bộ thay đổi (bao gồm .specify/, specs/, và code tính năng lõi) vào Git để lưu lại minh chứng cho cả quy trình SDD đã thực hiện. Giữ nguyên project để tiếp tục ở Chapter 7 — triển khai lên Vercel và TiDB.
