10. Phát triển phần mềm với Spec-Kit Framework / Lab - Constitution & Specify cho tính năng mới
Bài lab này tiếp tục dùng project D:\lab-expense-management đã khởi tạo Spec-Kit ở Chapter 5. Nếu chưa hoàn thành Chapter 5, hãy quay lại thực hiện trước.
Phân biệt với tính năng đã làm ở Section 4 Chapter 6: Tính năng thực hành ở Section 10 là "xuất báo cáo chi tiêu theo khoảng thời gian (từ ngày - đến ngày) dạng PDF hoặc Excel" — khác với tính năng "xuất CSV danh sách chi tiêu theo tháng" đã làm ở Section 4. Hai tính năng độc lập, tồn tại song song trong project, không thay thế nhau. Lý do chọn một tính năng mới: để thấy rõ toàn bộ quy trình SDD từ đầu (spec → plan → task → code) trên một yêu cầu chưa từng được Claude Code implement trước đó.

Mục tiêu

  • Dùng /speckit.constitution định nghĩa nguyên tắc chung cho project lab-expense-management.
  • Dùng /speckit.specify đặc tả chi tiết tính năng mới: xuất báo cáo chi tiêu theo khoảng thời gian, dạng PDF/Excel.
  • Xem lại file constitution.md và spec.md được Claude Code sinh ra, đối chiếu với yêu cầu đã nêu.

/speckit.specify đọc lại constitution.md vừa tạo để đảm bảo bản đặc tả tính năng mới tuân theo nguyên tắc chung đã định nghĩa cho project.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Chapter 5 — project D:\lab-expense-management đã có thư mục .specify/, slash command /speckit.* đã dùng được trong Claude Code.
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Định nghĩa Constitution cho project

  1. Bước 1: Vào project và khởi động Claude Code 
    cd D:\lab-expense-management
claude
  2. Bước 2: Chạy /speckit.constitution với nguyên tắc chung của project

    Nêu rõ các ràng buộc quan trọng nhất mà mọi tính năng sau này (bao gồm tính năng xuất báo cáo) phải tuân theo.

    /speckit.constitution Định nghĩa nguyên tắc chung cho project lab-expense-management (Next.js + Prisma + MySQL):
1. Mọi API route mới phải validate input đầu vào (kiểu dữ liệu, giá trị hợp lệ) trước khi xử lý, trả lỗi rõ ràng (status code + message) nếu input không hợp lệ.
2. Không được thay đổi hoặc phá vỡ contract của các API route đã có (GET/POST /api/expenses, /api/categories, /api/expenses/export CSV, /api/expenses/summary) — chỉ được thêm route mới.
3. Giữ style code nhất quán với phần code hiện có: TypeScript, dùng Prisma Client đã cấu hình sẵn, không thêm ORM/thư viện trùng chức năng đã có.
4. Mọi logic nghiệp vụ quan trọng (tính toán, tạo file) nên tách thành hàm thuần trong thư mục lib/, tương tự cách đã làm với lib/csv-export.ts, để dễ viết unit test.
5. Không tự ý xoá hoặc sửa dữ liệu trong database khi implement tính năng mới, trừ khi được yêu cầu rõ ràng.
  3. Bước 3: Xem lại file constitution.md được sinh ra

    Đọc lại toàn bộ nội dung để xác nhận Claude Code ghi đúng và đủ các nguyên tắc đã nêu.

    code .specify\memory\constitution.md

Phần 2: Đặc tả tính năng xuất báo cáo

  1. Bước 4: Chạy /speckit.specify cho tính năng xuất báo cáo

    Mô tả rõ tính năng làm gì (hành vi, input, output mong đợi) — chưa cần nói đến thư viện hay tên file kỹ thuật, việc đó dành cho /speckit.plan ở bài lab sau.

    /speckit.specify Thêm tính năng xuất báo cáo chi tiêu theo khoảng thời gian cho app Quản lý chi tiêu. Đây là tính năng MỚI, khác với tính năng xuất CSV theo tháng đã có. Yêu cầu:
1. Người dùng chọn một khoảng thời gian bất kỳ (ngày bắt đầu, ngày kết thúc) trên trang chủ, không giới hạn theo tháng như tính năng CSV hiện tại.
2. Người dùng chọn định dạng xuất báo cáo: PDF hoặc Excel (.xlsx).
3. Báo cáo gồm: danh sách khoản chi tiêu trong khoảng thời gian đã chọn (ngày, danh mục, tiêu đề, số tiền), tổng chi tiêu theo từng danh mục, và tổng chi tiêu toàn bộ khoảng thời gian.
4. Nếu không có khoản chi tiêu nào trong khoảng thời gian đã chọn, báo cáo vẫn được tạo ra bình thường, hiển thị rõ "Không có dữ liệu" và tổng bằng 0.
5. Tính năng này không thay đổi hay xoá tính năng xuất CSV theo tháng đã có — cả hai cùng tồn tại, phục vụ hai nhu cầu khác nhau.
  2. Bước 5: Trả lời các câu hỏi làm rõ (nếu Claude Code hỏi lại)

    Ở giai đoạn Specification, Claude Code có thể hỏi lại để làm rõ các điểm còn mơ hồ trong yêu cầu (vd định dạng ngày cụ thể, giới hạn khoảng thời gian tối đa). Trả lời rõ ràng để bản spec chính xác nhất có thể trước khi sang giai đoạn Planning.

  3. Bước 6: Xem lại file spec.md được sinh ra

    Xác nhận thư mục tính năng mới đã được tạo dưới specs/ và nội dung spec.md phản ánh đúng yêu cầu đã nêu ở Bước 4.

    dir specs

    Mở file spec.md vừa được tạo (tên thư mục cụ thể tuỳ Spec-Kit tự đặt, ví dụ specs/001-xuat-bao-cao-chi-tieu/spec.md) để đọc lại toàn bộ nội dung.

    code specs\001-xuat-bao-cao-chi-tieu\spec.md

✅ Kết quả mong đợi

.specify/memory/constitution.md chứa đủ 5 nguyên tắc đã nêu. Thư mục specs/{feature-id}/spec.md mới xuất hiện, mô tả đầy đủ hành vi tính năng xuất báo cáo theo khoảng thời gian, dạng PDF/Excel — không nhắc đến hoặc trùng lặp với tính năng xuất CSV theo tháng đã có.

Troubleshoot

Lỗi: /speckit.constitution báo đã có file constitution.md, hỏi có muốn ghi đè không.
Nguyên nhân: File đã được tạo sẵn (rỗng hoặc mẫu) khi chạy specify init ở Chapter 5.
Giải pháp: Xác nhận ghi đè (merge/overwrite) — vì đây là lần đầu định nghĩa nguyên tắc thật cho project.
Lỗi: Bản spec.md sinh ra vẫn nhắc đến logic của tính năng xuất CSV cũ, gây nhầm lẫn hai tính năng.
Nguyên nhân: Prompt ở Bước 4 chưa nhấn đủ mạnh sự khác biệt, hoặc Claude Code đọc lẫn ngữ cảnh từ code cũ.
Giải pháp: Chạy lại /speckit.specify, nhấn rõ hơn "đây là tính năng độc lập, không sửa/không dựa trên route export CSV hiện có".

Dọn dẹp resource

Bài lab này chỉ tạo file Markdown (constitution.md, spec.md) trong project — không tạo resource nào trên Cloud, không có gì cần dọn dẹp. Giữ nguyên toàn bộ file vừa tạo để tiếp tục ở Chapter 7 (Plan & Tasks).
