10. Phát triển phần mềm với Spec-Kit Framework / Lab - Plan & Tasks cho tính năng Kéo thả vượt mê cung
Bài lab này tiếp tục dùng project D:\lab-codekids-blocks và bản đặc tả spec.md của tính năng "kéo thả khối lệnh vượt mê cung" đã tạo ở Chapter 4. Nếu chưa hoàn thành Chapter 4, hãy quay lại thực hiện trước.

Mục tiêu

  • Dùng /speckit.plan lập kế hoạch kỹ thuật: mô hình dữ liệu mê cung/khối lệnh, engine thực thi, cơ chế kéo thả, API route và schema Prisma.
  • Dùng /speckit.tasks chia kế hoạch kỹ thuật thành các task nhỏ, thực hiện độc lập được từng phần.
  • Xem lại file plan.md và tasks.md được sinh ra, đối chiếu với spec.md ở Chapter 4.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Chapter 4 — constitution.md và specs/{feature-id}/spec.md đã tồn tại và đúng nội dung tính năng kéo thả vượt mê cung.
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Lập kế hoạch kỹ thuật với /speckit.plan

  1. Bước 1: Vào project và khởi động Claude Code 
    cd D:\lab-codekids-blocks
claude
  2. Bước 2: Chạy /speckit.plan với định hướng kỹ thuật cụ thể

    Đưa lại các quyết định kỹ thuật đã phân tích ở Chapter 4 (Phần 2) vào prompt, để Claude Code lập kế hoạch bám sát đúng hướng thay vì tự chọn giải pháp khác.

    /speckit.plan Lập kế hoạch kỹ thuật để triển khai tính năng trong spec.md. Định hướng cụ thể:
1. Mô hình dữ liệu Prisma: model Level (id, tên, dữ liệu mê cung dạng JSON gồm lưới ô, điểm xuất phát, điểm đích, số khối lệnh tối thiểu để đạt 3 sao), model Player (id, nickname, tạo tự động khi lần đầu nhập biệt danh, không cần mật khẩu), model Progress (playerId, levelId, số sao đạt được, số khối lệnh đã dùng, thời điểm hoàn thành, unique theo playerId+levelId — lưu lần chơi tốt nhất).
2. Engine thực thi khối lệnh: hàm thuần trong lib/maze-engine.ts, nhận vào dữ liệu mê cung (từ Level) và mảng khối lệnh (bao gồm khối Lặp lại chứa khối con), trả về danh sách từng bước di chuyển của nhân vật và kết quả cuối (đến đích/va tường/chưa hoàn thành) — không phụ thuộc DOM hay React, để chạy được cả ở client (xem trước khi lưu) lẫn server (chấm điểm chính thức, tránh gian lận từ client).
3. Giao diện kéo thả: dùng HTML5 Drag and Drop API (draggable, ondragstart, ondrop) thuần, không thêm thư viện drag-and-drop ngoài; component palette (danh sách khối lệnh mẫu) và workspace (khung ghép lệnh) là React component trong app/.
4. API route mới: POST /api/progress nhận playerId, levelId, chuỗi khối lệnh đã ghép — server tự chạy lại lib/maze-engine.ts để xác thực kết quả (không tin số sao gửi từ client), sau đó lưu/cập nhật Progress nếu tốt hơn lần trước.
5. API route GET /api/levels trả danh sách màn chơi kèm trạng thái đã hoàn thành (số sao) nếu có playerId; GET /api/players/[nickname] tạo Player mới nếu nickname chưa tồn tại.
6. Đảm bảo tuân theo constitution.md: validate input ở mọi route, tách logic chấm điểm khỏi UI, không thêm ORM/thư viện kéo thả khác ngoài đã liệt kê.
  3. Bước 3: Xem lại file plan.md được sinh ra

    Đối chiếu kế hoạch với spec.md ở Chapter 4 — xác nhận kế hoạch đáp ứng đủ hành vi đã đặc tả (3 kết quả khi chạy chương trình, cách chấm sao, chơi bằng biệt danh không cần đăng nhập).

    code specs\001-keo-tha-vuot-me-cung\plan.md

Phần 2: Chia nhỏ kế hoạch với /speckit.tasks

  1. Bước 4: Chạy /speckit.tasks để chia plan.md thành các task cụ thể 
    /speckit.tasks Chia kế hoạch trong plan.md thành các task nhỏ, mỗi task chỉ nên tập trung vào một phần cụ thể (vd một model Prisma, một hàm trong engine, một API route, hoặc một phần giao diện kéo thả), có thể thực hiện và kiểm tra độc lập theo đúng thứ tự phụ thuộc. Ưu tiên viết unit test cho lib/maze-engine.ts thành task riêng vì đây là logic chấm điểm quan trọng nhất.
  2. Bước 5: Xem lại file tasks.md được sinh ra

    Kiểm tra danh sách task có hợp lý, đủ chi tiết để thực hiện độc lập ở bài lab tiếp theo (vd: cập nhật schema.prisma + migrate, tạo lib/maze-engine.ts, viết unit test cho engine, tạo API route /api/progress và /api/levels, tạo component palette/workspace kéo thả, nối UI với API).

    code specs\001-keo-tha-vuot-me-cung\tasks.md
  3. Bước 6: Yêu cầu chia nhỏ thêm nếu task còn quá lớn 
    Task số [X] trong tasks.md vẫn còn gộp nhiều việc khác nhau. Hãy chia nhỏ task này thành các task con cụ thể hơn, cập nhật lại tasks.md.

Troubleshoot

Lỗi: plan.md đề xuất chấm điểm/xác thực kết quả hoàn toàn ở phía client, không có bước server tự chạy lại engine để xác thực.
Nguyên nhân: Prompt ở Bước 2 tuy đã nêu nhưng Claude Code có thể đơn giản hoá bỏ qua bước xác thực server.
Giải pháp: Yêu cầu Claude Code chạy lại /speckit.plan, nhấn mạnh rõ ràng buộc "API route phải tự chạy lại maze-engine ở server để xác thực, không tin kết quả gửi từ client".
Lỗi: tasks.md gộp việc tạo engine và viết unit test chung một task.
Nguyên nhân: Prompt ở Bước 4 nêu ưu tiên nhưng chưa đủ rõ ràng để tách hẳn thành 2 task.
Giải pháp: Dùng lại prompt ở Bước 6, chỉ định rõ "tách việc viết lib/maze-engine.ts và viết unit test cho nó thành 2 task riêng biệt".

Dọn dẹp resource

Bài lab này chỉ tạo file Markdown (plan.md, tasks.md) trong project — không tạo resource nào trên Cloud, không có gì cần dọn dẹp. Giữ nguyên toàn bộ file vừa tạo để tiếp tục ở Chapter 6 (Implement & đối chiếu kết quả).
