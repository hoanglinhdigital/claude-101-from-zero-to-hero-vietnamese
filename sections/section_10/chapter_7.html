10. Phát triển phần mềm với Spec-Kit Framework / Lab - Plan & Tasks
Bài lab này tiếp tục dùng project D:\lab-expense-management và bản đặc tả spec.md của tính năng "xuất báo cáo chi tiêu theo khoảng thời gian dạng PDF/Excel" đã tạo ở Chapter 6. Nếu chưa hoàn thành Chapter 6, hãy quay lại thực hiện trước.

Mục tiêu

  • Dùng /speckit.plan lập kế hoạch kỹ thuật cho tính năng xuất báo cáo: chọn thư viện tạo PDF/Excel, thiết kế API route mới, xác định các file cần thêm/sửa.
  • Dùng /speckit.tasks chia kế hoạch kỹ thuật thành các task nhỏ, cụ thể, thực hiện được từng phần.
  • Xem lại file plan.md và tasks.md được sinh ra, đối chiếu với spec.md ở Chapter 6.

/speckit.plan đọc lại spec.md và constitution.md để đảm bảo kế hoạch kỹ thuật đúng yêu cầu và tuân theo nguyên tắc chung; /speckit.tasks đọc lại plan.md vừa tạo để chia thành các task cụ thể.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Chapter 6 — constitution.md và specs/{feature-id}/spec.md đã tồn tại và đúng nội dung tính năng xuất báo cáo.
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Lập kế hoạch kỹ thuật với /speckit.plan

  1. Bước 1: Vào project và khởi động Claude Code 
    cd D:\lab-expense-management
claude
  2. Bước 2: Chạy /speckit.plan với định hướng kỹ thuật cụ thể

    Nêu rõ các quyết định kỹ thuật mong muốn — chọn thư viện, đặt tên route mới — để Claude Code lập kế hoạch bám sát thực tế project (Next.js API Routes, Prisma).

    /speckit.plan Lập kế hoạch kỹ thuật để triển khai tính năng xuất báo cáo trong spec.md. Định hướng cụ thể:
1. Tạo API route mới app/api/reports/export/route.ts, nhận query param startDate, endDate (định dạng YYYY-MM-DD, bắt buộc) và format (giá trị "pdf" hoặc "excel", bắt buộc).
2. Dùng thư viện exceljs để sinh file Excel (.xlsx), và một thư viện tạo PDF phù hợp với Next.js API Route (đề xuất cụ thể, ưu tiên thư viện chạy tốt trên Node.js runtime, không cần trình duyệt).
3. Tách logic truy vấn dữ liệu + tính tổng theo danh mục ra hàm thuần trong lib/report-generator.ts, tương tự cách đã tổ chức lib/csv-export.ts và lib/expense-service.ts hiện có — không phụ thuộc Next.js request/response, để viết unit test dễ dàng.
4. Route trả về file với Content-Type và Content-Disposition phù hợp để browser tải file xuống, đặt tên file theo mẫu bao-cao-chi-tieu_{startDate}_{endDate}.pdf hoặc .xlsx.
5. Thêm giao diện chọn khoảng thời gian (2 ô ngày) và dropdown chọn định dạng trên trang chủ, kèm nút "Xuất báo cáo".
6. Đảm bảo tuân theo constitution.md: validate input ngày/format, không đổi các route hiện có.
  3. Bước 3: Xem lại file plan.md được sinh ra

    Đối chiếu kế hoạch với spec.md ở Chapter 6 — xác nhận kế hoạch đáp ứng đủ hành vi đã đặc tả, không bỏ sót yêu cầu nào (vd trường hợp không có dữ liệu, tổng theo danh mục).

    code specs\001-xuat-bao-cao-chi-tieu\plan.md

Phần 2: Chia nhỏ kế hoạch với /speckit.tasks

  1. Bước 4: Chạy /speckit.tasks để chia plan.md thành các task cụ thể 
    /speckit.tasks Chia kế hoạch trong plan.md thành các task nhỏ, mỗi task chỉ nên tập trung vào một phần cụ thể (vd một file, một hàm, hoặc một phần giao diện), có thể thực hiện và kiểm tra độc lập theo đúng thứ tự phụ thuộc.
  2. Bước 5: Xem lại file tasks.md được sinh ra

    Kiểm tra danh sách task có hợp lý, đủ chi tiết để thực hiện từng task một cách độc lập ở bài lab tiếp theo (vd: tạo lib/report-generator.ts, viết unit test cho hàm sinh dữ liệu báo cáo, tạo API route, thêm UI chọn khoảng thời gian, nối UI với API).

    code specs\001-xuat-bao-cao-chi-tieu\tasks.md
  3. Bước 6: Yêu cầu chia nhỏ thêm nếu task còn quá lớn

    Nếu một task trong danh sách vẫn gộp quá nhiều việc (vd vừa tạo hàm sinh PDF vừa tạo hàm sinh Excel vừa viết route trong 1 task), yêu cầu Claude Code chia nhỏ thêm trước khi sang giai đoạn Implementation.

    Task số [X] trong tasks.md vẫn còn gộp nhiều việc khác nhau. Hãy chia nhỏ task này thành các task con cụ thể hơn, cập nhật lại tasks.md.

✅ Kết quả mong đợi

specs/{feature-id}/plan.md nêu rõ thư viện PDF/Excel được chọn, route mới, và các file cần tạo/sửa — tuân theo constitution.md. specs/{feature-id}/tasks.md chứa danh sách task nhỏ, đủ chi tiết, đúng thứ tự phụ thuộc, sẵn sàng cho /speckit.implement ở Chapter 8.

Troubleshoot

Lỗi: plan.md đề xuất thư viện PDF không chạy được trên Node.js runtime của Next.js API Route (yêu cầu trình duyệt hoặc binary hệ điều hành riêng).
Nguyên nhân: Một số thư viện PDF phổ biến được thiết kế chạy phía client (browser) hoặc cần cài thêm dependency hệ thống, không phù hợp API Route.
Giải pháp: Yêu cầu Claude Code chạy lại /speckit.plan, nêu rõ ràng buộc "chỉ dùng thư viện Node.js thuần, không phụ thuộc trình duyệt hoặc binary ngoài", để đề xuất lại thư viện phù hợp.
Lỗi: tasks.md chỉ có 2-3 task rất lớn, không đủ chi tiết để implement từng phần.
Nguyên nhân: Prompt ở Bước 4 chưa nhấn đủ mạnh yêu cầu chia nhỏ.
Giải pháp: Dùng lại prompt ở Bước 6, chỉ định rõ số lượng task tối thiểu mong muốn hoặc phạm vi cụ thể của từng task con.

Dọn dẹp resource

Bài lab này chỉ tạo file Markdown (plan.md, tasks.md) trong project — không tạo resource nào trên Cloud, không có gì cần dọn dẹp. Giữ nguyên toàn bộ file vừa tạo để tiếp tục ở Chapter 8 (Implement & đối chiếu kết quả).
