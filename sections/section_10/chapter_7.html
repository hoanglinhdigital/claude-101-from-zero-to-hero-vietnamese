10. Phát triển phần mềm với Spec-Kit Framework / Lab - Triển khai CodeKids Blocks lên Vercel & TiDB Serverless
Bài lab cuối của Section 10 — đưa CodeKids Blocks (project D:\lab-codekids-blocks đã hoàn thiện ở Chapter 6) từ máy local lên Internet: database chuyển từ MySQL chạy trong Docker sang TiDB Serverless (tương thích giao thức MySQL, có gói miễn phí), và ứng dụng Next.js được host trên Vercel.

Mục tiêu

  • Tạo một TiDB Serverless cluster miễn phí trên TiDB Cloud, lấy connection string.
  • Cập nhật cấu hình Prisma để kết nối đúng chuẩn TiDB (SSL bắt buộc) và chạy migration lên database này.
  • Đẩy code CodeKids Blocks lên GitHub và import vào Vercel.
  • Cấu hình biến môi trường, build command trên Vercel và deploy thành công.
  • Kiểm chứng màn chơi kéo thả vượt mê cung hoạt động đúng trên domain thực tế do Vercel cấp.

Vercel build và chạy Next.js dưới dạng Serverless Function cho mỗi request, không giữ kết nối cố định tới database — vì vậy CodeKids Blocks cần một database serverless-friendly như TiDB Serverless thay vì container MySQL chạy trên máy local.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Chapter 6 — project D:\lab-codekids-blocks chạy đúng với MySQL local.
  • Tài khoản GitHub, đã đăng nhập git trên máy local.
  • Tài khoản TiDB Cloud (đăng ký miễn phí tại tidbcloud.com).
  • Tài khoản Vercel (đăng ký miễn phí tại vercel.com, có thể đăng nhập bằng GitHub).
  • Vercel CLI (tuỳ chọn, dùng để deploy/kiểm tra từ terminal): npm install -g vercel.

Các bước thực hành

Phần 1: Tạo TiDB Serverless cluster

  1. Bước 1: Tạo cluster mới trên TiDB Cloud

    Đăng nhập tidbcloud.com → Create Cluster → chọn gói Serverless (miễn phí) → đặt tên cluster (vd codekids-blocks) → chọn region gần Việt Nam nhất (vd Singapore/ap-southeast) → Create.

  2. Bước 2: Lấy connection string

    Sau khi cluster khởi tạo xong (thường vài chục giây), vào tab Connect, chọn Prisma trong danh sách framework/driver để TiDB Cloud sinh sẵn connection string đúng định dạng Prisma cần, dạng:

    mysql://<user>.root:<password>@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/codekids_blocks?sslaccept=strict
    Lưu ý: Mật khẩu chỉ hiển thị/tải xuống được một lần duy nhất khi tạo. Lưu lại ngay vào nơi an toàn (không commit vào Git).
  3. Bước 3: Cập nhật DATABASE_URL cục bộ để kiểm tra kết nối

    Tạm sửa .env trỏ sang TiDB (nhớ backup connection string MySQL local trước đó) rồi thử kết nối.

    DATABASE_URL="mysql://<user>.root:<password>@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/codekids_blocks?sslaccept=strict"
    npx prisma db pull

    Nếu lệnh chạy không báo lỗi kết nối, connection string đã đúng.

Phần 2: Chạy migration lên TiDB

  1. Bước 4: Áp dụng toàn bộ migration đã tạo ở Chapter 6 lên TiDB

    Dùng migrate deploy (áp dụng migration đã có sẵn, không tạo migration mới) thay vì migrate dev — đúng lệnh dùng cho môi trường không phải máy phát triển cục bộ.

    npx prisma migrate deploy
  2. Bước 5: Kiểm tra bảng đã được tạo đúng trên TiDB

    Vào tab Chat2Query hoặc SQL Editor trên TiDB Cloud, chạy thử truy vấn kiểm tra.

    SHOW TABLES;

    Xác nhận có đủ 3 bảng Level, Player, Progress (tên bảng cụ thể tuỳ theo schema.prisma đã viết ở Chapter 5).

  3. Bước 6: Seed dữ liệu màn chơi (nếu project có script seed)

    Nếu Claude Code đã tạo prisma/seed.ts chứa dữ liệu mẫu 3 màn chơi ở Chapter 6, chạy lại seed nhắm vào TiDB.

    npx prisma db seed

Phần 3: Đẩy code lên GitHub và import vào Vercel

  1. Bước 7: Khôi phục lại .env cho môi trường local, thêm .env vào .gitignore

    Trả DATABASE_URL trong .env về lại MySQL local (dùng cho máy phát triển), và đảm bảo file .env không bị commit lên Git (connection string TiDB sẽ được cấu hình riêng trên Vercel ở Bước 9).

    git status

    Xác nhận .env nằm trong danh sách bị ignore, không xuất hiện trong git status.

  2. Bước 8: Tạo repository GitHub và push code 
    cd D:\lab-codekids-blocks
git init
git add .
git commit -m "CodeKids Blocks: keo tha vuot me cung, hoan tat SDD voi Spec-Kit"
gh repo create lab-codekids-blocks --private --source=. --remote=origin --push
    Lưu ý: Nếu chưa cài gh CLI, tạo repository thủ công trên github.com/new rồi chạy git remote add origin <url> và git push -u origin main.
  3. Bước 9: Import project vào Vercel

    Đăng nhập vercel.com → Add New → Project → chọn repository lab-codekids-blocks vừa push → Vercel tự nhận diện đây là Next.js project.

  4. Bước 10: Cấu hình biến môi trường DATABASE_URL trỏ vào TiDB

    Ở màn hình cấu hình project trước khi deploy (hoặc Settings → Environment Variables sau khi tạo project), thêm biến sau cho cả 3 môi trường Production/Preview/Development:

    DATABASE_URL=mysql://<user>.root:<password>@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/codekids_blocks?sslaccept=strict
  5. Bước 11: Cấu hình build command để tự sinh Prisma Client khi deploy

    Vào Settings → Build & Development Settings, đặt Build Command để chạy prisma generate trước khi build Next.js (tránh lỗi thiếu Prisma Client trên môi trường build của Vercel).

    prisma generate && next build
  6. Bước 12: Deploy

    Bấm Deploy và theo dõi log build. Sau khi hoàn tất, Vercel cấp một domain dạng lab-codekids-blocks.vercel.app.

Phần 4: Kiểm chứng trên domain thực tế

  1. Bước 13: Mở domain Vercel và chơi thử màn chơi kéo thả

    Truy cập https://lab-codekids-blocks.vercel.app, nhập biệt danh mới, thử ghép khối lệnh và chạy màn 1 — xác nhận hành vi giống hệt khi chạy local ở Chapter 6 (di chuyển từng bước, chấm sao, xử lý va chạm).

  2. Bước 14: Xác nhận dữ liệu được lưu đúng vào TiDB

    Sau khi hoàn thành một màn trên domain thực, vào lại TiDB Cloud SQL Editor kiểm tra bản ghi Progress vừa được tạo.

    SELECT * FROM Progress ORDER BY completedAt DESC LIMIT 5;

✅ Kết quả mong đợi

CodeKids Blocks chạy được trên domain công khai do Vercel cấp, kết nối và ghi dữ liệu đúng vào TiDB Serverless. Toàn bộ hành vi của màn chơi kéo thả vượt mê cung (đã kiểm chứng local ở Chapter 6) hoạt động giống hệt trên môi trường production.

Troubleshoot

Lỗi: Build trên Vercel báo lỗi PrismaClientInitializationError hoặc không tìm thấy Prisma Client.
Nguyên nhân: Vercel cache node_modules giữa các lần build, không tự chạy lại prisma generate nếu chưa cấu hình build command.
Giải pháp: Xác nhận lại Build Command ở Bước 11 có prisma generate, hoặc thêm script "postinstall": "prisma generate" vào package.json để tự chạy sau mỗi lần npm install.
Lỗi: Deploy thành công nhưng gọi API trả lỗi kết nối database (connection refused/timeout).
Nguyên nhân: DATABASE_URL trên Vercel bị gõ sai, thiếu tham số ?sslaccept=strict bắt buộc của TiDB Serverless, hoặc chưa áp dụng cho đúng môi trường (Production).
Giải pháp: Vào lại Settings → Environment Variables, kiểm tra chính xác giá trị đã copy từ TiDB Cloud, đảm bảo áp dụng cho môi trường Production, sau đó Redeploy.
Lỗi: Ứng dụng chạy chậm hoặc báo lỗi hết kết nối (too many connections) khi nhiều học sinh chơi cùng lúc.
Nguyên nhân: Mỗi Serverless Function của Vercel có thể mở một kết nối Prisma riêng; nếu không quản lý đúng, số kết nối có thể vượt giới hạn cho phép của TiDB Serverless.
Giải pháp: Yêu cầu Claude Code áp dụng mẫu khởi tạo PrismaClient dạng singleton (tái sử dụng instance có sẵn thay vì tạo mới mỗi request) — mẫu phổ biến khi dùng Prisma với Next.js trên môi trường serverless.

Dọn dẹp resource

Quan trọng: TiDB Serverless và Vercel đều có gói miễn phí, nhưng nếu không dùng nữa nên dọn dẹp để tránh chiếm quota tài khoản hoặc phát sinh chi phí nếu sau này nâng cấp gói.
  1. Xoá project trên Vercel

    Vào project lab-codekids-blocks trên vercel.com → Settings → Advanced → Delete Project → xác nhận tên project để xoá.

  2. Xoá cluster trên TiDB Cloud

    Vào cluster codekids-blocks trên tidbcloud.com → Settings → Delete Cluster → xác nhận tên cluster để xoá. Toàn bộ dữ liệu (Level, Player, Progress) sẽ mất vĩnh viễn sau bước này.

Repository trên GitHub và code trên máy local (D:\lab-codekids-blocks) không cần xoá — vẫn là minh chứng đầy đủ cho toàn bộ quy trình SDD đã thực hiện qua Section 10, từ phân tích yêu cầu đến triển khai production.
