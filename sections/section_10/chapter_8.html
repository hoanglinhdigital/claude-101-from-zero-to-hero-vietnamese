10. Phát triển phần mềm với Spec-Kit Framework / Lab - Implement & đối chiếu kết quả
Bài lab này tiếp tục dùng project D:\lab-expense-management và tasks.md của tính năng "xuất báo cáo chi tiêu theo khoảng thời gian dạng PDF/Excel" đã tạo ở Chapter 7. Đây là bài lab cuối cùng của Section 10 — khép lại vòng SDD bằng giai đoạn Implementation và Convergence.

Mục tiêu

  • Dùng /speckit.implement để Claude Code triển khai lần lượt các task đã chia ở tasks.md.
  • Theo dõi tiến độ thực thi từng task, xác nhận từng bước trước khi cho phép ghi file.
  • Kiểm chứng tính năng chạy đúng thực tế trên trình duyệt sau khi implement xong.
  • Đối chiếu kết quả thực tế với spec.md ban đầu (giai đoạn Convergence) — xác nhận không thiếu, không lệch yêu cầu.

Claude Code thực thi tuần tự từng task trong tasks.md, đánh dấu hoàn thành ngược lại vào file này. Sau khi hết task, bước Convergence đối chiếu toàn bộ kết quả với spec.md gốc để xác nhận đúng yêu cầu — khép vòng SDD cho tính năng này.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Chapter 7 — specs/{feature-id}/plan.md và tasks.md đã có nội dung chi tiết, đủ nhỏ để implement từng phần.
  • Docker Desktop đang chạy, MySQL container (expense-mysql) đã khởi động lại nếu trước đó đã docker compose down.
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Triển khai bằng /speckit.implement

  1. Bước 1: Khởi động lại MySQL container và Claude Code 
    cd D:\lab-expense-management
docker compose up -d
claude
  2. Bước 2: Chạy /speckit.implement để bắt đầu triển khai

    Claude Code sẽ đọc tasks.md và thực thi lần lượt từng task theo đúng thứ tự đã chia ở Chapter 7.

    /speckit.implement
  3. Bước 3: Theo dõi và xác nhận từng task

    Ở mỗi task (tạo lib/report-generator.ts, viết unit test, tạo API route, thêm UI...), đọc qua thay đổi được đề xuất trước khi xác nhận cho ghi file — không xác nhận hàng loạt mà không xem nội dung, đặc biệt với các file liên quan trực tiếp đến logic tính tổng chi tiêu.

  4. Bước 4: Chạy unit test sau khi các task liên quan lib/report-generator.ts hoàn tất

    Tự chạy lại test độc lập, không chỉ tin vào báo cáo "đã pass" của Claude Code.

    npm test
PASS  __tests__/report-generator.test.ts
  buildReportData
    ✓ tính đúng tổng chi tiêu theo danh mục trong khoảng thời gian
  5. Bước 5: Chờ Claude Code hoàn thành toàn bộ task và báo cáo tổng kết

    Sau khi hết task trong tasks.md, Claude Code thường tự tổng kết các file đã tạo/sửa. Đọc lại tổng kết này trước khi qua bước kiểm chứng thực tế.

Phần 2: Kiểm chứng thực tế và Convergence

  1. Bước 6: Khởi động dev server và thử tính năng trên trình duyệt 
    npm run dev

    Mở http://localhost:3000, chọn một khoảng thời gian có dữ liệu chi tiêu, chọn định dạng PDF, bấm "Xuất báo cáo" và xác nhận file tải xuống mở được, hiển thị đúng danh sách + tổng theo danh mục. Lặp lại với định dạng Excel.

  2. Bước 7: Thử trường hợp không có dữ liệu

    Chọn một khoảng thời gian chắc chắn không có khoản chi tiêu nào, xuất báo cáo và xác nhận file vẫn được tạo, hiển thị "Không có dữ liệu" và tổng bằng 0 đúng như đã đặc tả ở spec.md.

  3. Bước 8: Xác nhận các tính năng cũ không bị ảnh hưởng

    Thử lại tính năng xuất CSV theo tháng (Section 4 Chapter 6) và các API CRUD hiện có, xác nhận vẫn hoạt động đúng như trước — đúng nguyên tắc "không phá vỡ contract API hiện có" đã định nghĩa trong constitution.md.

  4. Bước 9: Đối chiếu kết quả với spec.md — giai đoạn Convergence

    Mở lại spec.md ở Chapter 6, lập checklist từng yêu cầu và xác nhận từng mục đã đáp ứng đúng trên thực tế (khoảng thời gian tuỳ chọn, 2 định dạng PDF/Excel, tổng theo danh mục, trường hợp rỗng, không ảnh hưởng tính năng cũ).

    Đọc lại spec.md của tính năng xuất báo cáo và so sánh với code đã implement. Liệt kê rõ: yêu cầu nào đã đáp ứng đầy đủ, yêu cầu nào còn thiếu hoặc chưa đúng (nếu có), kèm vị trí file liên quan.
  5. Bước 10: Xử lý phần chưa khớp (nếu có)

    Nếu Bước 9 phát hiện sai lệch, quay lại cập nhật spec.md/plan.md/tasks.md cho đúng thực tế mong muốn rồi chạy lại /speckit.implement cho phần liên quan — không sửa tay trực tiếp vào code mà bỏ qua việc cập nhật spec, để tránh code và spec lệch nhau trở lại.

✅ Kết quả mong đợi

Tính năng xuất báo cáo chi tiêu theo khoảng thời gian hoạt động đúng với cả 2 định dạng PDF và Excel, xử lý đúng trường hợp không có dữ liệu, không làm hỏng các tính năng đã có (CRUD, xuất CSV theo tháng). Toàn bộ yêu cầu trong spec.md được đối chiếu và xác nhận đã đáp ứng — hoàn tất giai đoạn Convergence, khép vòng SDD cho tính năng này.

Troubleshoot

Lỗi: /speckit.implement dừng giữa chừng, báo lỗi khi thực thi một task cụ thể.
Nguyên nhân: Task đó phụ thuộc vào một thư viện chưa được cài đặt đúng, hoặc mô tả task chưa đủ rõ so với thực tế project.
Giải pháp: Đọc thông báo lỗi cụ thể, yêu cầu Claude Code cài package còn thiếu (npm install) hoặc làm rõ lại task đó rồi tiếp tục /speckit.implement — không cần chạy lại từ đầu, các task đã hoàn thành trước đó vẫn được giữ nguyên.
Lỗi: File PDF/Excel xuất ra bị lỗi font tiếng Việt (dấu hiển thị sai) khi mở lên.
Nguyên nhân: Thư viện tạo PDF/Excel dùng font mặc định không hỗ trợ đầy đủ ký tự tiếng Việt có dấu.
Giải pháp: Yêu cầu Claude Code cấu hình lại font hỗ trợ Unicode/tiếng Việt cho thư viện đang dùng, hoặc encode đúng UTF-8 tuỳ theo thư viện cụ thể.
Lỗi: Sau khi implement, tính năng xuất CSV theo tháng (Section 4) không còn hoạt động đúng.
Nguyên nhân: Claude Code vô ý sửa vào file/logic dùng chung (vd lib/expense-service.ts) khi implement tính năng mới, vi phạm nguyên tắc "không phá vỡ contract API hiện có".
Giải pháp: Dùng git diff để xem chính xác phần nào bị đổi ngoài phạm vi tính năng mới, yêu cầu Claude Code khôi phục lại phần đó và tách rõ logic dùng riêng cho báo cáo mới.
