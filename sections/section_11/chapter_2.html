11. Harness Engineering / Các thành phần của Harness & ánh xạ vào Claude Code

Giới thiệu

Một harness không phải là một sản phẩm riêng lẻ mà là tập hợp các thành phần cùng phục vụ một mục tiêu: giúp agent biết việc cần làm, làm được việc đó trong giới hạn an toàn, và nhận phản hồi để tự sửa sai. Chương này liệt kê 7 thành phần cốt lõi của harness và chỉ ra mỗi thành phần tương ứng với tính năng nào của Claude Code mà bạn đã học — để từ đó biết cần "vặn" núm nào khi agent làm chưa tốt.

Các tính năng chính

  • Context & hướng dẫn: thông tin agent cần để hiểu dự án — quy tắc, kiến trúc, lệnh build/test.
  • Tools: hành động agent có thể thực hiện — đọc/sửa file, chạy lệnh, gọi hệ thống ngoài qua MCP.
  • Permissions & sandbox: ranh giới được phép — thư mục, lệnh, thao tác cần xác nhận hoặc bị cấm.
  • Memory & State: những gì agent "nhớ" qua nhiều lượt và nhiều phiên — file tiến độ, lịch sử Git.
  • Chuyên môn hoá & cô lập: Skill nạp quy trình đúng lúc; Sub-agent làm việc trong context riêng.
  • Kiểm chứng: các bước tự động xác nhận kết quả — typecheck, lint, test, kiểm tra kiến trúc.
  • Quan sát & vòng đời: transcript/log để hiểu agent đã làm gì; điều phối chạy tự động (headless, CI).

Use Cases

Chẩn đoán agent làm sai

Khi Claude Code tạo code vi phạm kiến trúc, dùng bảng ánh xạ để xác định thành phần thiếu: thiếu guide (CLAUDE.md chưa nêu rõ), thiếu sensor (chưa có kiểm tra tự động) hay thiếu quyền hạn (tool quá rộng).

Chuẩn hoá cách làm việc của cả team

Đưa CLAUDE.md, .claude/settings.json và script hook vào Git để mọi thành viên dùng chung một harness — kết quả của agent nhất quán giữa các máy.

Đánh giá công cụ AI trước khi áp dụng

Khi cân nhắc một công cụ agent mới, kiểm tra nó cung cấp được bao nhiêu trong 7 thành phần trên — công cụ thiếu kiểm chứng hay phân quyền sẽ cần bạn tự bổ sung.

Thông tin bổ sung

  • Đừng xây tất cả cùng lúc: bắt đầu với CLAUDE.md ngắn + một sensor (ví dụ typecheck), chỉ thêm thành phần khi có lỗi lặp lại chứng minh cần thiết.
  • Chi phí context: mọi thứ nạp vào context (CLAUDE.md, mô tả tool MCP, kết quả hook) đều tiêu tốn token ở mỗi lượt. Giữ ngắn gọn và chỉ nạp khi cần.
  • Hook chạy với quyền của bạn: áp dụng đầy đủ lưu ý an toàn ở Section 9 cho mọi script kiểm chứng.
  • Harness là code: nên review, version bằng Git và có test (ít nhất chạy thử thủ công) như bất kỳ code nào khác.
