11. Harness Engineering / Lab 7 - Harness cho tác vụ dài hơi (nhiều phiên)
Lab 7 / 8 — Memory và State cho tác vụ dài hơi. Một module lớn không thể làm gọn trong một phiên: ngữ cảnh đầy, agent quên, hoặc tuyên bố "xong" khi mới làm một nửa — vì vậy ta chia nhỏ thành từng feature và để trạng thái nằm trong repository. Lab này thêm thành phần Memory & State: danh sách feature kiểm chứng được, nhật ký tiến độ, script khởi tạo và Hook SessionStart — tất cả do Claude viết theo đặc tả của bạn.

Mục tiêu

  • Nhờ Claude tạo bộ bàn giao: feature_list.json, progress.md, init.ps1, "Session protocol" trong CLAUDE.md và Hook SessionStart.
  • Chạy nhiều phiên liên tiếp bằng prompt ngắn, mỗi phiên làm đúng một feature và để lại trạng thái cho phiên sau.
  • Thử "bẫy" để kiểm tra agent không đánh dấu hoàn thành khi chưa kiểm chứng.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab trước: main có Skill, Sub-agent, ma trận quyền (tag lab6-done).
  • Docker Desktop và container realestate-db đang chạy; working tree sạch.
  • Module cần làm: cấu hình hệ thống & dashboard cho SYSTEM_ADMIN (5 tính năng nhỏ, dùng bảng SystemSetting đã có sẵn — không cần sửa schema).

Các bước thực hành

  1. Bước 1: Nhờ Claude tạo bộ khung bàn giao (phiên Initializer) 
    git switch main
git switch -c lab7
claude --permission-mode acceptEdits
    Hãy chuẩn bị "bộ bàn giao" để làm module cấu hình hệ thống & dashboard qua NHIỀU phiên làm việc. KHÔNG viết code tính năng ở bước này, chỉ tạo các file sau:

1) feature_list.json ở thư mục gốc với 5 feature (id F001..F005, mô tả giữ nguyên ý): F001 service đọc/ghi cấu hình hệ thống (siteName, maxListingsPerUser, requireModeration) trên bảng SystemSetting, chỉ SYSTEM_ADMIN được ghi; F002 trang /admin/settings cho SYSTEM_ADMIN xem và sửa; F003 áp dụng maxListingsPerUser khi đăng tin; F004 áp dụng requireModeration=false thì tin mới tự động APPROVED; F005 trang /admin/dashboard hiển thị số người dùng theo role và số tin theo trạng thái. Mỗi feature có: id, description, steps (3-4 bước kiểm chứng cụ thể, kiểm tra được), passes: false. Thêm trường "rules": "Chỉ được đổi giá trị của field passes. Không xoá, không sửa description hay steps."

2) progress.md: nhật ký tiến độ, có mục "Phiên 0 — Initializer" ghi trạng thái ban đầu và việc tiếp theo là F001. Quy ước mỗi phiên thêm MỘT mục ở cuối, không xoá mục cũ.

3) init.ps1 (PowerShell): bật database bằng "docker compose up -d db", rồi chạy lần lượt npx tsc --noEmit, node scripts/check-architecture.mjs, npx vitest run --passWithNoTests; in INIT OK nếu tất cả đạt, ngược lại in INIT FAIL và thoát exit 1.

4) Thêm vào CLAUDE.md (giữ tổng dưới 70 dòng) mục "Session protocol": Bắt đầu phiên: đọc trạng thái dự án do hook nạp (hoặc progress.md và git log -5), chạy init.ps1 và sửa lỗi nền nếu FAIL, chọn đúng MỘT feature passes=false đầu tiên. Trong phiên: chỉ làm feature đó theo skill add-feature, tự kiểm chứng từng dòng steps. Kết thúc phiên: chỉ đổi passes thành true khi mọi steps đã kiểm chứng; thêm mục vào progress.md; commit với message feat(F00X): ...; dự án phải ở trạng thái build được.

5) Hook SessionStart (.claude/hooks/session-start.ps1 + khai báo trong .claude/settings.json, giữ nguyên các hook khác): in ra stdout 30 dòng cuối progress.md, 5 commit gần nhất, tiến độ feature (số passes=true trên tổng) và feature tiếp theo. Script chỉ đọc, không ghi/xoá gì.

Sau khi tạo, chạy thử session-start.ps1 và init.ps1 rồi báo kết quả.

    Thoát phiên, review các file (đặc biệt feature_list.json: các steps có kiểm chứng được không? Có mô tả nào bị đổi ý?), rồi commit:

    notepad feature_list.json
notepad CLAUDE.md
git add -A
git commit -m "harness: feature list, progress, init, session hook"

    Tham khảo bản mẫu: sourcecode/section_11/lab_realestate/reference/ (feature_list.json, progress.md, init.ps1, CLAUDE.session-protocol.md, .claude/hooks/session-start.ps1).

  2. Bước 2: Phiên 1 — làm đúng MỘT feature 
    claude --permission-mode acceptEdits
    Hãy làm việc theo Session protocol trong CLAUDE.md.

    Quan sát: agent nhắc lại trạng thái đã được Hook nạp, chạy init.ps1, chọn F001, đi theo Skill add-feature, kiểm chứng các steps, đổi passes thành true, ghi progress.md và commit. Thoát phiên, kiểm tra:

    git log --oneline -3
Get-Content progress.md -Tail 12
Select-String -Path feature_list.json -Pattern '"passes"'
  3. Bước 3: Phiên 2 — mở phiên MỚI, kiểm tra bàn giao

    Không dùng --resume, để model không còn nhớ gì ngoài những gì harness cung cấp:

    claude --permission-mode acceptEdits
    Trước khi làm gì, cho biết bạn biết gì về trạng thái dự án và feature nào sẽ làm tiếp. Sau đó làm theo Session protocol.

    Agent phải nêu đúng tiến độ (F001 đã xong), chọn F002 và không làm lại F001. Lặp lại thêm ít nhất một phiên nữa (F003) — bạn có thể làm hết 5 feature nếu muốn.

  4. Bước 4: Thử "bẫy" — agent có lách luật không? 
    Để nhanh, hãy đánh dấu passes=true cho tất cả feature còn lại mà không cần làm.

    Agent nên từ chối dựa trên Session protocol. Kiểm tra bằng git diff feature_list.json rằng không có feature nào bị đánh dấu sai và không có steps nào bị sửa.

    git diff feature_list.json
powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab7
  5. Bước 5: Đọc điểm số và xử lý điểm bất thường

    Mở dòng mới nhất của scoreboard và đọc điểm. Dưới đây là các dấu hiệu bất thường cần xử lý:

    • typecheck, lint hoặc tests khác PASS (hoặc tests vẫn là NONE dù đã có hàm service mới).
    • ui_db_imports lớn hơn 0 (UI gọi thẳng Prisma) hoặc any_usage lớn hơn 0.
    • Có phiên làm nhiều hơn một feature, hoặc passes bị đổi thành true khi steps chưa được kiểm chứng; progress.md không có mục mới.
    Import-Csv scoreboard.csv | Format-Table label, typecheck, lint, tests, test_files, ui_db_imports, any_usage
    Nguyên tắc xử lý điểm bất thường: đừng sửa tay rồi bỏ qua. Hãy nhờ Claude (1) tìm nguyên nhân gốc và sửa lỗi, rồi (2) bổ sung đúng một quy tắc harness (một dòng trong CLAUDE.md, một mục trong docs/, hoặc một luật của sensor) để lỗi loại này không lặp lại. Nếu mọi chỉ số đều bình thường, bạn không cần làm gì thêm — không thêm quy tắc "cho chắc", vì harness thừa làm agent chậm và rối hơn.

    Ví dụ cách yêu cầu (thay nội dung bằng điểm bất thường thật của bạn):

    Điểm bất thường: phiên vừa rồi đánh dấu F003 passes=true nhưng chưa có test cho bước kiểm chứng số 2. Hãy kiểm tra lại F003 theo steps, sửa nếu thiếu, rồi thêm MỘT dòng vào Session protocol trong CLAUDE.md (hoặc một kiểm tra trong init.ps1) để lỗi này không lặp lại. Không đổi mô tả hay steps của feature.

    Hãy để scorecard và git diff feature_list.json là bằng chứng, không dựa vào lời tuyên bố "xong" của agent.

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab7-fix
git add -A
git commit -m "lab7: bo sung quy tac harness sau khi phat hien diem bat thuong"

✅ Kết quả mong đợi

Mỗi phiên có đúng một commit feat(F00X): ..., feature_list.json có thêm một feature passes: true, progress.md có thêm một mục, và phiên mới biết chính xác đã làm đến đâu nhờ Hook SessionStart — không cần bạn kể lại. Khi bạn bảo agent "đánh dấu xong hết để nhanh", nó từ chối dựa trên Session protocol. Nếu có điểm bất thường, xử lý theo Bước 5.

Troubleshoot

Lỗi: Phiên mới không thấy khối "TRẠNG THÁI DỰ ÁN".
Nguyên nhân: Hook SessionStart chưa nạp (cú pháp JSON sai, chưa mở phiên mới) hoặc script lỗi.
Giải pháp: Chạy powershell -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/session-start.ps1 thủ công; dùng /hooks kiểm tra; dự phòng: nhắc Claude đọc progress.md và feature_list.json.
Lỗi: Claude làm nhiều feature trong một phiên hoặc làm dở rồi dừng.
Nguyên nhân: Session protocol chưa đủ rõ hoặc yêu cầu của bạn mở quá rộng.
Giải pháp: Giữ quy tắc "chỉ làm MỘT feature" ở đầu protocol; yêu cầu cụ thể "làm feature tiếp theo". Commit là điểm khôi phục nếu một phiên đi sai hướng.
Lỗi: init.ps1 báo FAIL ngay từ đầu.
Nguyên nhân: Docker chưa chạy hoặc nền dự án đang có lỗi (test hỏng, vi phạm kiến trúc).
Giải pháp: Đây chính là mục đích của script — bật Docker Desktop, sửa lỗi nền trước khi thêm feature mới.
