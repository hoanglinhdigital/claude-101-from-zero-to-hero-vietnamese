11. Harness Engineering / Lab 6 - Skill & Sub-agent reviewer
Lab 6 / 8 — Skill và Sub-agent. Hai thành phần harness cuối cùng bạn đã học ở Section 3 nay được dùng đúng vai trò: Skill = guide đóng gói thành quy trình chuẩn, nạp theo nhu cầu; Sub-agent reviewer = sensor dạng inferential (đánh giá bằng LLM) chạy trong context riêng. Cả hai được tạo bằng cách nhờ Claude viết.

Mục tiêu

  • Nhờ Claude tạo Skill add-feature (quy trình chuẩn thêm tính năng) và Sub-agent code-reviewer (read-only).
  • Thêm tính năng "SYSTEM_ADMIN quản lý tài khoản" bằng một prompt ngắn và quan sát Skill tự được kích hoạt, Sub-agent review độc lập.
  • Phân biệt khi nào dùng sensor computational (code) và inferential (LLM reviewer).

Skill giữ cho agent chính đi đúng quy trình mà không làm phình CLAUDE.md. Sub-agent reviewer chạy trong context riêng và chỉ có quyền đọc: nó nhìn code bằng "con mắt mới", bắt được những lỗi ngữ nghĩa mà script không viết thành quy tắc được.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab trước: main có test, Hook, ma trận quyền, permissions.deny (tag lab5-done).
  • Hiểu cơ bản về Skill và Sub-agent (Section 3).

Các bước thực hành

  1. Bước 1: Nhờ Claude tạo Skill add-feature 
    git switch main
git switch -c lab6
claude --permission-mode acceptEdits
    Hãy tạo một Skill cho project tại .claude/skills/add-feature/SKILL.md (có frontmatter name và description). Mô tả (description) phải đủ rõ để Skill tự được kích hoạt mỗi khi tôi yêu cầu thêm tính năng, trang hoặc nghiệp vụ mới.

Nội dung Skill là quy trình chuẩn, thực hiện lần lượt:
1. Đọc docs/DOMAIN.md và docs/ARCHITECTURE.md; xác định role nào được làm gì với tính năng này.
2. Lập kế hoạch ngắn (5-8 dòng): file sẽ tạo/sửa theo từng tầng. Nếu cần đổi prisma/schema.prisma thì dừng lại hỏi tôi.
3. Tạo Zod schema trong src/lib/validators.
4. Thêm hàm vào src/services/-service.ts: tham số đầu là actor, gọi requireRole/requireUser trước khi đọc/ghi, throw AppError cho lỗi nghiệp vụ.
5. Viết unit test cho service TRƯỚC khi làm UI, bắt buộc có ca "role không được phép bị từ chối" và ca dữ liệu không hợp lệ; thêm hàm mới vào MATRIX trong authz-matrix.test.ts.
6. Viết server action mỏng rồi mới tới UI.
7. Chạy npm run typecheck, npm run lint, npm run check:arch, npm test; sửa đến khi pass.
8. Gọi sub-agent code-reviewer trên thay đổi vừa làm và sửa các vấn đề mức CAO/TRUNG BÌNH.
9. Báo cáo: file đã đổi, kết quả 4 lệnh, các điểm cần tôi quyết định.
Giữ Skill ngắn gọn, dưới 50 dòng.
  2. Bước 2: Nhờ Claude tạo Sub-agent code-reviewer

    Trong cùng phiên, tạo sub-agent chỉ có quyền đọc. (Cũng có thể dùng lệnh /agents và chọn tạo bằng Claude.)

    Hãy tạo sub-agent tại .claude/agents/code-reviewer.md với frontmatter: name code-reviewer, description nêu rõ "dùng sau khi hoàn thành một tính năng, trước khi commit để review git diff", tools chỉ gồm Read, Grep, Glob, Bash (KHÔNG có Edit/Write).

System prompt của sub-agent: bạn là reviewer khó tính nhưng công bằng; chỉ đọc và nhận xét, không sửa code. Quy trình: chạy git diff và git status --short; đọc docs/ARCHITECTURE.md và docs/DOMAIN.md; kiểm tra từng file thay đổi theo checklist: kiến trúc (UI gọi thẳng Prisma? service import UI/next? server action làm nghiệp vụ?), phân quyền (mỗi hàm service gọi đúng requireRole theo ma trận? kiểm tra quyền sở hữu?), nghiệp vụ (luồng trạng thái, ràng buộc đặc biệt như admin cuối cùng, tự khoá mình), validation Zod ở server, test (có ca bị từ chối quyền?), chất lượng (any, console.log thừa, bí mật hard-code). Trả về báo cáo ngắn: KẾT LUẬN (ĐẠT/CẦN SỬA) và danh sách vấn đề dạng [mức độ] file:dòng — mô tả — cách sửa.

    Thoát phiên, kiểm tra hai file và commit:

    notepad .claude\skills\add-feature\SKILL.md
notepad .claude\agents\code-reviewer.md
git add -A
git commit -m "harness: skill add-feature va sub-agent code-reviewer"

    Checklist review: Skill có đủ 9 bước và description rõ; sub-agent có tools không chứa Edit/Write. (Bản tham khảo: reference/.claude/skills và reference/.claude/agents.)

  3. Bước 3: Thêm tính năng bằng một prompt ngắn

    Mở phiên mới và không nhắc tới Skill hay reviewer — kiểm tra chúng có tự được dùng không:

    claude --permission-mode acceptEdits
    Thêm chức năng quản lý tài khoản cho SYSTEM_ADMIN: trang /admin/users liệt kê người dùng (email, tên, role, trạng thái), có thể khoá/mở khoá tài khoản và đổi role. Không được hạ role hoặc khoá SYSTEM_ADMIN cuối cùng; không được tự khoá chính mình.

    Quan sát: dòng thông báo kích hoạt Skill add-feature; agent lập kế hoạch, viết test trước UI; cuối cùng gọi sub-agent code-reviewer. Đo và commit:

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab6
git add -A
git commit -m "lab6: quan ly tai khoan"
  4. Bước 4: Đọc báo cáo của reviewer và đối chiếu ràng buộc

    Xem báo cáo reviewer trong phiên (hoặc yêu cầu Claude gọi lại: Hãy gọi code-reviewer review thay đổi hiện tại). Tự đối chiếu hai ràng buộc trong yêu cầu (admin cuối cùng, tự khoá chính mình):

    Select-String -Path src\services\*.ts -Pattern "last|cuối|self|tự khoá|chính mình"
Get-ChildItem src\services\__tests__ -File | Select-Object -ExpandProperty Name

    Kiểm tra: mỗi ràng buộc nghiệp vụ có được xử lý và có test không, các hàm mới có nằm trong MATRIX không.

  5. Bước 5: Đọc điểm số và xử lý điểm bất thường

    Mở dòng mới nhất của scoreboard và đọc điểm. Dưới đây là các dấu hiệu bất thường cần xử lý:

    • typecheck, lint hoặc tests khác PASS (hoặc tests vẫn là NONE dù đã có hàm service mới).
    • ui_db_imports lớn hơn 0 (UI gọi thẳng Prisma) hoặc any_usage lớn hơn 0.
    • Một ràng buộc nghiệp vụ (admin cuối cùng, tự khoá chính mình) thiếu xử lý hoặc thiếu test; hoặc reviewer báo mức CAO mà agent chưa sửa.
    Import-Csv scoreboard.csv | Format-Table label, typecheck, lint, tests, test_files, ui_db_imports, any_usage
    Nguyên tắc xử lý điểm bất thường: đừng sửa tay rồi bỏ qua. Hãy nhờ Claude (1) tìm nguyên nhân gốc và sửa lỗi, rồi (2) bổ sung đúng một quy tắc harness (một dòng trong CLAUDE.md, một mục trong docs/, hoặc một luật của sensor) để lỗi loại này không lặp lại. Nếu mọi chỉ số đều bình thường, bạn không cần làm gì thêm — không thêm quy tắc "cho chắc", vì harness thừa làm agent chậm và rối hơn.

    Ví dụ cách yêu cầu (thay nội dung bằng điểm bất thường thật của bạn):

    Điểm số/báo cáo review bất thường: ràng buộc "không khoá SYSTEM_ADMIN cuối cùng" chưa có test. Hãy bổ sung test và sửa code nếu cần, rồi thêm MỘT thay đổi harness: bổ sung mục kiểm tra này vào checklist của sub-agent code-reviewer hoặc vào bước 5 của Skill add-feature, để các ràng buộc đặc biệt luôn được test.

    Reviewer và Skill là nơi tốt để ghi những "bài học nghiệp vụ" dạng mềm; các lỗi kiểm tra được bằng máy nên chuyển thành test hoặc sensor.

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab6-fix
git add -A
git commit -m "lab6: bo sung quy tac harness sau khi phat hien diem bat thuong"
  6. Bước 6: Hợp nhất vào main

    Khi điểm số ổn, hợp nhất vào main và đặt tag để Lab sau bắt đầu từ đây:

    git status --short
git switch main
git merge --ff-only lab6
git tag lab6-done

✅ Kết quả mong đợi

Ở lab6, agent đi đúng quy trình 9 bước mà bạn không phải nhắc: có kế hoạch, test trước UI, hàm mới nằm trong MATRIX, và reviewer độc lập đưa ra báo cáo có file:dòng. Hai ràng buộc "admin cuối cùng" và "tự khoá chính mình" được xử lý và có test đi kèm. Reviewer là sensor inferential — hữu ích nhưng không thay thế được test và script. Nếu có điểm bất thường, xử lý theo Bước 5.

Troubleshoot

Lỗi: Skill không được kích hoạt khi bạn yêu cầu thêm tính năng.
Nguyên nhân: description của Skill chưa đủ rõ, hoặc chưa mở phiên mới sau khi tạo.
Giải pháp: Nhờ Claude viết lại description nêu rõ các tình huống kích hoạt; mở phiên mới; thử gọi tường minh bằng tên add-feature để kiểm tra file có hợp lệ.
Lỗi: Reviewer nhận xét chung chung hoặc "ĐẠT" cho code có vấn đề.
Nguyên nhân: Checklist trong system prompt chưa đủ cụ thể; reviewer là sensor inferential nên có độ biến thiên.
Giải pháp: Bổ sung các mục kiểm tra cụ thể vào checklist (ví dụ ràng buộc admin cuối cùng) và dựa vào test/sensor computational cho những gì kiểm tra được bằng máy.
Lỗi: Agent chính không gọi reviewer.
Nguyên nhân: Bước 8 trong Skill chưa nhấn mạnh bắt buộc, hoặc description của sub-agent mơ hồ.
Giải pháp: Sửa Skill: "BẮT BUỘC gọi code-reviewer trước khi báo xong"; hoặc yêu cầu tường minh: "Hãy dùng sub-agent code-reviewer để review".
