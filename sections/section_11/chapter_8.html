11. Harness Engineering / Lab 4 - Vòng phản hồi tự động với Test & Hooks
Lab 4 / 8 — tự động hoá phản hồi: Test + Hook. Sensor ở Lab trước vẫn phụ thuộc agent "nhớ" chạy. Lab này thêm hai thành phần: bộ test (sensor kiểm tra hành vi) và Hook (chạy sensor tự động, đẩy lỗi ngược lại agent). Bạn nhờ Claude viết cả hai.

Mục tiêu

  • Nhờ Claude cài Vitest, viết unit test cho các service hiện có và cập nhật quy tắc test trong CLAUDE.md.
  • Nhờ Claude tạo Hook PostToolUse (lint + typecheck + kiến trúc sau mỗi lần sửa file) và Stop (test + kiến trúc trước khi kết thúc), dùng exit code 2 để đẩy lỗi ngược lại agent.
  • Thêm tính năng sửa/xoá tin của chính mình bằng một prompt ngắn và quan sát agent tự sửa nhờ phản hồi tự động.

Phân tầng sensor theo chi phí: kiểm tra nhanh sau mỗi lần sửa file, kiểm tra nặng (toàn bộ test) chỉ ở cuối lượt. Nét đứt là phản hồi tự động quay lại agent — bạn không phải nhắn thêm câu nào.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab trước: main có npm run check:arch (tag lab3-done).
  • Hiểu cơ bản về Hook (Section 9): event, matcher, stdin JSON, exit code.
  • PowerShell chạy được .ps1 với -ExecutionPolicy Bypass; database container đang chạy.

Các bước thực hành

  1. Bước 1: Nhờ Claude thiết lập Vitest và viết test 
    git switch main
git switch -c lab4
claude --permission-mode acceptEdits
    Hãy thiết lập kiểm thử tự động cho project:
1) Cài vitest, tạo vitest.config.ts có alias "@" trỏ tới src, thêm script "test": "vitest run" vào package.json.
2) Viết unit test cho các hàm hiện có trong src/services (auth-service, listing-service), đặt trong src/services/__tests__/-service.test.ts. Dùng vi.mock('@/lib/prisma') để không phụ thuộc database. Mỗi hàm service phải có ít nhất: 1 ca chạy đúng, và 1 ca bị từ chối vì sai role hoặc dữ liệu không hợp lệ.
3) Cập nhật CLAUDE.md (giữ dưới 60 dòng): thêm quy tắc "mỗi hàm service mới phải có unit test, gồm ca bị từ chối quyền", và Definition of Done gồm npm run typecheck, npm run lint, npm run check:arch, npm test.
Chạy npm test và báo kết quả.

    Thoát phiên, commit:

    npm test
git add -A
git commit -m "harness: vitest + unit test cho service"
  2. Bước 2: Nhờ Claude viết Hook phản hồi tự động

    Mô tả hành vi mong muốn thật cụ thể — đây là kỹ năng "đặc tả sensor" bạn đã luyện ở Lab trước:

    claude --permission-mode acceptEdits
    Hãy tạo Hook cho Claude Code trong project này, dùng PowerShell, đặt script trong .claude/hooks/ và khai báo trong .claude/settings.json (project scope):

1) Hook PostToolUse, matcher "Edit|Write": đọc JSON từ stdin, lấy tool_input.file_path. Chỉ xử lý file .ts/.tsx. Chạy lần lượt: npx eslint ; npx tsc --noEmit; node scripts/check-architecture.mjs. Nếu có lỗi: gom nội dung lỗi (có tiền tố [ESLINT]/[TYPECHECK]/[ARCHITECTURE]), cắt tối đa 4000 ký tự, ghi ra stderr và thoát exit code 2. Nếu ổn thoát 0.

2) Hook Stop: đọc JSON từ stdin; NẾU stop_hook_active = true thì thoát 0 ngay (chống vòng lặp vô hạn). Ngược lại chạy node scripts/check-architecture.mjs và npx vitest run --passWithNoTests; nếu fail thì ghi lỗi ra stderr (cắt 4000 ký tự) và thoát exit code 2.

Command trong settings.json dùng: powershell -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/.ps1
Lưu ý: script không được ghi/xoá file nào ngoài việc chạy các lệnh kiểm tra nêu trên. Sau khi tạo, hãy chỉ cho tôi cách chạy thử script thủ công bằng JSON giả lập trước khi tôi khởi động lại Claude Code.
    Bắt buộc review: Hook chạy tự động với quyền của bạn. Trước khi dùng, hãy mở từng script và xác nhận chỉ chạy các lệnh kiểm tra (eslint, tsc, node, vitest), không gọi mạng, không xoá/ghi file ngoài ý muốn. (Có bản tham khảo tại sourcecode/section_11/lab_realestate/reference/.claude/.)
  3. Bước 3: Chạy thử Hook thủ công

    Tạo file vi phạm, giả lập JSON mà Claude Code gửi vào stdin, kiểm tra exit code rồi xoá file:

    mkdir src\app\tmp-violation -Force
Set-Content -Path src\app\tmp-violation\page.tsx -Value "import { prisma } from '@/lib/prisma';`nexport default function P() { return null; }"
'{"tool_input":{"file_path":"src/app/tmp-violation/page.tsx"}}' | powershell -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/verify-changed-file.ps1
"exit code = $LASTEXITCODE"
Remove-Item src\app\tmp-violation -Recurse -Force

    Tên script có thể khác nếu Claude đặt tên khác — dùng đúng tên trong thư mục .claude/hooks. Kết quả mong đợi: có [ARCHITECTURE] và exit code = 2. Rồi commit harness:

    git add -A
git commit -m "harness: hook PostToolUse va Stop"
  4. Bước 4: Thêm tính năng bằng một prompt ngắn — Hook làm việc

    Khởi động lại Claude Code để nạp Hook:

    claude --permission-mode acceptEdits

    Gõ /hooks để xác nhận thấy PostToolUse và Stop, rồi dán yêu cầu (chỉ nêu nghiệp vụ, không dặn về test hay kiểm tra):

    Cho phép BUYER và SELLER sửa và xoá tin của chính mình (trang /my-listings có nút Sửa, Xoá). Khi sửa tin đã APPROVED hoặc REJECTED thì tin quay về PENDING. Người khác không được sửa/xoá tin không phải của mình.

    Quan sát log: sau mỗi lần ghi file Claude Code chạy Hook; nếu có lỗi lint/type/kiến trúc, nó tự sửa; trước khi dừng, npm test được chạy. Đo và commit:

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab4
git add -A
git commit -m "lab4: sua/xoa tin cua chinh minh"
  5. Bước 5: Thử "backpressure" của Hook Stop bằng một test cố ý hỏng 
    Set-Content -Path src\services\__tests__\demo-fail.test.ts -Value "import { test, expect } from 'vitest';`ntest('demo harness', () => { expect(1 + 1).toBe(3); });"
claude
    Liệt kê cấu trúc thư mục src/ ở mức 2 cấp và tóm tắt ngắn gọn.

    Khi Claude Code định kết thúc, Hook Stop chạy test, thấy lỗi và đẩy lại; Claude Code tiếp tục xử lý. Nhờ stop_hook_active nó không bị chặn vô hạn. Xoá file demo sau khi thử:

    Remove-Item src\services\__tests__\demo-fail.test.ts -Force
git status --short
  6. Bước 6: Đọc điểm số và xử lý điểm bất thường

    Mở dòng mới nhất của scoreboard và đọc điểm. Dưới đây là các dấu hiệu bất thường cần xử lý:

    • typecheck, lint hoặc tests khác PASS (hoặc tests vẫn là NONE dù đã có hàm service mới).
    • ui_db_imports lớn hơn 0 (UI gọi thẳng Prisma) hoặc any_usage lớn hơn 0.
    • test_files không tăng, hoặc không có ca "người khác không được sửa/xoá" cho hàm service mới.
    Import-Csv scoreboard.csv | Format-Table label, typecheck, lint, tests, test_files, ui_db_imports, any_usage
    Nguyên tắc xử lý điểm bất thường: đừng sửa tay rồi bỏ qua. Hãy nhờ Claude (1) tìm nguyên nhân gốc và sửa lỗi, rồi (2) bổ sung đúng một quy tắc harness (một dòng trong CLAUDE.md, một mục trong docs/, hoặc một luật của sensor) để lỗi loại này không lặp lại. Nếu mọi chỉ số đều bình thường, bạn không cần làm gì thêm — không thêm quy tắc "cho chắc", vì harness thừa làm agent chậm và rối hơn.

    Ví dụ cách yêu cầu (thay nội dung bằng điểm bất thường thật của bạn):

    Điểm số bất thường: test_files không tăng sau khi thêm hàm sửa/xoá tin, và chưa có test nào kiểm tra người khác bị từ chối. Hãy viết bổ sung test còn thiếu, rồi thêm MỘT quy tắc vào CLAUDE.md hoặc vào Hook Stop (ví dụ: hàm service mới mà không có file test tương ứng thì Stop hook báo lỗi) để lỗi này không lặp lại.

    Quy tắc có thể là guide (một dòng trong CLAUDE.md) hoặc sensor (mở rộng Hook). Ưu tiên sensor nếu kiểm tra được bằng máy.

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab4-fix
git add -A
git commit -m "lab4: bo sung quy tac harness sau khi phat hien diem bat thuong"
  7. Bước 7: Hợp nhất vào main

    Khi điểm số ổn, hợp nhất vào main và đặt tag để Lab sau bắt đầu từ đây:

    git status --short
git switch main
git merge --ff-only lab4
git tag lab4-done

✅ Kết quả mong đợi

Ở lab4, test_files > 0, tests = PASS, có ca test "người khác không được sửa/xoá". Quan trọng hơn: mọi vi phạm lint/type/kiến trúc trong quá trình làm đều được Hook phát hiện ngay lúc phát sinh và agent tự sửa, không cần bạn can thiệp. Với bước thử "backpressure", Hook Stop chặn kết thúc lượt khi có test hỏng và không kẹt vô hạn nhờ stop_hook_active. Nếu điểm bất thường, xử lý theo Bước 6.

Troubleshoot

Lỗi: Hook báo lỗi nhưng Claude Code không tự sửa, chỉ hiện cảnh báo.
Nguyên nhân: Script thoát với exit code khác 2 hoặc ghi lỗi ra stdout thay vì stderr.
Giải pháp: Nhờ Claude kiểm tra: lỗi phải ghi ra stderr và thoát exit 2.
Lỗi: Claude Code bị kẹt: sửa mãi rồi lại bị Stop hook chặn.
Nguyên nhân: Test fail do nguyên nhân agent không thể tự sửa (ví dụ database chưa chạy), hoặc thiếu kiểm tra stop_hook_active.
Giải pháp: Đảm bảo có kiểm tra stop_hook_active; chạy npm test thủ công tìm nguyên nhân; nhấn Esc ngắt phiên nếu cần.
Lỗi: Mỗi lần sửa file phải chờ rất lâu.
Nguyên nhân: tsc --noEmit kiểm tra toàn project mỗi lần.
Giải pháp: Yêu cầu Claude bật "incremental": true trong tsconfig.json, hoặc chuyển typecheck sang Hook Stop và chỉ giữ ESLint + kiểm tra kiến trúc ở PostToolUse.
Lỗi: Agent "lách" bằng cách sửa hoặc xoá test cho pass.
Nguyên nhân: Sensor nào cũng có thể bị lách nếu agent được phép sửa nó.
Giải pháp: Review git diff phần test; đã có quy tắc "không sửa/xoá test để lách" trong thông báo của Stop hook; Lab sau thêm thêm lớp kiểm soát bằng ma trận quyền và quyền hạn của agent.
