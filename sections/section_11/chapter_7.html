11. Harness Engineering / Lab 3 - Thêm Sensor kiểm tra kiến trúc
Lab 3 / 8 — thêm Sensor đầu tiên. Context (guide) chỉ nhắc agent làm đúng, không bảo đảm. Lab này thêm Sensor: một script kiểm tra kiến trúc bằng code (computational) để phát hiện vi phạm một cách chắc chắn. Quan trọng: bạn sẽ nhờ Claude viết sensor theo đặc tả của bạn rồi tự kiểm chứng sensor hoạt động đúng.

Mục tiêu

  • Nhờ Claude tạo scripts/check-architecture.mjs và lệnh npm run check:arch; học cách đặc tả một sensor và kiểm chứng sensor (bắt đúng lỗi, không báo nhầm).
  • Đưa sensor vào "Definition of Done" trong CLAUDE.md, thêm một tính năng bằng prompt ngắn và quan sát agent tự chạy sensor, tự sửa khi bị báo lỗi.

Sensor đọc mã nguồn và trả về kết quả xác định (pass/fail) kèm hướng dẫn sửa. Ở Lab này agent chạy sensor vì CLAUDE.md yêu cầu; Lab sau sẽ tự động hoá bằng Hook để không còn phụ thuộc agent có "nhớ" chạy hay không.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab trước: nhánh main có CLAUDE.md, docs/, tầng src/services (tag lab2-done).
  • Container database đang chạy; working tree sạch.

Các bước thực hành

  1. Bước 1: Nhờ Claude viết sensor theo đặc tả

    Từ main, tạo nhánh làm việc và đưa đặc tả. Chú ý đặc tả nêu rõ cái cần bắt, cái không được báo nhầm và định dạng thông báo lỗi dành cho agent:

    git switch main
git switch -c lab3
claude --permission-mode acceptEdits
    Hãy viết một "sensor" kiểm tra kiến trúc bằng code, theo docs/ARCHITECTURE.md.

Yêu cầu:
- File scripts/check-architecture.mjs, Node.js ESM thuần, KHÔNG dùng thư viện ngoài.
- Quy tắc 1: các file trong src/app và src/components không được import @prisma/client (trừ "import type") và không được import @/lib/prisma (kể cả đường dẫn tương đối tới src/lib/prisma).
- Quy tắc 2: các file trong src/services không được import từ @/app, @/components hoặc next/*.
- Bỏ qua các file *.test.ts / *.test.tsx.
- KHÔNG được báo nhầm với "import type { Role } from '@prisma/client'" trong UI.
- Khi vi phạm: in ra stderr, mỗi lỗi gồm file:dòng, tên quy tắc, dòng code vi phạm và "Cách sửa" ngắn gọn bằng tiếng Việt; thoát với exit code 1. Khi hợp lệ: in "Kiểm tra kiến trúc: OK" và exit 0.
- Thêm script "check:arch": "node scripts/check-architecture.mjs" vào package.json.
- Cập nhật CLAUDE.md: Definition of Done gồm cả npm run check:arch (giữ CLAUDE.md dưới 60 dòng).

Sau khi viết xong, hãy CHỨNG MINH sensor hoạt động: (1) chạy trên code hiện tại; (2) tạo tạm một file src/app/tmp-violation/page.tsx có import { prisma } from '@/lib/prisma' và chạy lại, phải báo vi phạm; (3) tạo tạm một file khác dùng "import type { Role } from '@prisma/client'" trong UI, phải KHÔNG báo lỗi; (4) xoá các file tạm và chạy lại cho OK. Báo cáo kết quả từng bước.
    Mẹo: bước "chứng minh" là điều khiến sensor đáng tin. Một sensor chưa từng được thử với lỗi thật có thể chạy "pass" mãi vì chính nó sai.
  2. Bước 2: Tự kiểm tra lại (đừng chỉ tin báo cáo)

    Thoát phiên, tự chạy và đọc script do Claude tạo:

    npm run check:arch
notepad scripts\check-architecture.mjs
git status --short

    Kiểm tra: không còn file tạm; script đúng đặc tả. Rồi commit:

    git add -A
git commit -m "harness: sensor check-architecture + DoD"
  3. Bước 3: Thêm tính năng bằng một prompt ngắn — sensor làm việc

    Mở phiên mới. Yêu cầu chỉ mô tả tính năng, không dặn gì về kiến trúc hay sensor — những thứ đó đã nằm trong harness:

    claude --permission-mode acceptEdits
    Thêm trang chi tiết tin /listings/[id] hiển thị đầy đủ thông tin tin đã duyệt.

    Quan sát chuỗi hành vi: agent viết code → chạy npm run check:arch theo Definition of Done → nếu có vi phạm thì tự sửa (ví dụ chuyển truy vấn vào service). Đo và commit:

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab3
git add -A
git commit -m "lab3: trang chi tiet tin"
  4. Bước 4: Đọc điểm số và xử lý điểm bất thường

    Mở dòng mới nhất của scoreboard và đọc điểm. Dưới đây là các dấu hiệu bất thường cần xử lý:

    • typecheck, lint hoặc tests khác PASS (hoặc tests vẫn là NONE dù đã có hàm service mới).
    • ui_db_imports lớn hơn 0 (UI gọi thẳng Prisma) hoặc any_usage lớn hơn 0.
    • npm run check:arch báo vi phạm khi bạn tự chạy lại, dù agent đã báo "xong".
    Import-Csv scoreboard.csv | Format-Table label, typecheck, lint, tests, test_files, ui_db_imports, any_usage
    Nguyên tắc xử lý điểm bất thường: đừng sửa tay rồi bỏ qua. Hãy nhờ Claude (1) tìm nguyên nhân gốc và sửa lỗi, rồi (2) bổ sung đúng một quy tắc harness (một dòng trong CLAUDE.md, một mục trong docs/, hoặc một luật của sensor) để lỗi loại này không lặp lại. Nếu mọi chỉ số đều bình thường, bạn không cần làm gì thêm — không thêm quy tắc "cho chắc", vì harness thừa làm agent chậm và rối hơn.

    Ví dụ cách yêu cầu (thay nội dung bằng điểm bất thường thật của bạn):

    Điểm số bất thường: ui_db_imports = 1 và npm run check:arch báo vi phạm ở src/app/listings/[id]/page.tsx. Hãy sửa lỗi, rồi xem sensor hoặc CLAUDE.md thiếu gì khiến agent không tự phát hiện, và bổ sung MỘT thay đổi nhỏ (ví dụ siết rule trong scripts/check-architecture.mjs kèm ca kiểm chứng, hoặc làm rõ Definition of Done). Không viết lại phần khác.

    Nhớ rằng sensor mới cũng cần được kiểm chứng: sau khi sửa, hãy chạy lại bước "chứng minh" ở Bước 1 với file vi phạm tạm.

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab3-fix
git add -A
git commit -m "lab3: bo sung quy tac harness sau khi phat hien diem bat thuong"
  5. Bước 5: Hợp nhất vào main

    Khi điểm số ổn, hợp nhất vào main và đặt tag để Lab sau bắt đầu từ đây:

    git status --short
git switch main
git merge --ff-only lab3
git tag lab3-done

✅ Kết quả mong đợi

npm run check:arch bắt đúng file tạm vi phạm, không báo nhầm import type, và trả OK sau khi dọn. Với prompt ngắn ở Bước 3, ui_db_imports bằng 0 và check:arch pass — kể cả khi agent lỡ viết sai lần đầu thì nó cũng bị sensor phản hồi và tự sửa. Bài học: Guide làm tăng xác suất đúng, Sensor làm lỗi không thể lọt qua mà không bị phát hiện. Nếu điểm vẫn bất thường, bổ sung quy tắc theo Bước 4.

Troubleshoot

Lỗi: Sensor báo vi phạm ở file không nên vi phạm (báo nhầm).
Nguyên nhân: Biểu thức chính quy quá rộng, hoặc chưa loại trừ import type/file test.
Giải pháp: Cho Claude xem dòng bị báo nhầm và yêu cầu: "Sensor báo nhầm dòng này, hãy sửa quy tắc và thêm ca kiểm chứng cho trường hợp đó."
Lỗi: Sensor luôn "OK" kể cả khi bạn tạo thử file vi phạm.
Nguyên nhân: Đường dẫn quét sai (ví dụ project không dùng thư mục src/) hoặc regex không khớp cách import của agent.
Giải pháp: Chạy lại bước "chứng minh" và yêu cầu Claude sửa tới khi file tạm bị bắt. Không tin một sensor chưa từng fail.
Lỗi: Agent bỏ qua check:arch, không chạy dù DoD có yêu cầu.
Nguyên nhân: Đây là điểm yếu còn lại của Guide — việc chạy sensor vẫn phụ thuộc agent.
Giải pháp: Hoàn toàn bình thường ở Lab này; Lab tiếp theo dùng Hook để chạy sensor tự động, không phụ thuộc agent.
