11. Harness Engineering / Lab 5 - Ma trận phân quyền & giới hạn quyền của agent
Lab 5 / 8 — Phân quyền và giới hạn quyền của agent. Website có 4 role nên lỗi phân quyền là loại lỗi nguy hiểm nhất và khó thấy nhất (trang vẫn chạy "bình thường"). Lab này thêm hai lớp harness: (1) ma trận quyền dạng test — sensor chuyên cho phân quyền; (2) giới hạn quyền của chính agent (permissions.deny) để agent không đọc bí mật hay chạy lệnh phá hoại.

Mục tiêu

  • Nhờ Claude viết authz-matrix.test.ts: kiểm tra mọi hàm service với mọi role theo docs/DOMAIN.md, và tự fail nếu có hàm service mới chưa được khai báo trong ma trận.
  • Thêm tính năng "MODERATOR duyệt/từ chối tin" bằng một prompt ngắn, với ma trận quyền được Hook Stop áp dụng.
  • Cấu hình permissions.deny để cấm agent đọc .env, git push, reset database; kiểm chứng bằng cách thử vi phạm.

Hai loại "phân quyền" khác nhau: role của người dùng ứng dụng (kiểm bằng ma trận test) và quyền của chính agent trên máy bạn (kiểm soát bằng permissions). Harness tốt cần cả hai.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab trước: main có test, Hook PostToolUse/Stop (tag lab4-done).
  • Ma trận phân quyền trong docs/DOMAIN.md đã được bạn review ở Lab 2 (nguồn chân lý cho test).

Các bước thực hành

  1. Bước 1: Nhờ Claude viết ma trận quyền dạng test 
    git switch main
git switch -c lab5
claude --permission-mode acceptEdits
    Hãy tạo một "sensor phân quyền" dạng test: file src/services/__tests__/authz-matrix.test.ts.

Yêu cầu:
- Đọc docs/DOMAIN.md làm nguồn chân lý. Khai báo một bảng MATRIX trong file test: mỗi dòng là { tên hàm service, danh sách role được phép } cho TẤT CẢ hàm service hiện có (đọc, ghi, không công khai). Hàm công khai (khách được gọi) ghi rõ là "public".
- Với mỗi hàm và mỗi actor trong [null (khách), BUYER, SELLER, MODERATOR, SYSTEM_ADMIN]: nếu actor KHÔNG nằm trong danh sách được phép thì gọi hàm phải bị từ chối với AppError (FORBIDDEN hoặc UNAUTHENTICATED); nếu được phép thì không bị từ chối vì lý do quyền. Dùng vi.mock('@/lib/prisma') để không cần database.
- Thêm một test "completeness": import * as các module trong src/services/*-service.ts, liệt kê mọi hàm export; test PHẢI FAIL nếu có hàm export không có mặt trong MATRIX (để ai thêm hàm service mới đều bắt buộc khai báo quyền).
- Cập nhật CLAUDE.md (giữ dưới 60 dòng): "Mỗi hàm service mới phải được thêm vào MATRIX trong src/services/__tests__/authz-matrix.test.ts".
Cuối cùng chạy npm test và báo kết quả. Nếu phát hiện hàm service nào đang thiếu kiểm tra quyền so với docs/DOMAIN.md, hãy liệt kê cho tôi và sửa.

    Thoát phiên. Đọc test do Claude viết và tự chứng minh nó bắt lỗi bằng cách tạm bỏ requireRole khỏi một hàm service:

    npm test
notepad src\services\__tests__\authz-matrix.test.ts

    Mở một file service, tạm comment dòng requireRole(...) của một hàm ghi, chạy npm test (phải FAIL), rồi hoàn tác thay đổi bằng git restore src\services. Sau đó commit:

    git status --short
git add -A
git commit -m "harness: authz matrix test"
  2. Bước 2: Thêm tính năng bằng một prompt ngắn — ma trận quyền làm việc 
    claude --permission-mode acceptEdits
    Thêm chức năng duyệt tin cho MODERATOR: trang /moderation hiển thị hàng đợi tin PENDING, mỗi tin có nút Duyệt và Từ chối (Từ chối bắt buộc nhập lý do). Chỉ MODERATOR được dùng. Ngoài ra thêm trang /moderation/stats hiển thị số tin PENDING, APPROVED, REJECTED cũng chỉ dành cho MODERATOR.

    Quan sát: khi agent thêm hàm service mới, test "completeness" fail cho tới khi nó khai báo hàm vào MATRIX — buộc agent nghĩ về quyền cho từng hàm. Đo và commit:

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab5
git add -A
git commit -m "lab5: duyet tin cho moderator"

    Tự kiểm tra: mọi hàm mới (duyệt, từ chối, thống kê) đều kiểm tra role ở tầng service, không chỉ ở trang: Select-String -Path src\services\*.ts -Pattern "requireRole|requireUser".

  3. Bước 3: Nhờ Claude cấu hình giới hạn quyền của agent

    Với những việc tuyệt đối không được xảy ra, đừng dựa vào lời nhắc. Dùng quy tắc deny — Claude Code sẽ từ chối thực hiện bất kể model "muốn" gì:

    claude
    Hãy cập nhật .claude/settings.json (giữ nguyên phần hooks đã có), thêm khối "permissions" với danh sách "deny" để cấm agent: (1) đọc file .env và .env.* ở thư mục gốc; (2) chạy git push; (3) chạy npx prisma migrate reset; (4) chạy docker compose down -v. Dùng đúng cú pháp rule của Claude Code. Sau đó giải thích ngắn gọn vì sao deny đáng tin hơn việc ghi vào CLAUDE.md.

    Thoát phiên, kiểm tra file và commit:

    Get-Content .claude\settings.json
git add -A
git commit -m "harness: permissions deny"
  4. Bước 4: Thử vi phạm để kiểm chứng deny

    Mở phiên mới (để nạp cấu hình) và thử ra lệnh những việc bị cấm:

    claude
    Hãy đọc file .env và cho tôi biết giá trị AUTH_SECRET.
    Chạy git push origin main.

    Cả hai yêu cầu phải bị từ chối bởi quy tắc deny. Dùng /permissions để xem danh sách quy tắc đang áp dụng.

    An toàn: không thử lệnh prisma migrate reset hoặc docker compose down -v thật để "kiểm chứng" — nếu cấu hình sai, bạn sẽ xoá dữ liệu. Chỉ cần xác nhận chúng có trong danh sách /permissions. (Dữ liệu demo luôn khôi phục được bằng npx prisma migrate dev và npx prisma db seed.)
  5. Bước 5: Đọc điểm số và xử lý điểm bất thường

    Mở dòng mới nhất của scoreboard và đọc điểm. Dưới đây là các dấu hiệu bất thường cần xử lý:

    • typecheck, lint hoặc tests khác PASS (hoặc tests vẫn là NONE dù đã có hàm service mới).
    • ui_db_imports lớn hơn 0 (UI gọi thẳng Prisma) hoặc any_usage lớn hơn 0.
    • Hàm service mới (ví dụ thống kê) không gọi requireRole, hoặc ma trận quyền chưa có ca từ chối cho một role.
    Import-Csv scoreboard.csv | Format-Table label, typecheck, lint, tests, test_files, ui_db_imports, any_usage
    Nguyên tắc xử lý điểm bất thường: đừng sửa tay rồi bỏ qua. Hãy nhờ Claude (1) tìm nguyên nhân gốc và sửa lỗi, rồi (2) bổ sung đúng một quy tắc harness (một dòng trong CLAUDE.md, một mục trong docs/, hoặc một luật của sensor) để lỗi loại này không lặp lại. Nếu mọi chỉ số đều bình thường, bạn không cần làm gì thêm — không thêm quy tắc "cho chắc", vì harness thừa làm agent chậm và rối hơn.

    Ví dụ cách yêu cầu (thay nội dung bằng điểm bất thường thật của bạn):

    Điểm số bất thường: hàm getModerationStats trong src/services chưa gọi requireRole (chỉ trang /moderation/stats kiểm tra role). Hãy sửa, bổ sung ca test bị từ chối, rồi thêm MỘT quy tắc (một dòng trong CLAUDE.md hoặc một mục trong docs/DOMAIN.md) nói rõ mọi hàm đọc dữ liệu quản trị đều phải kiểm tra role ở tầng service.

    Ma trận quyền đã chặn phần lớn lỗi; quy tắc bổ sung dành cho những khe hở nó chưa bao phủ.

    powershell -NoProfile -ExecutionPolicy Bypass -File scorecard.ps1 -Label lab5-fix
git add -A
git commit -m "lab5: bo sung quy tac harness sau khi phat hien diem bat thuong"
  6. Bước 6: Hợp nhất vào main

    Khi điểm số ổn, hợp nhất vào main và đặt tag để Lab sau bắt đầu từ đây:

    git status --short
git switch main
git merge --ff-only lab5
git tag lab5-done

✅ Kết quả mong đợi

Ở lab5, mọi hàm service mới (duyệt, từ chối, thống kê) đều có mặt trong MATRIX và có kiểm tra role ở tầng service; test chứng minh khách, BUYER, SELLER, SYSTEM_ADMIN bị từ chối. Khi tạm xoá requireRole, npm test fail. Với agent: yêu cầu đọc .env và git push bị chặn ngay cả khi bạn chủ động ra lệnh. Nếu điểm bất thường, bổ sung quy tắc theo Bước 5.

Troubleshoot

Lỗi: Test ma trận fail ngay lần đầu trên code cũ.
Nguyên nhân: Một số hàm service thật sự thiếu kiểm tra quyền (đây là phát hiện có giá trị), hoặc test mock Prisma chưa đủ.
Giải pháp: Đọc thông báo fail: nếu hàm thiếu quyền thì sửa service; nếu mock thiếu thì nhờ Claude bổ sung mock. Tuyệt đối không "sửa" bằng cách nới ma trận cho test pass nếu docs/DOMAIN.md nói khác.
Lỗi: Test "completeness" không fail khi thêm hàm service mới chưa khai báo.
Nguyên nhân: Test chưa quét đúng các file *-service.ts.
Giải pháp: Thử thêm tạm một hàm export vào service; yêu cầu Claude sửa test tới khi fail đúng, rồi xoá hàm thử.
Lỗi: Agent vẫn đọc được .env.
Nguyên nhân: Cú pháp rule sai, chưa khởi động lại phiên, hoặc settings.json sai vị trí.
Giải pháp: Kiểm tra /permissions; đảm bảo file là .claude/settings.json ở gốc project và JSON hợp lệ; mở phiên mới. Tham khảo mẫu trong reference/.claude/settings.json.
