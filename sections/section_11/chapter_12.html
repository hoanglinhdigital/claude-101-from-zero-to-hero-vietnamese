11. Harness Engineering / Lab 8 - Quan sát, cải tiến & tổng kết hành trình
Lab 8 / 8 — Quan sát và cải tiến. Một harness không "xong" ở lần đầu. Lab cuối dạy vòng lặp khép kín của người làm Harness Engineering: quan sát → đo → sửa một điều → đo lại → ghi nhận, rồi nhìn lại toàn bộ hành trình từ Prompt tới Harness hoàn chỉnh bằng số liệu.

Mục tiêu

  • Nhờ Claude viết công cụ đọc transcript của một phiên để thấy agent đã gọi tool nào và vấp lỗi nào.
  • Nhờ Claude tạo bộ eval (3 task cố định, chạy headless, chấm điểm bằng scorecard.ps1) và đo harness hiện tại (nhãn v1).
  • Biến một lỗi lặp lại thành cải tiến harness (guide hoặc sensor), ghi harness-changelog.md và đo lại (nhãn v2).
  • Tổng hợp bản đồ hành trình: mỗi thành phần harness ngăn được loại lỗi nào, qua scoreboard.csv.
  • Dọn dẹp toàn bộ môi trường (container, volume, nhánh thực hành).

Vòng cải tiến khép kín: chạy bộ task → chấm điểm tự động → đọc transcript tìm lỗi lặp → sửa harness → chạy lại với nhãn mới và so sánh số liệu. Mọi thay đổi đều có bằng chứng đo lường.

Yêu cầu trước khi bắt đầu

  • Hoàn thành các Lab trước: main chứa toàn bộ harness (tag lab7-done); container database đang chạy.
  • Claude Code CLI hỗ trợ chế độ -p (chạy không tương tác): kiểm tra claude --help.
  • Chấp nhận chi phí token: 3 task × mỗi lần đo, giới hạn --max-turns 40 cho mỗi task.

Các bước thực hành

  1. Bước 1: Tạo nhánh và nhờ Claude viết công cụ phân tích transcript 
    cd D:\lab-realestate
git switch main
git switch -c lab8-improve
claude --permission-mode acceptEdits
    Hãy viết script PowerShell analyze-transcript.ps1 để tóm tắt một phiên Claude Code từ file transcript .jsonl. Claude Code lưu transcript tại %USERPROFILE%\.claude\projects\<đường-dẫn-project-mã-hoá, mọi ký tự không phải chữ/số thay bằng dấu gạch ngang>\*.jsonl. Script: nhận tham số -Path (tuỳ chọn; nếu bỏ trống thì lấy file .jsonl mới nhất của project hiện tại); đọc từng dòng JSON (bỏ qua dòng không parse được); đếm số lần gọi mỗi tool (phần tử content có type=tool_use, lấy name); gom các tool_result có is_error=true, cắt 160 ký tự đầu, nhóm theo nội dung và in 10 lỗi lặp lại nhiều nhất. Cuối cùng in gợi ý: lỗi lặp từ 2 lần trở lên là ứng viên để thêm rule hoặc sensor. Script chỉ đọc, không ghi file.

    Thoát phiên, chạy thử (có thể truyền transcript của phiên bất kỳ ở các Lab trước):

    powershell -NoProfile -ExecutionPolicy Bypass -File analyze-transcript.ps1
    Lưu ý: định dạng transcript là chi tiết nội bộ của Claude Code và có thể đổi giữa các phiên bản. Nếu kết quả trống, mở một file .jsonl để xem cấu trúc thực tế và nhờ Claude điều chỉnh script. (Bản tham khảo: reference/analyze-transcript.ps1.)
  2. Bước 2: Nhờ Claude tạo bộ eval 
    claude --permission-mode acceptEdits
    Hãy tạo bộ đánh giá (eval) cho harness:

1) eval-tasks.json: mảng 3 task có id và prompt, đều là task KHÔNG cần đổi schema Prisma và chưa có trong code hiện tại: T1-profile — thêm trang /profile cho người dùng đã đăng nhập, hiển thị email, tên, role và số tin đã đăng theo từng trạng thái; T2-area-filter — thêm bộ lọc diện tích tối thiểu/tối đa (areaM2) vào trang danh sách /listings; T3-admin-user-detail — thêm trang /admin/users/[id] chỉ cho SYSTEM_ADMIN, hiển thị chi tiết tài khoản và danh sách tin của tài khoản đó. (Nếu một tính năng đã tồn tại trong code thì đổi prompt sang tính năng tương tự chưa có.)

2) run-eval.ps1 (PowerShell) với tham số bắt buộc -Label: từ chối chạy nếu "git status --porcelain" không rỗng; với mỗi task: chạy "claude -p  --permission-mode acceptEdits --max-turns 40", rồi chạy scorecard.ps1 -Label "

    Thoát phiên. Review kỹ run-eval.ps1 — script có lệnh xoá file (git clean), phải chắc chắn nó chỉ chạy khi working tree sạch và chỉ làm trên nhánh thực hành. (Bản tham khảo: reference/run-eval.ps1, reference/eval-tasks.json.)

    notepad run-eval.ps1
git add -A
git commit -m "harness: eval tools"
  3. Bước 3: Chạy bộ eval trên harness hiện tại (nhãn v1)
    Cảnh báo: run-eval.ps1 khôi phục working tree sau mỗi task (git clean -fd), xoá mọi thay đổi chưa commit. Hãy chắc chắn đã commit hết và chỉ chạy trên nhánh thực hành lab8-improve. File bị Git bỏ qua (.env, scoreboard.csv) không bị xoá. 
    git status --short
powershell -NoProfile -ExecutionPolicy Bypass -File run-eval.ps1 -Label v1

    Quá trình mất vài phút. Kết quả cuối in ra bảng của ba task với các cột typecheck, lint, tests, ui_db_imports, any_usage.

  4. Bước 4: Phân tích để tìm lỗi lặp 
    powershell -NoProfile -ExecutionPolicy Bypass -File analyze-transcript.ps1

    Chỉ ra: task nào có cột FAIL/chỉ số xấu? Lỗi nào lặp từ 2 lần trở lên? Mở lại task đó bằng chế độ tương tác (claude + dán prompt của task) nếu cần hiểu nguyên nhân gốc.

    Mẹo: nếu cả 3 task đều "xanh" ở v1, hãy làm khó bộ task (thêm yêu cầu liên quan đến nhiều role hoặc ràng buộc nghiệp vụ) rồi chạy lại với nhãn mới. Harness tốt cần bộ task đủ khó để lộ điểm yếu.
  5. Bước 5: Khi v1 lộ điểm bất thường — chọn loại cải tiến (Guide hay Sensor) và chỉ đổi MỘT điều

    Chỉ cải tiến khi số liệu v1 cho thấy vấn đề thật; nếu mọi chỉ số đều bình thường, hãy làm khó bộ task (Bước 4) chứ đừng thêm quy tắc "cho chắc".

    • Lỗi kiểm tra được bằng máy → thêm/siết sensor (rule trong check-architecture.mjs, test, bước trong Hook).
    • Lỗi do agent thiếu thông tin → bổ sung guide (ví dụ cụ thể trong docs/*.md, một dòng rõ ràng trong CLAUDE.md, mô tả Skill).

    Ví dụ yêu cầu Claude thực hiện cải tiến (thay nội dung bằng lỗi thật bạn quan sát được):

    claude --permission-mode acceptEdits
    Trong lần eval v1, task T3 (trang chi tiết tài khoản của SYSTEM_ADMIN) bị lỗi: hàm lấy danh sách tin của một tài khoản không kiểm tra role ở tầng service, chỉ kiểm ở trang. Hãy cải tiến harness để lỗi loại này không lặp lại, chỉ thay đổi MỘT điều: bổ sung vào docs/DOMAIN.md một mục "Hàm đọc dữ liệu không công khai" nêu rõ mọi hàm đọc dữ liệu của người khác hay dữ liệu quản trị cũng phải gọi requireRole ở tầng service, kèm ví dụ ngắn; và thêm một dòng nhắc trong CLAUDE.md. Không đổi gì khác.

Troubleshoot

Lỗi: run-eval.ps1 báo "Working tree chưa sạch".
Nguyên nhân: Còn thay đổi chưa commit (kể cả file mới).
Giải pháp: git status --short để xem, rồi git add -A và git commit. Đảm bảo scoreboard.csv nằm trong .gitignore.
Lỗi: claude -p dừng chờ xác nhận quyền hoặc không sửa được file.
Nguyên nhân: Chế độ không tương tác không thể hỏi bạn; thao tác ngoài phạm vi acceptEdits hoặc bị permissions.deny chặn.
Giải pháp: Giữ task trong phạm vi sửa file và các lệnh kiểm tra; nếu cần thêm lệnh, khai báo trong permissions.allow của .claude/settings.json. Không dùng chế độ bỏ qua toàn bộ quyền trên máy thật.
Lỗi: analyze-transcript.ps1 báo không tìm thấy transcript.
Nguyên nhân: Tên thư mục project được mã hoá khác dự kiến.
Giải pháp: Liệt kê Get-ChildItem "$env:USERPROFILE\.claude\projects", chọn thư mục tương ứng và truyền đường dẫn file bằng -Path.
Lỗi: Kết quả v1 và v2 dao động khó kết luận.
Nguyên nhân: Kết quả của model có tính ngẫu nhiên; ba task là mẫu nhỏ.
Giải pháp: Chạy mỗi nhãn 2–3 lần, tăng số task; chỉ rút ra kết luận khi sự khác biệt lặp lại.
