3. Claude Skills & Agent / Claude Sub-Agent là gì?

Giới thiệu

Agent là một hệ thống AI có khả năng tự chủ thực hiện một chuỗi hành động để đạt mục tiêu được giao, thay vì chỉ trả lời một câu hỏi duy nhất: nó tự lên kế hoạch, gọi các tool (đọc/ghi file, chạy lệnh, tìm kiếm, gọi API...), quan sát kết quả rồi quyết định bước tiếp theo, lặp lại cho đến khi hoàn thành hoặc cần hỏi lại người dùng. Claude Code chính là một agent như vậy — phiên CLI bạn đang trò chuyện đã có đầy đủ system prompt, bộ tool và khả năng tự điều phối công việc.

Minh họa AI Agent bởi Gemini

Sub-agent trong Claude Code là một "trợ lý con" chuyên biệt, có system prompt riêng và phạm vi công cụ (tools) riêng, được Agent chính (main agent — phiên Claude Code User đang trò chuyện trực tiếp) gọi đến để xử lý một loại việc cụ thể, rồi trả kết quả tổng hợp lại. Thay vì để một Agent duy nhất phải "biết tuốt" và chia sẻ chung một context dài, mô hình Sub-agent giúp chuyên biệt hoá từng phần việc, giữ context của Agent chính gọn nhẹ, và hạn chế rủi ro khi giao cho một tác vụ nhạy cảm chỉ đúng những tool cần thiết.

Một số lưu ý

Claude Code chính là "agent": phiên làm việc CLI bạn đang chạy (đọc file, sửa code, chạy lệnh...) đã là một agent hoàn chỉnh. Nó không cần bạn định nghĩa thêm một "agent gốc" nào khác — vai trò đó do chính CLI đảm nhiệm.
Sub-agent giải quyết vấn đề cụ thể: Một sub-agent trong Claude Code là một instance Claude độc lập, có system prompt riêng, context window riêng, danh sách tool riêng và permission mode riêng. Khi Claude Code chạy sub-agent, nó tạo ra một context window tách biệt, đưa input vào và chỉ trả lại bản tóm tắt cho phiên chính.
Mục đích thiết kế: nên dùng sub-agent khi một tác vụ phụ sẽ làm ngập conversation chính bằng kết quả tìm kiếm, log, hay nội dung file mà bạn sẽ không cần tham chiếu lại — sub-agent sẽ làm việc đó trong context riêng và chỉ trả về bản tóm tắt. Đây là lý do nó được gọi là "sub" — nó luôn phục vụ và báo cáo lại cho agent chính (phiên CLI của bạn), chứ không tồn tại như một thực thể độc lập ngang hàng.

Các tính năng chính

  • Mỗi Sub-agent được khai báo trong một file Markdown riêng tại .claude/agents/<ten-agent>.md, với YAML frontmatter khai báo name, description, tools (danh sách công cụ được phép dùng) và model (model nào xử lý Sub-agent này).
  • Phạm vi tool riêng biệt — Sub-agent chỉ được cấp đúng những tool cần cho công việc của nó (vd Sub-agent review code chỉ cần đọc file, không cần quyền ghi/xoá), giảm rủi ro so với việc dùng chung toàn quyền của Agent chính.
  • System prompt riêng — Sub-agent có bộ hướng dẫn hành vi độc lập, không lẫn với system prompt của Agent chính, giúp nó tập trung đúng vai trò được giao (vd luôn phản hồi theo format checklist khi review code).
  • Agent chính gọi Sub-agent thông qua Agent tool (còn gọi là Task tool) — có thể tự động dựa trên description (tương tự cách Skill được auto-discover), hoặc gọi rõ ràng qua lệnh /agents.
  • Sub-agent chạy trong ngữ cảnh (context) riêng, không làm phình to context của Agent chính — chỉ kết quả cuối cùng được trả về, giúp phiên làm việc chính giữ được nhiều "chỗ trống" cho các bước tiếp theo.

Use Cases

code-reviewer

Sub-agent chỉ có quyền đọc code (không quyền ghi), chuyên review chất lượng, bảo mật, coding convention trước khi merge.

test-writer

Sub-agent chuyên viết unit test/integration test cho một hàm hoặc module cụ thể theo đúng framework test của project.

doc-writer

Sub-agent chuyên tổng hợp và viết tài liệu kỹ thuật (API docs, README) theo đúng template chuẩn của team.

Research / Explore agent

Sub-agent chuyên tìm kiếm, đọc nhiều file trong codebase lớn để trả lời câu hỏi kiến trúc, tránh làm phình context của Main Agent.

Thông tin bổ sung

Best practice khi thiết kế Skill/Agent

  • Đặt tên rõ ràng, ngắn gọn — tên Skill/Sub-agent nên phản ánh đúng chức năng (vd code-reviewer thay vì helper1), giúp cả người và Claude Code dễ nhận diện.
  • Viết description mô tả rõ trigger — liệt kê cụ thể ngữ cảnh, từ khoá người dùng thường dùng khi cần đến Skill/Sub-agent đó, tránh mô tả chung chung khiến việc auto-invoke không chính xác.
  • Giới hạn phạm vi tools ở mức tối thiểu cần thiết — Sub-agent chỉ nên có đúng những tool cần cho công việc (nguyên tắc least privilege), không nên mặc định cấp toàn quyền giống Agent chính.
  • Tránh chồng chéo phạm vi — không nên có nhiều Skill/Sub-agent mô tả trùng lặp ý nghĩa, dễ gây nhầm lẫn khi Main Agent phải chọn giữa nhiều lựa chọn giống nhau.
  • Chọn model phù hợp cho từng Sub-agent — Sub-agent xử lý việc đơn giản, lặp lại nhiều (vd review syntax cơ bản) có thể dùng model nhẹ hơn (Haiku) để tiết kiệm chi phí, giữ Sonnet/Opus cho việc cần suy luận sâu.
