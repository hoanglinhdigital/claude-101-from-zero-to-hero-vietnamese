4. Claude Code cho Developer / Kỹ thuật viết yêu cầu (prompt) rõ ràng cho tác vụ code

Giới thiệu

Chất lượng kết quả của Claude Code phụ thuộc rất lớn vào chất lượng của prompt đầu vào. Một prompt mơ hồ khiến Claude Code phải tự đoán ngữ cảnh — dễ chọn sai file, sai phạm vi ảnh hưởng, hoặc hỏi lại nhiều lần làm chậm tiến độ. Chương này trình bày kỹ thuật viết prompt rõ ràng cho 3 loại tác vụ code phổ biến: thêm tính năng (feature), sửa lỗi (bugfix) và refactor.

Các tính năng chính

  • Một prompt rõ ràng cho tác vụ code cần đủ 3 phần: Context (file/module liên quan), Hành vi mong đợi (kết quả cụ thể sau khi hoàn thành), và Ràng buộc (những gì không được thay đổi, convention cần tuân theo).
  • Với feature: nêu rõ tính năng làm gì, đặt ở đâu trong cấu trúc project, có phụ thuộc vào tính năng/module nào đã có sẵn hay không.
  • Với bugfix: nêu rõ hành vi hiện tại (sai) vs hành vi mong đợi (đúng), bước tái hiện lỗi, và file/log liên quan nếu có.
  • Với refactor: nêu rõ mục tiêu refactor (dễ đọc hơn, tách logic, giảm trùng lặp...) và cam kết không thay đổi hành vi hiện tại — đây là ràng buộc quan trọng nhất của loại tác vụ này.
  • Nên chỉ định rõ file/đường dẫn cụ thể nếu đã biết, thay vì để Claude Code tự tìm kiếm toàn bộ project — giúp tiết kiệm thời gian và context.

Use Cases

Feature request từ Product Owner

Chuyển yêu cầu nghiệp vụ mơ hồ thành prompt kỹ thuật cụ thể có context file, giúp Claude Code hiện thực hoá đúng ý định ban đầu.

Bugfix từ báo cáo lỗi ngắn

Bổ sung bước tái hiện lỗi và hành vi mong đợi trước khi giao cho Claude Code, giảm số lần phải sửa lại.

Refactor an toàn

Ràng buộc rõ "không đổi hành vi" giúp Claude Code tự kiểm tra lại bằng test hiện có trước khi báo hoàn thành.

Thông tin bổ sung

Không cần viết prompt dài dòng cho mọi tác vụ — với việc nhỏ, rõ ràng tự nhiên (vd "đổi tên biến amt thành amount trong file X"), một câu ngắn là đủ. Kỹ thuật viết prompt rõ ràng nên áp dụng có chọn lọc: dùng đầy đủ 3 phần (Context – Hành vi mong đợi – Ràng buộc) cho tác vụ có rủi ro sai lệch cao hoặc ảnh hưởng nhiều file; tác vụ đơn giản, phạm vi hẹp thì không cần cầu kỳ.

Nếu project đã có file CLAUDE.md mô tả convention chung (đã học ở Section 2), phần "Ràng buộc" trong prompt có thể được rút ngắn vì Claude Code đã tự đọc convention đó mỗi phiên làm việc — chỉ cần nêu ràng buộc riêng biệt cho tác vụ hiện tại.
