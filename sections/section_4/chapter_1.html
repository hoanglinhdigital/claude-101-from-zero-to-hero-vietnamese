4. Claude Code cho Developer / Quy trình làm việc chuẩn: Explore → Plan → Code → Verify

Giới thiệu

Khi giao một tác vụ code cho Claude Code, kết quả tốt nhất không đến từ việc gõ một yêu cầu duy nhất và chờ Claude "làm hết trong một lần" — mà đến từ việc đi theo một quy trình làm việc chuẩn gồm 4 giai đoạn: Explore → Plan → Code → Verify. Quy trình này giúp Claude Code hiểu đúng ngữ cảnh trước khi sửa code, cho học viên cơ hội duyệt lại kế hoạch trước khi thay đổi được thực thi, và luôn kết thúc bằng một bước kiểm chứng kết quả — thay vì "vibe coding" (code theo cảm tính, tin tưởng mù quáng vào output của AI).

Các tính năng chính

  • Explore — Claude Code đọc và tìm hiểu codebase liên quan, chưa sửa bất kỳ file nào.
  • Plan — Claude Code đề xuất kế hoạch thực hiện chi tiết, học viên đọc và duyệt (approve) trước khi cho thực thi.
  • Code — Claude Code thực thi thay đổi đúng theo kế hoạch đã được duyệt: sửa file, tạo file mới, chạy lệnh cần thiết.
  • Verify — Build, chạy test/lint, xem lại git diff để xác nhận thay đổi đúng như mong đợi, không phát sinh lỗi ngoài ý muốn.
  • 4 giai đoạn này lặp lại theo vòng — nếu Verify phát hiện vấn đề, quay lại Explore/Plan để điều chỉnh, không nên "vá" tạm bằng một prompt sửa lỗi rời rạc.

Explore → Plan → Code → Verify là một vòng lặp: nếu Verify phát hiện sai lệch, quay lại Explore/Plan để điều chỉnh kế hoạch thay vì chỉ sửa vá tạm ở bước Code.

Chi tiết từng giai đoạn

Explore Yêu cầu Claude Code đọc file liên quan, tóm tắt cách hoạt động hiện tại. Không cho phép sửa file ở bước này.
Plan Chuyển sang Plan mode (Shift+Tab). Claude Code trình bày các bước dự kiến thực hiện, học viên đọc kỹ và duyệt hoặc yêu cầu chỉnh sửa kế hoạch.
Code Sau khi kế hoạch được duyệt, Claude Code thực thi: sửa file, tạo file mới, cài package, chạy lệnh cần thiết.
Verify Chạy build/test/lint, đọc lại git diff từng file đã đổi để xác nhận đúng phạm vi, không sửa nhầm chỗ không liên quan.
Vì sao không nên bỏ qua bước Explore và Plan? Với codebase nhỏ, một prompt trực tiếp có thể vẫn cho kết quả đúng. Nhưng với codebase lớn hoặc tác vụ ảnh hưởng nhiều file, bỏ qua Explore/Plan khiến Claude Code dễ đoán sai ngữ cảnh (vd: sửa nhầm phiên bản cũ của một hàm đã được refactor ở nơi khác), dẫn đến phải sửa lại nhiều lần — tốn thời gian hơn so với việc dành 1-2 phút đọc kế hoạch trước.

Use Cases

Thêm tính năng vào codebase lớn

Explore giúp Claude Code hiểu đúng convention hiện có trước khi Plan đề xuất vị trí đặt code mới, tránh phá vỡ cấu trúc sẵn có.

Sửa bug khó tái hiện

Explore kỹ luồng dữ liệu liên quan đến bug trước khi Plan đề xuất hướng fix, tránh sửa nhầm nguyên nhân triệu chứng thay vì gốc rễ.

Refactor phạm vi rộng

Plan giúp học viên thấy trước toàn bộ danh sách file sẽ bị ảnh hưởng trước khi cho Claude Code thực thi đồng loạt.

Thông tin bổ sung

Trong thực tế, 4 giai đoạn này không nhất thiết cần 4 prompt riêng biệt — Claude Code có thể tự chuyển từ Explore sang Plan trong cùng một phiên trò chuyện khi đang ở Plan mode. Điều quan trọng là học viên luôn dừng lại ở bước Plan để đọc và duyệt trước khi cho phép Code thực thi, và luôn có bước Verify cuối cùng — không nên coi phản hồi "đã hoàn thành" của Claude Code là đủ để tin tưởng tuyệt đối.

Lưu ý: Với các tác vụ đơn giản, lặp lại nhiều lần và rủi ro thấp (vd: đổi tên biến, sửa lỗi chính tả trong comment), có thể rút ngắn quy trình và bỏ qua Plan mode để làm việc nhanh hơn. Tuy nhiên bước Verify (xem lại diff) nên luôn được giữ lại, bất kể tác vụ lớn hay nhỏ.
