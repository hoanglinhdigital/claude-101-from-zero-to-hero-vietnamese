4. Claude Code cho Developer / Lab - Tích hợp Claude Code với Git để review pull request tự động
Điều kiện tiên quyết: Bài lab này dùng lại project D:\lab-expense-management — đã được khởi tạo và tổ chức lại kèm file CLAUDE.md ở bài lab "Tổ chức project và định nghĩa quy tắc làm việc thông qua CLAUDE.md". Nếu chưa hoàn thành bài đó, hãy quay lại thực hiện trước. Nếu bạn đã làm tiếp bài Skill & Sub-agent thì càng tốt — phần review sẽ bắt được nhiều lỗi hơn.

Vấn đề đang gặp phải

Đến thời điểm này, mọi quy tắc của project đã nằm trong CLAUDE.md — nhưng chúng chỉ có tác dụng khi bạn ngồi trước máy và gõ prompt. Ngay khi code được đẩy lên GitHub dưới dạng pull request, các quy tắc đó biến mất: người review là con người, và có thể bỏ sót.

  • Review thủ công không đồng đều. Cùng một lỗi "quên lọc userId", hôm nay bạn bắt được, tuần sau mệt thì bỏ qua — và đó là lỗ hổng bảo mật thật sự.
  • Người review là điểm nghẽn. PR nằm chờ vài ngày chỉ vì tech lead bận. Tác giả PR cũng không biết mình sai ở đâu để sửa trước.
  • Quy tắc project không được kiểm tra tự động. ESLint bắt được lỗi cú pháp, nhưng không bắt được "số tiền phải dùng Decimal chứ không dùng Float" hay "mọi truy vấn phải lọc isDeleted".
  • Kiến thức chỉ nằm trong đầu người review. Thành viên mới vào không có cách nào học được các quy ước ngầm ngoài việc bị nhắc đi nhắc lại trong comment.
Ý tưởng của bài lab: đưa chính CLAUDE.md và bộ quy tắc project lên GitHub Actions, để mỗi pull request đều được Claude review tự động theo đúng tiêu chuẩn đó — trước khi con người kịp nhìn vào. Con người vẫn là người quyết định merge, Claude chỉ làm vòng lọc đầu tiên.

Mục tiêu

  • Dùng Claude Code cho toàn bộ luồng Git ở máy local: soạn .gitignore, viết commit message theo Conventional Commits, tạo pull request kèm mô tả đầy đủ.
  • Cài đặt Claude GitHub App bằng lệnh /install-github-app và cấu hình secret ANTHROPIC_API_KEY cho repository.
  • Viết workflow GitHub Actions dùng anthropics/claude-code-action@v1 để tự động review mọi pull request theo quy tắc riêng của project.
  • Tạo một pull request có lỗi cố ý (thiếu điều kiện userId, cộng tiền bằng Number, không validate input) và kiểm chứng Claude có phát hiện đúng hay không.
  • Tương tác hai chiều với Claude ngay trên pull request bằng cách mention @claude, rồi để Claude Code sửa lỗi ở local và push lại.
  • Hiểu giới hạn: khi nào tin tưởng nhận xét của Claude, khi nào bắt buộc phải có con người duyệt.

name: Claude Code Review

on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]
    # Optional: Only run on specific file changes
    # paths:
    #   - "src/**/*.ts"
    #   - "src/**/*.tsx"
    #   - "src/**/*.js"
    #   - "src/**/*.jsx"

jobs:
  claude-review:
    # Optional: Filter by PR author
    # if: |
    #   github.event.pull_request.user.login == 'external-contributor' ||
    #   github.event.pull_request.user.login == 'new-developer' ||
    #   github.event.pull_request.author_association == 'FIRST_TIME_CONTRIBUTOR'

    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
      issues: read
      id-token: write

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 1

      - name: Run Claude Code Review
        id: claude-review
        uses: anthropics/claude-code-action@v1
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: 'https://github.com/anthropics/claude-code.git'
          plugins: 'code-review@claude-code-plugins'
          prompt: |
            REPO: ${{ github.repository }}
            PR NUMBER: ${{ github.event.pull_request.number }}

            Bạn là senior reviewer của project Expense Management (Next.js + Prisma + MySQL).
            Hãy review pull request này và để lại nhận xét bằng TIẾNG VIỆT.

            Đọc quy tắc dự án trong CLAUDE.md và file .github/review-guidelines.md
            trước khi review. Ưu tiên kiểm tra theo thứ tự:

            1. BẢO MẬT: mọi truy vấn Prisma trên dữ liệu người dùng phải có điều kiện
               userId của người đang đăng nhập. Thiếu điều kiện này là lỗi nghiêm trọng.
            2. DỮ LIỆU: số tiền phải dùng Decimal @db.Decimal(18,2), tuyệt đối không dùng
               Float/Double/number cho tiền tệ.
            3. SOFT DELETE: không hard delete, mọi truy vấn đọc phải lọc isDeleted: false.
            4. VALIDATION: query param và request body phải được validate trước khi dùng.
            5. HIỆU NĂNG: không truy vấn trong vòng lặp (N+1), không findMany() trả toàn bộ field.

            Cách trình bày nhận xét:
            - Với mỗi vấn đề: nêu rõ file:line, mức độ (Nghiêm trọng / Cảnh báo / Góp ý),
              nguyên nhân và đoạn code sửa gợi ý.
            - Sắp xếp từ nghiêm trọng đến nhẹ. Không báo lỗi về format hay đặt tên biến.
            - Nếu không tìm thấy vấn đề nào, nói rõ điều đó thay vì bịa ra nhận xét.

            Cuối cùng, dùng lệnh gh pr comment để đăng toàn bộ nhận xét lên pull request.
          claude_args: |
            --allowed-tools "Read,Grep,Glob,Bash(gh pr view:*),Bash(gh pr diff:*),Bash(gh pr comment:*)"
    Thành phầnÝ nghĩa
    on: pull_requestKích hoạt khi PR được mở (opened) và mỗi lần push thêm commit vào PR đó (synchronize).
    permissionsQuyền tối thiểu: đọc code, ghi comment lên PR. Không cấp contents: write để Claude không thể tự sửa code trong workflow này.

    promptChính là "system prompt" của người review. Đây là nơi bạn mã hoá tiêu chuẩn của team — phần quan trọng nhất cần tuỳ biến.

    Tạo file .github/review-guidelines.md:

    # Review Guidelines — Expense Management

## 1. Bảo mật dữ liệu người dùng (mức độ: Nghiêm trọng)
- Mọi truy vấn Prisma đọc/ghi dữ liệu nghiệp vụ BẮT BUỘC có điều kiện userId
  của người đang đăng nhập.
- Không nhận userId từ query param hoặc request body của client.
- Không trả về passwordHash hoặc field nhạy cảm trong response.

## 2. Kiểu dữ liệu tiền tệ (mức độ: Nghiêm trọng)
- amount, balance, initialBalance, budget: Decimal @db.Decimal(18, 2).
- Cấm Float, Double, và cấm cộng/trừ tiền bằng Number trong JavaScript.
- Số tiền trả về API dưới dạng chuỗi decimal (.toString()).

## 3. Soft delete (mức độ: Nghiêm trọng)
- Không hard delete. Xoá là set isDeleted = true.
- Mọi truy vấn đọc phải có isDeleted: false.

## 4. Validation (mức độ: Cảnh báo)
- Query param và request body phải validate bằng zod trước khi dùng.
- Sai định dạng trả 400 kèm thông báo cụ thể, không để lộ lỗi gốc của Prisma.

## 5. Hiệu năng (mức độ: Cảnh báo)
- Cấm truy vấn trong vòng lặp (N+1). Dùng include, groupBy hoặc aggregate.
- Mọi field dùng để lọc hoặc sắp xếp phải có index.

## 6. Những gì KHÔNG cần báo cáo
- Format code, thứ tự import, khoảng trắng.
- Sở thích đặt tên biến nếu vẫn đúng convention của project.

Phần 3: Tạo pull request có lỗi cố ý và xem Claude review

Vì sao phải cố tình viết code sai? Nếu chỉ tạo một PR "sạch", Claude sẽ khen tốt và bạn không học được gì. Cách duy nhất để tin tưởng một công cụ review là đưa cho nó những lỗi mà bạn đã biết trước, rồi đối chiếu xem nó bắt được bao nhiêu.
  1. Bước 9: Tạo branch mới và thêm code có lỗi 
    git checkout -b feature/transaction-summary

    Tạo file src/app/api/transaction/summary/route.ts với nội dung dưới đây. Đoạn code này chứa 5 lỗi cố ý — hãy tự đọc và thử tìm ra trước khi xem Claude nói gì:

    
import { NextRequest, NextResponse } from 'next/server';
import { prisma } from '@/lib/prisma';

export async function GET(req: NextRequest) {
  const userId = req.nextUrl.searchParams.get('userId');
  const month = req.nextUrl.searchParams.get('month');

  const transactions = await prisma.transaction.findMany({
    where: {
      date: { gte: new Date(month + '-01') },
    },
  });

  let totalExpense = 0;
  let totalIncome = 0;

  for (const t of transactions) {
    if (t.type === 'EXPENSE') {
      totalExpense = totalExpense + Number(t.amount);
    } else {
      totalIncome = totalIncome + Number(t.amount);
    }
  }

  return NextResponse.json({
    userId,
    totalExpense,
    totalIncome,
    balance: totalIncome - totalExpense,
    transactions,
  });
}

    Nếu cấu trúc project của bạn khác một chút (tên model, đường dẫn), cứ điều chỉnh cho khớp — điều quan trọng là giữ nguyên 5 lỗi.

  2. Bước 10: Commit và tạo pull request bằng Claude Code

    Đây là lúc Claude Code phát huy tác dụng ở phía local — viết commit message và PR description từ chính diff thực tế:

    Đọc diff hiện tại, sau đó:

1. Tạo commit với message theo chuẩn Conventional Commits.
2. Push branch feature/transaction-summary lên origin.
3. Dùng gh pr create để mở pull request vào nhánh master. PR description phải gồm:
   - Mục đích của thay đổi
   - Danh sách file bị ảnh hưởng
   - Cách kiểm thử thủ công (gọi API nào, với tham số gì)

Chỉ soạn nội dung dựa trên diff thật, không suy đoán thêm tính năng không có trong code.
    Quan sát điều Claude Code KHÔNG làm: ở phiên local này, Claude không tự nhận xét rằng code có lỗi — vì bạn chỉ yêu cầu nó commit và mở PR. Đây chính là lý do cần một vòng review độc lập chạy tự động ở phía server.

    Nếu muốn làm thủ công:

    git add src/app/api/transaction/summary/route.ts

Phần 4: Sửa theo nhận xét và tương tác hai chiều

  1. Bước 13: Giao lại nhận xét cho Claude Code ở local để sửa

    Quay về terminal, ở đúng branch feature/transaction-summary:

    Đọc các nhận xét review trên pull request hiện tại bằng lệnh gh pr view --comments,
sau đó sửa file src/app/api/transaction/summary/route.ts theo đúng các nhận xét đó.

Nguyên tắc khi sửa:
- Lấy userId từ phiên đăng nhập ở server, KHÔNG lấy từ query param.
- Dùng Prisma Client singleton trong src/lib/prisma.ts.
- Tính tổng bằng aggregate/groupBy của database, không cộng bằng JavaScript.
- Validate tham số month bằng zod, sai định dạng trả 400.
- Chỉ sửa đúng những gì review nêu ra, không refactor thêm phần khác.

Sửa xong thì commit và push lên cùng branch, chưa merge.

    Sau khi push, workflow sẽ tự chạy lại nhờ event synchronize. Xem lượt review thứ hai:

    gh run watch
gh pr view --comments

    Đây là vòng lặp thực tế của một team: PR → review tự động → sửa → review lại, mà không cần chờ ai rảnh.

  2. Bước 14: Tương tác trực tiếp với Claude trên pull request bằng @claude

    Ngoài review tự động, bạn có thể "hỏi lại" người review ngay trên PR. Tính năng này cần thêm một workflow thứ hai — tạo file .github/workflows/claude.yml:

    name: Claude Mention

name: Claude Code

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
  issues:
    types: [opened, assigned]
  pull_request_review:
    types: [submitted]

jobs:
  claude:
    if: |
      (github.event_name == 'issue_comment' && contains(github.event.comment.body, '@claude')) ||
      (github.event_name == 'pull_request_review_comment' && contains(github.event.comment.body, '@claude')) ||
      (github.event_name == 'pull_request_review' && contains(github.event.review.body, '@claude')) ||
      (github.event_name == 'issues' && (contains(github.event.issue.body, '@claude') || contains(github.event.issue.title, '@claude')))
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
      issues: write
      id-token: write
      actions: write # Required for Claude to read CI results on PRs
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 1

      - name: Run Claude Code
        id: claude
        uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}

          # This is an optional setting that allows Claude to read CI results on PRs
          additional_permissions: |
            actions: read

          # Optional: Give a custom prompt to Claude. If this is not specified, Claude will perform the instructions specified in the comment that tagged it.
          # prompt: 'Update the pull request description to include a summary of changes.'

          # Optional: Add claude_args to customize behavior and configuration
          # See https://github.com/anthropics/claude-code-action/blob/main/docs/usage.md
          # or https://code.claude.com/docs/en/cli-reference for available options
          # claude_args: '--allowed-tools Bash(gh pr *)'

    Commit file này lên master (workflow xử lý comment phải nằm ở nhánh mặc định mới có hiệu lực):

    git checkout master
git add .github/workflows/claude.yml
git commit -m "ci: them workflow phan hoi khi mention @claude"
git push origin master
git checkout feature/transaction-summary

    Quay lại PR trên trình duyệt và để lại một comment như sau:

    @claude Giải thích giúp tôi vì sao việc cộng tiền bằng Number() lại nguy hiểm
với kiểu Decimal, và cho ví dụ một trường hợp số tiền cụ thể bị sai lệch.
    Chú ý mức rủi ro tăng lên: workflow này có contents: write — nghĩa là Claude có thể tự commit sửa code khi bạn yêu cầu trong comment. Tiện, nhưng chỉ nên bật ở repo private của cá nhân hoặc team đã thống nhất. Với repo có người ngoài đóng góp, bất kỳ ai comment được cũng có thể kích hoạt nó.
  3. Bước 15: Merge pull request

    Khi đã hài lòng — và sau khi chính bạn đã đọc lại diff, không chỉ dựa vào nhận xét của Claude:

    gh pr diff
gh pr merge --squash --delete-branch
    Nguyên tắc không được phá vỡ: Claude review là vòng lọc đầu tiên, không phải người phê duyệt. Nó không biết ngữ cảnh nghiệp vụ, không biết các quyết định kỹ thuật trong quá khứ của team, và có thể tự tin nói sai. Với thay đổi ảnh hưởng đến production hoặc dữ liệu người dùng thật, luôn cần một con người có thẩm quyền approve trước khi merge.

Troubleshoot

Lỗi: Workflow không chạy khi mở pull request.
Nguyên nhân: File workflow chưa có trên nhánh mặc định (master), hoặc sai đường dẫn thư mục. GitHub chỉ đọc workflow từ nhánh mặc định đối với event pull_request.
Giải pháp: Chạy git ls-tree origin/master .github/workflows/ để xác nhận file đã có trên remote. Đường dẫn đúng là .github/workflows/ — có chữ "s" ở cả hai từ.
Lỗi: Error: Input required and not supplied: anthropic_api_key, hoặc job fail ngay bước đầu với lỗi 401.
Nguyên nhân: Secret ANTHROPIC_API_KEY chưa được tạo, sai tên, hoặc key đã bị thu hồi.
Giải pháp: Chạy gh secret list để đối chiếu tên secret (phân biệt hoa thường). Tạo lại bằng gh secret set ANTHROPIC_API_KEY. Kiểm tra key còn hiệu lực trong Anthropic Console.
Lỗi:
Error: Claude result reported subtype success with is_error:true (run did not complete successfully)
Error: Action failed with error: Claude execution failed: result is_error:true
Error: Process completed with exit code 1.
kèm hiện tượng Job chỉ khởi động xong fail luôn.
Nguyên nhân: tài khoản Hết Credit hoặc giới hạn credit đã tới hạn
Giải pháp: Nạp thêm tiền vào Anthropic account, set giới hạn nếu đã chạm limit.
Lỗi: Workflow chạy thành công nhưng không thấy comment nào trên pull request.
Nguyên nhân: Thiếu quyền pull-requests: write, hoặc claude_args không cho phép tool Bash(gh pr comment:*).
Giải pháp: Kiểm tra khối permissions trong YAML và danh sách --allowed-tools. Mở log của job bằng gh run view --log để xem Claude có bị chặn khi gọi tool hay không.
Lỗi: Nhận xét chung chung, chỉ khen code tốt, không bắt được lỗi nào.
Nguyên nhân: Prompt quá mơ hồ ("review this PR"), hoặc Claude không đọc được file quy tắc do đường dẫn sai.
Giải pháp: Nêu đích danh những gì cần kiểm tra trong prompt, kèm mức độ nghiêm trọng. Xác nhận .github/review-guidelines.md đã được commit và đường dẫn trong prompt viết đúng.
Lỗi: Mention @claude trong comment nhưng không có phản hồi.
Nguyên nhân: Chưa cài Claude GitHub App cho repository, hoặc workflow claude.yml chưa nằm trên master.
Giải pháp: Chạy lại /install-github-app trong Claude Code, kiểm tra App đã được cấp quyền cho đúng repo, và xác nhận claude.yml đã có trên nhánh mặc định.
Lỗi: Hoá đơn Anthropic tăng bất thường.
Nguyên nhân: Workflow chạy lại mỗi lần push commit vào PR (event synchronize). Một PR bị sửa 10 lần là 10 lượt review.
Giải pháp: Bỏ synchronize để chỉ review khi PR mở lần đầu, thêm bộ lọc paths để chỉ chạy khi file mã nguồn thay đổi, hoặc chỉ chạy khi PR được gắn label needs-review.

Tổng kết bài lab

Ở các bài lab trước, tiêu chuẩn của project nằm trong CLAUDE.md và các Skill — nhưng chỉ có tác dụng khi bạn chủ động gõ prompt. Bài lab này đưa chính bộ tiêu chuẩn đó ra khỏi máy local và gắn vào quy trình Git: từ nay mọi pull request đều được kiểm tra, kể cả khi bạn quên.

  • Đóng vòng lặp review → sửa → review lại và tương tác trực tiếp qua @claude.
