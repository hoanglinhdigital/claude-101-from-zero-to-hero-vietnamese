4. Claude Code cho Developer / Lab - Refactor code & tạo Pull Request
Bài lab này tiếp tục dùng project D:\lab-expense-management đã tạo ở Chapter 4 và cập nhật ở Chapter 6. Nếu chưa hoàn thành 2 bài lab trước, hãy quay lại thực hiện trước.

Mục tiêu

  • Yêu cầu Claude Code refactor một đoạn logic có sẵn — tách logic tính tổng chi tiêu theo tháng ra service riêng — mà không thay đổi hành vi hiện tại.
  • Dùng bộ test đã có (từ Chapter 4.6) để xác nhận refactor không phá vỡ chức năng.
  • Dùng Claude Code tạo Git commit với message chuẩn, và tạo Pull Request qua GitHub CLI (gh pr create) với PR description do Claude Code viết.

Claude Code thực hiện refactor, tự chạy lại test hiện có để xác nhận không đổi hành vi, sau đó hỗ trợ commit, push và tạo Pull Request kèm description tóm tắt thay đổi.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Chapter 4 và Chapter 6 — project D:\lab-expense-management đã có tính năng CRUD, xuất CSV và bộ unit test.
  • Git đã được cài đặt và project đã có repository Git cục bộ (được tự tạo sẵn khi create-next-app khởi tạo project ở Chapter 4).
  • GitHub CLI (gh) đã được cài đặt: gh --version chạy được. Cài tại cli.github.com nếu chưa có.
  • Đã đăng nhập GitHub CLI: gh auth login chạy thành công.
  • Terminal: PowerShell hoặc Windows Terminal.

Các bước thực hành

Phần 1: Chuẩn bị repository trên GitHub

  1. Bước 1: Vào thư mục project và kiểm tra trạng thái Git 
    cd D:\lab-expense-management
git status
  2. Bước 2: Tạo repository trên GitHub (nếu chưa có) và push nhánh main

    Lệnh này tạo repository riêng tư trên GitHub, gán làm remote origin và push toàn bộ code hiện tại lên nhánh main.

    gh repo create lab-expense-management --private --source=. --remote=origin
git add .
git commit -m "chore: initial commit - expense management app"
git push -u origin main
  3. Bước 3: Tạo nhánh mới cho công việc refactor

    Không refactor trực tiếp trên main — luôn tạo nhánh riêng để dễ tạo Pull Request và review.

    git checkout -b refactor/expense-summary-service

Phần 2: Yêu cầu Claude Code refactor

  1. Bước 4: Khởi động Claude Code và giao tác vụ refactor

    Nêu rõ ràng buộc quan trọng nhất của refactor: không đổi hành vi, chỉ tổ chức lại code cho dễ đọc/tái sử dụng, và yêu cầu tự chạy test để xác nhận.

    claude
    Refactor logic tính tổng chi tiêu theo tháng đang nằm trực tiếp trong app/api/expenses/summary/route.ts. Yêu cầu cụ thể:
1. Tạo file lib/expense-service.ts, thêm hàm getMonthlySummary(prisma) chứa toàn bộ logic query + group by tháng đang nằm trong route.ts hiện tại.
2. Sửa app/api/expenses/summary/route.ts để chỉ gọi getMonthlySummary() và trả response, không còn chứa logic nghiệp vụ trực tiếp trong route handler.
3. Đây là refactor thuần — giữ nguyên định dạng response trả về (JSON structure) và hành vi hiện tại, không đổi logic tính toán.
4. Sau khi refactor xong, chạy npm test để xác nhận toàn bộ test hiện có vẫn pass.
  2. Bước 5: Duyệt kế hoạch và xem lại diff

    Đọc qua các file bị ảnh hưởng (lib/expense-service.ts mới, app/api/expenses/summary/route.ts sửa) trước khi cho phép ghi thay đổi.

    git diff
  3. Bước 6: Tự chạy lại test để xác nhận độc lập

    Không chỉ tin vào báo cáo "test pass" của Claude Code — luôn tự chạy lại để xác nhận.

    npm test
PASS  __tests__/csv-export.test.ts
  buildExpensesCsv
    ✓ tạo đúng CSV với danh sách chi tiêu bình thường
    ✓ escape đúng giá trị chứa dấu phẩy

Phần 3: Commit, push và tạo Pull Request

  1. Bước 7: Yêu cầu Claude Code soạn commit message và commit

    Claude Code đọc git diff đã staged để soạn message theo convention (Conventional Commits), thay vì cần học viên tự viết.

    Stage toàn bộ thay đổi vừa refactor và tạo một git commit với message theo chuẩn Conventional Commits, mô tả đúng nội dung: tách logic tính tổng chi tiêu theo tháng ra service riêng, không đổi hành vi.
  2. Bước 8: Push nhánh refactor lên GitHub 
    git push -u origin refactor/expense-summary-service
  3. Bước 9: Yêu cầu Claude Code tạo Pull Request

    Claude Code có thể gọi trực tiếp GitHub CLI (gh pr create) nếu được cấp quyền chạy lệnh hệ thống — soạn title và description dựa trên diff thực tế giữa nhánh hiện tại và main.

    Tạo một Pull Request từ nhánh hiện tại vào main bằng GitHub CLI (gh pr create). Viết title ngắn gọn theo Conventional Commits và description đầy đủ gồm: mục đích thay đổi, danh sách file bị ảnh hưởng, cách đã kiểm chứng (npm test), và xác nhận đây là refactor không đổi hành vi.
  4. Bước 10: Xác nhận lệnh gh pr create trước khi Claude Code thực thi

    Đây là hành động thao tác lên GitHub remote — xem kỹ nội dung title/description Claude Code chuẩn bị chạy trước khi xác nhận (Yes) cho lệnh gh pr create thực thi, theo đúng nguyên tắc "git push/PR luôn cần xác nhận thủ công" đã học ở Chapter 3.

  5. Bước 11: Kiểm tra Pull Request trên GitHub

    Mở đường link Pull Request được trả về sau khi gh pr create thành công, hoặc dùng lệnh sau để xem trực tiếp trong terminal.

    gh pr view --web

✅ Kết quả mong đợi

Một Pull Request mới xuất hiện trên GitHub, chuyển từ nhánh refactor/expense-summary-service vào main, có title và description rõ ràng do Claude Code soạn. Nội dung diff chỉ gồm việc tách logic sang lib/expense-service.ts, response API và toàn bộ test hiện có vẫn pass — xác nhận refactor không làm đổi hành vi.

Troubleshoot

Lỗi: gh pr create báo lỗi "no upstream branch" hoặc "unknown repository".
Nguyên nhân: Nhánh hiện tại chưa được push lên remote, hoặc gh chưa nhận diện đúng repository (thiếu remote origin).
Giải pháp: Chạy lại git push -u origin refactor/expense-summary-service trước, kiểm tra remote bằng git remote -v.
Lỗi: gh báo chưa đăng nhập hoặc không đủ quyền tạo Pull Request.
Nguyên nhân: Chưa chạy gh auth login, hoặc token đăng nhập đã hết hạn/thiếu scope repo.
Giải pháp: Chạy gh auth login và làm theo hướng dẫn đăng nhập lại qua browser, chọn đủ scope truy cập repository.
Lỗi: Test fail sau khi refactor, dù logic có vẻ đã chuyển đúng.
Nguyên nhân: Response JSON structure bị thay đổi vô ý (vd đổi tên field) trong quá trình tách hàm.
Giải pháp: Yêu cầu Claude Code so sánh lại response cũ (trước refactor, xem qua git diff) và mới, đảm bảo cấu trúc JSON trả về giữ nguyên 100%.
