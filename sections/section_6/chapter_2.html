5. Claude cho DevOps & Cloud Engineer / Cách cấu trúc prompt cho Infrastructure as Code (Terraform)

Giới thiệu

Khác với prompt sinh code ứng dụng, prompt cho Infrastructure as Code (IaC) tác động trực tiếp lên tài nguyên Cloud thật — Security Rule mở sai, IAM quá rộng quyền hay thiếu tag đều có thể gây rủi ro bảo mật hoặc khó quản lý chi phí về sau. Chương này trình bày cách cấu trúc một prompt IaC rõ ràng, đủ chi tiết để Claude Code sinh Terraform đúng ý định ngay từ đầu, giảm số lần phải sửa lại sau khi đã plan/apply.

Các thành phần chính cần đưa vào prompt

  • Resource cần tạo — nêu rõ loại resource (VPC, EC2, S3, DynamoDB, IAM...) và mối quan hệ giữa chúng (vd EC2 nằm trong subnet nào).
  • Region — luôn chỉ định rõ region triển khai, tránh để Terraform provider dùng region mặc định ngoài ý muốn.
  • Naming convention — nêu rõ quy ước đặt tên resource (prefix theo project, môi trường) để dễ nhận diện và quản lý.
  • Tag — yêu cầu gắn tag chuẩn (Project, Environment, ManagedBy) cho mọi resource, phục vụ quản lý chi phí và truy vết.
  • Ràng buộc bảo mật — nêu rõ: không mở port public không cần thiết, dùng least privilege cho IAM (không dùng * cho Action/Resource, không gắn AdministratorAccess).

Prompt IaC thiếu ràng buộc bảo mật khiến Claude Code dễ chọn giá trị mặc định rủi ro (vd 0.0.0.0/0 cho SSH); nêu rõ ràng buộc ngay từ đầu giúp giảm số lần phải sửa lại sau khi review plan.

So sánh Prompt mơ hồ và Prompt rõ ràng — ví dụ tạo EC2 + Security Group

Thành phần promptPrompt mơ hồPrompt rõ ràng
Yêu cầu gốc "Viết Terraform tạo một con EC2 cho tôi test thử." "Viết Terraform tạo 1 EC2 instance loại t3.micro, region ap-southeast-1, đặt trong subnet public đã có sẵn (aws_subnet.public)."
Naming/Tag Không đề cập — Claude Code tự chọn tên resource và có thể bỏ qua tag. "Tên resource theo pattern ${var.project_name}-web. Gắn tag Project = var.project_name và ManagedBy = "Terraform" cho mọi resource."
Bảo mật (Security Group) "Mở SSH để tôi truy cập vào." → dễ dẫn đến Claude Code mặc định 0.0.0.0/0 cho port 22. "Security Group chỉ mở port 22 từ CIDR biến var.allowed_ssh_cidr (không có giá trị mặc định, bắt buộc nhập) — không mở SSH cho 0.0.0.0/0. Port 80 có thể mở public."
IAM cho EC2 "Cho EC2 quyền truy cập S3 và DynamoDB." → dễ dẫn đến Claude Code gắn policy quá rộng (vd s3:* trên Resource = "*"). "Tạo IAM role least-privilege: chỉ cho phép s3:GetObject/PutObject/ListBucket đúng trên ARN của bucket vừa tạo, và các action đọc/viết cần thiết trên đúng ARN của DynamoDB table vừa tạo — không dùng wildcard * cho Resource, không gắn AdministratorAccess."
Mẹo: Với prompt IaC, nên chốt trước 4 mục: Resource – Region – Naming/Tag – Ràng buộc bảo mật thành một danh sách gạch đầu dòng ngay trong prompt. Cách này giúp Claude Code không cần hỏi lại nhiều lần và kết quả terraform plan ít bất ngờ hơn.

Use Cases

Sinh module Terraform tái sử dụng

Nêu rõ input variables và ràng buộc bảo mật giúp Claude Code sinh module Terraform dễ tái sử dụng cho nhiều môi trường (dev/staging/prod).

Chuẩn hoá tagging cho Cost Monitor

Yêu cầu tag nhất quán ngay từ prompt giúp team dễ theo dõi chi phí theo project/môi trường trên AWS Cost Explorer.

Giảm rủi ro mở port/IAM quá rộng

Ràng buộc bảo mật rõ ràng trong prompt giúp phát hiện sớm, tránh phải vá lại security group hoặc IAM policy sau khi đã apply lên môi trường thật.

Thông tin bổ sung

Một prompt IaC đầy đủ 4 phần không cần viết lại từ đầu mỗi lần — có thể lưu thành template trong file CLAUDE.md của project hạ tầng hoặc trong skill terraform-creator. Chứa các quy tắc về naming convention, tag chuẩn, danh sách ràng buộc bảo mật cố định. Điều này giúp Claude Code tự áp dụng nhất quán cho mọi resource mới mà không cần nhắc lại trong từng prompt.

Lưu ý: Dù prompt đã rõ ràng, vẫn phải đọc lại terraform plan trước khi apply — prompt tốt giúp giảm rủi ro, không loại bỏ hoàn toàn nhu cầu review theo nguyên tắc an toàn đã học ở chương trước.
