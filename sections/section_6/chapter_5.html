6. Claude cho Tester / QA / Lab - Viết test tự động cho hàm/API có sẵn
Bài lab này tiếp tục dùng project D:\lab-expense-management đã tạo ở Section 4 - Chapter 4. Nếu chưa hoàn thành bài lab đó, hãy quay lại thực hiện trước khi bắt đầu.

Mục tiêu

  • Dùng Claude Code viết test tự động cho API POST /api/expenses, dựa trên 3 test case trọng tâm đã thiết kế ở Chapter 4: tạo hợp lệ (happy path), amount <= 0 (negative), ngày chi tiêu ở tương lai (negative).
  • Hiểu góc nhìn Tester khi viết test tự động: dựa vào test case/spec và API contract (input/output qua HTTP), không cần đọc chi tiết code implementation — khác với lab viết unit test ở Section 4 (góc nhìn Developer, biết rõ code và viết test cùng lúc với code).
  • Chạy test tự động và đọc kết quả để phát hiện case nào đang fail trên implementation hiện tại của app.

Test viết dưới dạng integration test gọi trực tiếp qua HTTP đến dev server đang chạy — đúng góc nhìn hộp đen (black-box) của Tester, không phụ thuộc vào chi tiết code trong route.ts.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành Section 4 - Chapter 4 — project D:\lab-expense-management chạy được, MySQL container hoạt động.
  • Node.js 18 trở lên (có sẵn fetch toàn cục, không cần cài thêm thư viện HTTP).
  • Claude Code CLI đã cài đặt và đăng nhập thành công.
  • Terminal: PowerShell hoặc Windows Terminal (cần mở 2 cửa sổ terminal).

Phần 2: Yêu cầu Claude Code viết test tự động theo góc nhìn Tester

  1. Bước 3: Gõ prompt yêu cầu viết integration test, nêu rõ đây là góc nhìn Tester (black-box)

    Prompt liệt kê rõ 3 test case bằng input/output mong đợi, không yêu cầu Claude Code đọc file route.ts.

    Đóng vai trò Tester, viết một bộ test tự động dạng integration test gọi trực tiếp qua HTTP đến API đang chạy tại http://localhost:3000/api/expenses. KHÔNG cần đọc code trong app/api/expenses/route.ts — chỉ dựa vào 3 test case sau (đã thiết kế từ trước, mô tả input và kết quả mong đợi qua HTTP):

Test case 1 (Happy path): POST /api/expenses với body { title: "Ăn trưa", amount: 50000, categoryId: <id của category đầu tiên, lấy qua GET /api/categories>, spentAt: <ngày hôm nay, định dạng ISO> }. Kết quả mong đợi: status 200 hoặc 201, response chứa id của bản ghi vừa tạo.

Test case 2 (Negative - amount <= 0): giống Test case 1 nhưng amount: -100. Kết quả mong đợi: status 400, response chứa message lỗi liên quan đến "amount"/"số tiền".

Test case 3 (Negative - ngày ở tương lai): giống Test case 1 nhưng spentAt là ngày 7 ngày sau thời điểm hiện tại. Kết quả mong đợi: status 400, response chứa message lỗi liên quan đến ngày chi tiêu.

Yêu cầu kỹ thuật:
1. Dùng Node.js built-in test runner (node:test) và fetch có sẵn (Node 18+), không cài thêm thư viện ngoài.
2. Trước các test case, tự gọi GET /api/categories để lấy một categoryId hợp lệ có sẵn, dùng chung cho cả 3 test case.
3. Đặt file tại tests/expenses.api.test.js.
4. Thêm script "test:api": "node --test tests/expenses.api.test.js" vào package.json.
5. Test giả định server đã đang chạy sẵn ở http://localhost:3000 — không tự khởi động server trong test.
  2. Bước 4: Duyệt kế hoạch và xác nhận thực thi

    Đọc qua nội dung file tests/expenses.api.test.js và thay đổi trong package.json trước khi cho phép Claude Code ghi file.

Phần 3: Tham khảo nội dung file test

Nội dung dưới đây là ví dụ tham khảo cho những gì Claude Code nên sinh ra ở Bước 3 (rút gọn, chỉ giữ 2/3 test case để minh hoạ) — dùng để đối chiếu, không cần tự tay chép lại.

tests/expenses.api.test.jsconst { test, before } = require('node:test');
const assert = require('node:assert/strict');

const BASE_URL = 'http://localhost:3000';
let categoryId;

before(async () => {
  const res = await fetch(`${BASE_URL}/api/categories`);
  const categories = await res.json();
  categoryId = categories[0].id;
});

test('tạo khoản chi tiêu hợp lệ (happy path)', async () => {
  const res = await fetch(`${BASE_URL}/api/expenses`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: 'Ăn trưa', amount: 50000, categoryId, spentAt: new Date().toISOString() })
  });
  assert.ok(res.status === 200 || res.status === 201);
});

test('từ chối khi amount <= 0', async () => {
  const res = await fetch(`${BASE_URL}/api/expenses`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: 'Test âm', amount: -100, categoryId, spentAt: new Date().toISOString() })
  });
  assert.equal(res.status, 400);
});

// test case 3 (ngày ở tương lai) tương tự, xem file đầy đủ Claude Code sinh ra

Troubleshoot

Lỗi: Test báo lỗi fetch failed hoặc ECONNREFUSED.
Nguyên nhân: Dev server ở Terminal 1 chưa chạy hoặc đã bị dừng trước khi chạy test.
Giải pháp: Kiểm tra Terminal 1 vẫn đang chạy npm run dev và truy cập được http://localhost:3000 trên browser trước khi chạy lại npm run test:api.
Lỗi: node --test báo không nhận diện được cú pháp hoặc lệnh không tồn tại.
Nguyên nhân: Phiên bản Node.js thấp hơn 18, chưa hỗ trợ đầy đủ built-in test runner và fetch toàn cục.
Giải pháp: Kiểm tra bằng node -v, nâng cấp lên Node.js 18 trở lên nếu cần.
Lỗi: Test case happy path cũng fail vì categoryId không hợp lệ.
Nguyên nhân: Database chưa có category nào (bảng Category rỗng).
Giải pháp: Vào app tại http://localhost:3000, tạo ít nhất một category trước khi chạy lại test, hoặc yêu cầu Claude Code cho phần before() tự tạo category nếu danh sách rỗng.
