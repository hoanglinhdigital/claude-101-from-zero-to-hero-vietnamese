6. Claude cho DevOps & Cloud Engineer / Lab - Thiết kế hạ tầng hệ thống trên AWS sử dụng Claude
Bài lab này không tạo resource thật trên AWS — chỉ dùng Claude để thiết kế kiến trúc hạ tầng, output là sơ đồ Draw.io. Việc dựng hạ tầng thật bằng Terraform sẽ thực hành ở Lab tiếp theo.

Mục tiêu

  • Tạo được một Claude Skill tên aws-architecture-design đóng gói bộ quy ước chuẩn khi vẽ sơ đồ kiến trúc AWS (icon, màu sắc, vị trí, quy tắc High Availability, naming convention).
  • Biết cách mô tả tech stack của một ứng dụng thực tế để Claude đề xuất kiến trúc AWS phù hợp (VPC, Subnet, ECS Cluster, ECR, RDS, CloudWatch Alarm, SNS).
  • Xuất được kiến trúc dưới dạng file .drawio, mở bằng Draw.io Desktop để review.
  • Biết 2 cách chỉnh sửa sơ đồ: chỉnh tay trực tiếp trên Draw.io, hoặc nhờ Claude Code sửa lại file XML theo yêu cầu.

Skill chỉ cần tạo một lần — sau đó tái sử dụng cho mọi lần yêu cầu Claude thiết kế kiến trúc AWS, đảm bảo mọi sơ đồ trong team đều theo cùng một chuẩn.

Yêu cầu trước khi bắt đầu

  • Claude Code đã cài đặt và login thành công (Section 2).
  • Project D:\lab-expense-management chạy được ở local (Lab Section 4).
  • Draw.io Desktop — công cụ vẽ sơ đồ miễn phí, mở được file .drawio do Claude sinh ra.

Các bước thực hành

Phần 1: Cài đặt Draw.io Desktop

  1. Bước 1: Cài đặt Draw.io Desktop bằng winget (Windows)

    Mở PowerShell và chạy lệnh sau. Nếu không dùng winget, có thể tải bản cài đặt trực tiếp tại https://www.drawio.com/.

    winget install --id JGraph.Draw -e
  2. Bước 2: Kiểm tra Draw.io mở được ứng dụng

    Mở Draw.io Desktop vừa cài, chọn Create New Diagram → Blank Diagram để chắc chắn ứng dụng hoạt động bình thường trước khi qua bước tiếp theo. Đóng lại file blank này.

Phần 2: Tạo Claude Skill "aws-architecture-design"

  1. Bước 3: Mở Claude Code tại project D:\lab-expense-management

    Skill sẽ được lưu trong project này tại .claude/skills/aws-architecture-design/, nhưng có thể copy sang project khác để tái sử dụng.

    cd D:\lab-expense-management
claude
  2. Bước 4: Yêu cầu Claude Code tạo Skill với bộ quy ước chuẩn

    Dán nguyên văn prompt sau (đây là phần quan trọng nhất bài lab — bộ quy ước này sẽ được Claude áp dụng cho mọi sơ đồ AWS thiết kế sau này). Dùng Plan mode hoặc Accept Edit mode.

    
Tạo cho tôi một Claude Skill tên "aws-architecture-design", lưu tại .claude/skills/aws-architecture-design/SKILL.md.

Mục đích của Skill: mỗi khi tôi yêu cầu Claude thiết kế/vẽ kiến trúc hạ tầng AWS, Claude phải tự động áp dụng
skill này và xuất ra một file .drawio (XML mxGraph hợp lệ, mở được trực tiếp bằng Draw.io Desktop).

Bộ quy ước BẮT BUỘC phải ghi rõ trong SKILL.md:

1. Icon & shape library
- Dùng đúng shape library chuẩn "mxgraph.aws4" có sẵn trong Draw.io (AWS 2019 Architecture Icons) — KHÔNG tự vẽ
  hình chữ nhật thường để giả icon.
- Mỗi service vẽ bằng đúng shape tương ứng, ví dụ: mxgraph.aws4.vpc, mxgraph.aws4.subnet, mxgraph.aws4.ecs,
  mxgraph.aws4.elastic_container_registry, mxgraph.aws4.rds, mxgraph.aws4.cloudwatch_alarm, mxgraph.aws4.sns,
  mxgraph.aws4.application_load_balancer, mxgraph.aws4.availability_zone.
- Nếu không chắc tên shape chính xác, ưu tiên giữ đúng tên service viết trong label và dùng group container màu
  đúng category thay vì bỏ icon.

2. Tông màu theo category chuẩn AWS
- Compute (ECS, ECR): cam #ED7100
- Database (RDS): xanh dương #3B48CC
- Network & Content Delivery (VPC, Subnet, ALB): tím #8C4FFF
- Management & Governance (CloudWatch Alarm): hồng #E7157B
- Application Integration (SNS): đỏ hồng #E7157B nhạt hơn hoặc đỏ cam theo đúng bảng màu AWS4
- Public Subnet: viền xanh lá, nền xanh lá nhạt
- Private Subnet: viền xanh dương, nền xanh dương nhạt
- VPC boundary: viền đứt nét màu tím đậm, không tô nền

3. Vị trí đặt icon & label
- Icon đặt góc trên-trái hoặc căn giữa phía trên của box, label (tên resource) đặt ngay bên dưới icon, in đậm.
- Không đặt icon chồng lên đường line kết nối.
- Sắp xếp layout theo hướng luồng traffic: Internet/User trên cùng → Load balancer → Compute tier (Private Subnet)
  → Data tier (Private Subnet riêng biệt) ở dưới cùng. Các thành phần monitoring (CloudWatch, SNS) đặt lệch sang
  một bên, không nằm trên luồng traffic chính.

4. Nguyên tắc High Availability (BẮT BUỘC)
- Subnet luôn phải đi theo CẶP tối thiểu ở 2 Availability Zone khác nhau (vd: subnet-public-a và subnet-public-b).
  Không bao giờ vẽ một subnet đơn lẻ cho tier cần HA.
- Mỗi Availability Zone vẽ thành 1 subgraph/group box riêng, đặt song song nhau, cùng chứa đủ các tầng subnet
  (public/app/data) để dễ so sánh.
- RDS phải vẽ ở chế độ Multi-AZ (icon RDS đặt tại vị trí kết nối tới cả 2 data subnet của 2 AZ).
- ECS Task/Service phải có instance chạy ở cả 2 AZ, không dồn hết vào 1 AZ.

5. Resource naming convention (BẮT BUỘC áp dụng cho MỌI resource trong sơ đồ)
- Format: {system}-{environment}-{ten-resource}, toàn bộ chữ thường, nối bằng dấu gạch ngang.
  - {system}: tên hệ thống/dự án, viết ngắn gọn (vd: expense)
  - {environment}: dev | staging | prod
  - {ten-resource}: loại resource + tên gợi nhớ (vd: vpc, subnet-public-a, ecs-cluster, ecr-app, rds-mysql,
    alarm-cpu-high, sns-alert)
  - Ví dụ đầy đủ: expense-prod-vpc, expense-prod-subnet-app-a, expense-prod-ecs-cluster, expense-prod-rds-mysql
- Label hiển thị trên sơ đồ PHẢI dùng đúng tên resource theo convention này, không dùng tên chung chung như
  "Database" hay "Cluster".

6. Output
- File .drawio phải là XML hợp lệ (thẻ <mxfile><diagram><mxGraphModel>...), mở trực tiếp được bằng
  Draw.io Desktop mà không lỗi.
- Luôn hỏi lại: hệ thống cần bao nhiêu Availability Zone (mặc định 2), và environment là gì (mặc định prod) nếu
  người dùng chưa nêu rõ.

Sau khi tạo xong Skill, hãy tóm tắt lại các quy tắc đã ghi vào SKILL.md cho tôi xem lại.
  3. Bước 5: Review nội dung Skill vừa được tạo

    Mở file .claude/skills/aws-architecture-design/SKILL.md Claude vừa tạo, đọc lại để chắc chắn đầy đủ 6 mục quy ước ở Bước 4. Có thể yêu cầu Claude bổ sung nếu thiếu.

Phần 3: Mô tả tech stack & yêu cầu Claude thiết kế hệ thống

  1. Bước 6: Yêu cầu Claude thiết kế kiến trúc AWS cho app Quản lý chi tiêu

    Prompt mẫu — mô tả rõ tech stack hiện tại và các thành phần AWS bắt buộc phải có:

    
Dùng skill aws-architecture-design để thiết kế kiến trúc hạ tầng AWS cho ứng dụng Quản lý chi tiêu tại project
này (D:\lab-expense-management).

Tech stack hiện tại:
- Frontend + Backend: Next.js (chạy container hoá bằng Docker, đã có docker-compose ở gốc project, chưa có Dockerfile)
- ORM: Prisma
- Database: MySQL

Yêu cầu kiến trúc:
- Compute: chạy ứng dụng Next.js bằng ECS Cluster (Fargate), image lưu trên ECR.
- Network: 1 VPC riêng, chia Public Subnet (đặt ALB) và Private Subnet (đặt ECS + RDS), tối thiểu 2 Availability
  Zone theo đúng nguyên tắc HA trong skill.
- Database: RDS MySQL Multi-AZ, đặt ở Private Subnet riêng (data tier), không cho Public access.
- Load balancing: Application Load Balancer nhận traffic từ Internet, forward vào ECS Service.
- Monitoring: 1 CloudWatch Alarm theo dõi CPU Utilization của ECS Service, khi vượt ngưỡng gửi cảnh báo qua SNS
  Topic (email subscriber).
- environment: prod
- Output ra file: diagrams\aws-architecture-prod.drawio

Sau khi xong, tóm tắt danh sách resource đã thiết kế kèm tên resource theo convention.
  2. Bước 7: Kiểm tra danh sách resource Claude tóm tắt

    Đối chiếu danh sách resource Claude trả về với 3 tiêu chí: (1) đủ 7 thành phần yêu cầu — VPC, Subnet, ECS Cluster, ECR, RDS, CloudWatch Alarm, SNS; (2) subnet đủ cặp theo 2 AZ; (3) tên resource đúng format system-env-ten-resource.

Phần 4: Mở bằng Draw.io, review và chỉnh sửa

Minh họa Sơ đồ được Claude tạo ra khi preview trong Drawio.

  1. Bước 8: Mở file .drawio bằng Draw.io Desktop

    Mở Draw.io Desktop → File → Open → chọn file diagrams\aws-architecture-prod.drawio vừa được sinh ra. Kiểm tra sơ đồ hiển thị đúng icon AWS, đúng màu, đúng vị trí như quy ước đã định nghĩa ở skill.

  2. Bước 9a: Chỉnh sửa trực tiếp trên Draw.io (cách thủ công)

    Nếu chỉ cần chỉnh nhỏ (đổi tên, đổi màu, kéo lại vị trí icon), có thể sửa trực tiếp trên giao diện Draw.io: click chọn shape → sửa label ở panel bên phải, hoặc kéo thả để sắp xếp lại layout. Nhớ Save (Ctrl+S) sau khi sửa.

  3. Bước 9b: Hoặc nhờ Claude Code chỉnh sửa lại file (cách qua prompt)

    Nếu cần thay đổi lớn hơn (thêm resource, đổi lại toàn bộ layout, đổi region/số lượng AZ), quay lại Claude Code và mô tả thay đổi mong muốn — Claude sẽ sửa trực tiếp file XML, vẫn tuân theo skill aws-architecture-design.

    
Sửa lại file diagrams\aws-architecture-prod.drawio: thêm thêm 1 NAT Gateway ở mỗi Public Subnet để Private Subnet
có thể ra Internet tải update, vẫn tuân theo skill aws-architecture-design (naming, màu sắc, nguyên tắc HA).

    Sau khi Claude sửa xong, mở lại file bằng Draw.io (hoặc bấm File → Reload nếu file đang mở sẵn) để xem kết quả.

Troubleshoot

Lỗi: Draw.io báo "Not a diagram file" hoặc mở ra màn hình trắng.
Nguyên nhân: File XML Claude sinh ra thiếu hoặc sai cấu trúc thẻ <mxfile>/<mxGraphModel>.
Giải pháp: Dán nội dung lỗi (hoặc copy nguyên file) cho Claude Code, yêu cầu "kiểm tra và sửa lại cho đúng cấu trúc XML hợp lệ của Draw.io".
Lỗi: Sơ đồ hiển thị hình chữ nhật/hình vuông thường thay vì icon AWS chuẩn.
Nguyên nhân: Claude dùng style mặc định thay vì đúng shape=mxgraph.aws4.*.
Giải pháp: Yêu cầu Claude "đọc lại skill aws-architecture-design, thay toàn bộ shape sai chuẩn bằng đúng shape mxgraph.aws4 tương ứng".
Lỗi: Subnet chỉ có 1 cái, không có cặp theo Availability Zone.
Nguyên nhân: Claude bỏ sót nguyên tắc HA đã ghi trong skill, hoặc SKILL.md ở Bước 4 thiếu mục 4.
Giải pháp: Mở lại SKILL.md, kiểm tra mục nguyên tắc HA có ghi rõ "subnet phải đi theo cặp ở tối thiểu 2 AZ" chưa — nếu thiếu, bổ sung rồi yêu cầu Claude thiết kế lại.
