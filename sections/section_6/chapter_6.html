5. Claude cho DevOps & Cloud Engineer / Lab - Viết script tự động hoá tác vụ vận hành

Mục tiêu

  • Dùng Claude Code viết một script PowerShell tự động hoá tác vụ vận hành lặp lại: backup thư mục log và xoá log cũ hơn N ngày.
  • Test chạy thử script với dữ liệu log mẫu, xác nhận đúng hành vi trước khi đưa vào lịch chạy tự động.
  • Lên lịch chạy script tự động bằng Windows Task Scheduler (schtasks).

Claude Code sinh script PowerShell, Engineer test chạy tay trước để xác nhận hành vi đúng, sau đó mới đăng ký vào Task Scheduler để chạy tự động định kỳ — không đưa script chưa test vào lịch chạy tự động.

Yêu cầu trước khi bắt đầu

  • Máy Windows với PowerShell 5.1 trở lên (mặc định có sẵn trên Windows 10/11).
  • Claude Code CLI đã cài đặt và đăng nhập thành công (xem lại Section 2).
  • Quyền chạy script PowerShell trên máy (không bị chặn bởi Execution Policy — xem phần Troubleshoot nếu gặp lỗi).
  • Terminal: PowerShell hoặc Windows Terminal, chạy với quyền phù hợp để tạo Scheduled Task.

Các bước thực hành

Phần 1: Chuẩn bị dữ liệu log mẫu

  1. Bước 1: Tạo thư mục log mẫu và một số file log giả để test

    Tạo vài file log với thời gian sửa đổi (LastWriteTime) khác nhau để kiểm chứng đúng logic lọc theo số ngày.

    mkdir D:\App\logs
mkdir D:\App\log-backups

"log moi nhat" | Out-File D:\App\logs\app-2026-07-08.log
"log 10 ngay truoc" | Out-File D:\App\logs\app-2026-06-29.log
(Get-Item D:\App\logs\app-2026-06-29.log).LastWriteTime = (Get-Date).AddDays(-10)

"log 40 ngay truoc" | Out-File D:\App\logs\app-2026-05-30.log
(Get-Item D:\App\logs\app-2026-05-30.log).LastWriteTime = (Get-Date).AddDays(-40)

    File app-2026-05-30.log (40 ngày trước) sẽ dùng để kiểm chứng logic xoá log cũ hơn RetentionDays mặc định (30 ngày).

Phần 2: Yêu cầu Claude Code viết script

  1. Bước 2: Tạo thư mục project và khởi động Claude Code 
    mkdir D:\lab-script-tu-dong-hoa
cd D:\lab-script-tu-dong-hoa
claude
  2. Bước 3: Giao yêu cầu viết script — nêu rõ hành vi, tham số, và yêu cầu xử lý lỗi 
    Viết một script PowerShell tên backup-and-cleanup-logs.ps1 tự động hoá tác vụ backup và dọn log. Yêu cầu cụ thể:
1. Tham số: -LogPath (bắt buộc, đường dẫn thư mục chứa log), -BackupPath (bắt buộc, đường dẫn thư mục gốc lưu backup), -RetentionDays (không bắt buộc, mặc định 30).
2. Kiểm tra LogPath phải tồn tại và là thư mục, nếu không thì in lỗi rõ ràng và exit 1. Nếu BackupPath chưa tồn tại thì tự tạo mới.
3. Copy toàn bộ file log hiện có trong LogPath sang một thư mục con mới trong BackupPath, đặt tên thư mục con theo timestamp hiện tại (định dạng yyyyMMdd_HHmmss).
4. Sau khi backup xong, xoá các file trong LogPath có LastWriteTime cũ hơn RetentionDays ngày.
5. In log ra console rõ ràng theo từng bước (có timestamp, level INFO/WARN/ERROR), báo rõ số file đã backup và số file đã xoá ở cuối.
6. Bọc các lệnh copy/xoá file trong try/catch để xử lý lỗi cơ bản, không dừng toàn bộ script nếu một file lỗi.
  3. Bước 4: Duyệt và xác nhận Claude Code tạo file script

    Đọc qua nội dung script trước khi cho phép ghi file — đặc biệt kiểm tra phần xoá file (Remove-Item) chỉ tác động đúng phạm vi LogPath, không có lệnh xoá rộng hơn dự kiến.

Phần 3: Tham khảo nội dung script (đối chiếu với kết quả Claude Code sinh ra)

Nội dung dưới đây là ví dụ tham khảo cho script Claude Code nên sinh ra ở Bước 3 — dùng để đối chiếu khi review, không cần gõ tay lại toàn bộ.

backup-and-cleanup-logs.ps1<#
.SYNOPSIS
    Backup file log moi va don dep (xoa) file log qua cu.
#>

[CmdletBinding()]
param(
    [Parameter(Mandatory = $true)]
    [string]$LogPath,

    [Parameter(Mandatory = $true)]
    [string]$BackupPath,

    [Parameter(Mandatory = $false)]
    [int]$RetentionDays = 30
)

function Write-Log {
    param([string]$Message, [string]$Level = "INFO")
    $timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    Write-Host "[$timestamp] [$Level] $Message"
}

# Kiểm tra LogPath tồn tại, tạo BackupPath nếu chưa có...
# Bước 1: copy log vào thư mục con theo timestamp...
# Bước 2: xoá log trong LogPath cũ hơn RetentionDays...

Toàn bộ script đầy đủ được lưu tại sourcecode/section_5/lab_script_tu_dong_hoa/backup-and-cleanup-logs.ps1 trong repository của khoá học.

Phần 5: Lên lịch chạy tự động bằng Windows Task Scheduler

  1. Bước 7: Tạo Scheduled Task chạy script mỗi ngày lúc 2:00 sáng

    Dùng schtasks /create để đăng ký task, gọi powershell.exe kèm đủ tham số như đã test ở Bước 5.

    schtasks /create /tn "ClaudeLab-BackupCleanupLogs" /tr "powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\lab-script-tu-dong-hoa\backup-and-cleanup-logs.ps1 -LogPath D:\App\logs -BackupPath D:\App\log-backups -RetentionDays 30" /sc daily /st 02:00
  2. Bước 8: Kiểm tra task đã được tạo đúng 
    schtasks /query /tn "ClaudeLab-BackupCleanupLogs"
TaskName                          Next Run Time         Status
==================================  ====================  ========
ClaudeLab-BackupCleanupLogs        7/10/2026 2:00:00 AM   Ready
  3. Bước 9: Chạy thử task ngay lập tức (không chờ đến 2:00 sáng) để xác nhận 
    schtasks /run /tn "ClaudeLab-BackupCleanupLogs"

    Sau vài giây, kiểm tra lại thư mục D:\App\log-backups — nếu có thêm một thư mục con mới theo timestamp, task đã chạy thành công qua Task Scheduler.

✅ Kết quả mong đợi

Script chạy tay ở Bước 5 in log rõ ràng, backup đúng số file và xoá đúng file cũ hơn RetentionDays. Scheduled Task ClaudeLab-BackupCleanupLogs xuất hiện trong Task Scheduler với trạng thái Ready, và khi chạy thử bằng schtasks /run tạo thêm được một thư mục backup mới — xác nhận việc tự động hoá hoạt động đúng.

Troubleshoot

Lỗi: Chạy script báo ...cannot be loaded because running scripts is disabled on this system.
Nguyên nhân: Execution Policy của PowerShell đang chặn chạy file .ps1 chưa được ký (mặc định trên nhiều máy Windows là Restricted).
Giải pháp: Chạy PowerShell với quyền Administrator và nới policy cho user hiện tại: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, hoặc chạy trực tiếp bằng powershell -ExecutionPolicy Bypass -File .\backup-and-cleanup-logs.ps1 ... như đã dùng trong lệnh schtasks /create ở Bước 7.
Lỗi: Scheduled Task hiển thị Ready nhưng đến giờ không tự chạy, hoặc Last Run Result khác 0.
Nguyên nhân: Task được tạo ở chế độ chỉ chạy khi user đã đăng nhập (Run only when user is logged on) nhưng máy đang khoá màn hình/đăng xuất; hoặc đường dẫn script/tham số trong /tr bị sai.
Giải pháp: Mở Task Scheduler (GUI), vào Properties của task, chọn Run whether user is logged on or not nếu cần chạy cả khi không đăng nhập; kiểm tra lại chính xác đường dẫn script trong câu lệnh /tr.
Lỗi: Script báo lỗi LogPath khong ton tai dù thư mục có vẻ đã tồn tại.
Nguyên nhân: Đường dẫn truyền vào có dấu cách hoặc ký tự đặc biệt chưa được đặt trong dấu ngoặc kép, hoặc gõ sai ổ đĩa/tên thư mục.
Giải pháp: Luôn đặt đường dẫn trong dấu ngoặc kép (vd -LogPath "D:\App\logs"), kiểm tra lại bằng Test-Path "D:\App\logs" trước khi chạy script.

Dọn dẹp resource

Bài lab này không tạo resource Cloud nào — chỉ tạo Scheduled Task và thư mục cục bộ trên máy Windows. Nếu không muốn giữ lại task chạy định kỳ, xoá bằng lệnh sau. 
schtasks /delete /tn "ClaudeLab-BackupCleanupLogs" /f

Có thể giữ lại thư mục D:\App\logs, D:\App\log-backups và D:\lab-script-tu-dong-hoa để tham khảo lại script, hoặc xoá bằng Remove-Item -Recurse -Force nếu không cần dùng nữa.
